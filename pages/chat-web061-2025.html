<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>青海厂内部采购管理系统</title>
  <script src="https://cdn.tailwindcss.com"></script>
  <style>
    body {
      background: linear-gradient(135deg, #f8fafc 0%, #e2e8f0 100%);
    }
    .active {
      background-color: #4b5563;
    }
  </style>
</head>
<body class="flex h-screen">

  <!-- 左侧导航栏 -->
  <aside class="w-64 bg-gray-800 text-gray-100 flex flex-col">
    <div class="text-center text-2xl font-bold py-6 border-b border-gray-700">
      内部查询中心
    </div>
    <nav id="nav" class="flex-1 p-4 space-y-3">
      <button data-page="CP/index.html" class="nav-btn w-full text-left px-4 py-2 rounded-lg bg-gray-700 hover:bg-gray-600 transition active">
        成品查询
      </button>
      <button data-page="bom/index.html" class="nav-btn w-full text-left px-4 py-2 rounded-lg bg-gray-700 hover:bg-gray-600 transition">
        产品BOM
      </button>
      <button data-page="tz/index.html" class="nav-btn w-full text-left px-4 py-2 rounded-lg bg-gray-700 hover:bg-gray-600 transition">
        物料查询
      </button>
      <button data-page="supplier/index.html" class="nav-btn w-full text-left px-4 py-2 rounded-lg bg-gray-700 hover:bg-gray-600 transition">
        供应商查询
      </button>
    </nav>

    <footer class="text-center text-gray-400 text-xs py-4 border-t border-gray-700">
      © 2025 德令哈采购管理部
    </footer>
  </aside>

  <!-- 右侧内容区 -->
  <main class="flex-1 p-6 overflow-auto">
    <div id="content" class="bg-white rounded-xl shadow p-4 min-h-[80vh]">
      加载中...
    </div>
  </main>

  <script>
    // 默认加载第一个模块
    window.addEventListener('DOMContentLoaded', () => {
      loadPage('CP/index.html');
    });

    // 点击切换模块
    document.getElementById('nav').addEventListener('click', (e) => {
      if (e.target.classList.contains('nav-btn')) {
        document.querySelectorAll('.nav-btn').forEach(btn => btn.classList.remove('active'));
        e.target.classList.add('active');
        const page = e.target.getAttribute('data-page');
        loadPage(page);
      }
    });

    // 动态加载页面
    async function loadPage(url) {
      const contentDiv = document.getElementById('content');
      contentDiv.innerHTML = '<div class="text-gray-500 animate-pulse">页面加载中...</div>';
      try {
        const response = await fetch(url);
        if (!response.ok) throw new Error('加载失败');
        const text = await response.text();
        // 提取body内部内容（避免重复<head>样式）
        const inner = text.match(/<body[^>]*>([\s\S]*)<\/body>/i);
        contentDiv.innerHTML = inner ? inner[1] : text;
      } catch (error) {
        contentDiv.innerHTML = `<div class="text-red-500">❌ 无法加载页面：${url}</div>`;
      }
    }
  </script>

</body>
</html>

很好，你发现的这个问题非常关键。 这不是脚本逻辑错误，而是由 fetch() 加载本地文件的浏览器安全策略引起的。让我们来拆开看：

---

🧠 原因解释

在浏览器里直接双击打开 index.html（即 file:// 协议）时， fetch("bom/index.html") 这类请求会被浏览器默认禁止，因为本地文件系统访问被视为跨源请求（CORS 限制）。

所以表现是： ✅ index.html 自己能打开 ❌ 其它页面加载时卡在“页面加载中…”

---

✅ 解决方案（3种任选其一）

方案 1：本地启动一个小型服务器（推荐）

这是最标准、最干净的办法。

如果你电脑上有 Python，可以在项目目录打开命令行，输入：

# Python 3
python -m http.server 8000

然后浏览器访问：

http://localhost:8000

此时所有 fetch() 都能正常加载到。

---

方案 2：放到 GitHub Pages / Vercel / Netlify

你之前已经在 GitHub 上部署过网页。 这个版本上传后，网页在 HTTPS 环境中访问（如 https://seamoonappear.github.io/...）， 同样不会触发本地安全限制，所有模块都会正常加载。

---

方案 3：仍用本地方式，但换成 iframe 版本

如果你确实只想本地打开文件（file://）， 那必须回到 iframe 方案，因为 iframe 能直接加载本地文件路径，而不会被 fetch 拦截。

---

⚙️ 小技巧：快速验证

如果你想确认是不是安全策略问题，可以打开浏览器控制台（F12 → Console） 看到类似：

Access to fetch at 'file:///C:/path/bom/index.html' from origin 'null' has been blocked by CORS policy

这就说明命中了 file 协议安全限制。

🚨 那为什么还在显示“加载中…”？

有一个微妙但非常常见的现象： GitHub Pages 返回的页面内容没有 <body> 标签匹配（因为有时 HTML 压缩或格式不标准）。

在我们的脚本里有这段：

const inner = text.match(/<body[^>]*>([\s\S]*)<\/body>/i);
contentDiv.innerHTML = inner ? inner[1] : text;

如果 GitHub 把返回的 HTML 改格式或压缩过，<body> 这一行就匹配不到，导致 inner 是 null， 页面内容其实被加载了，但没显示。

---

✅ 最简单修复办法

只要改这一行：

const inner = text.match(/<body[^>]*>([\s\S]*)<\/body>/i);
contentDiv.innerHTML = inner ? inner[1] : text;

改成：

const bodyMatch = text.match(/<body[^>]*>([\s\S]*)<\/body>/i);
const extracted = bodyMatch ? bodyMatch[1] : text;
contentDiv.innerHTML = extracted || '<div class="text-red-500">页面内容为空</div>';

或者更简单，直接替换整个加载函数为下面这个（最稳妥版本）：

async function loadPage(url) {
  const contentDiv = document.getElementById('content');
  contentDiv.innerHTML = '<div class="text-gray-500 animate-pulse">页面加载中...</div>';
  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error('加载失败');
    const text = await response.text();
    // 尝试提取 body，否则直接显示
    let inner = text.match(/<body[^>]*>([\s\S]*)<\/body>/i);
    if (inner && inner[1].trim().length > 0) {
      contentDiv.innerHTML = inner[1];
    } else {
      contentDiv.innerHTML = text;
    }
  } catch (error) {
    contentDiv.innerHTML = `<div class="text-red-500">❌ 无法加载页面：${url}</div>`;
  }
}

在 GitHub Pages 上，这种情况往往出在路径引用。 例如在你的主页面 index.html 中，JS 里用的是：

fetch('supplier/data.json')

但如果这个主页面位于根目录（https://trtjkqh.github.io/）， 浏览器实际请求的路径是：

https://trtjkqh.github.io/supplier/data.json

这没问题； 但如果你的子页面本身位于 /supplier/ 文件夹里， 那相对路径 supplier/data.json 会被解释成：

https://trtjkqh.github.io/supplier/supplier/data.json

→ 多了一层 supplier，于是就报“数据加载中”或 404。

---

✅ 解决方法之一是把所有 fetch 的路径改成绝对路径：

fetch('/supplier/data.json')

前面加一个 /，代表从网站根目录开始。

或者用完整网址：

fetch('https://trtjkqh.github.io/supplier/data.json')

---

为了统一所有模块（成品查询、产品BOM、物料查询、供应商查询）， 你可以在每个子页面的 JS 里检查类似的 fetch 语句：

fetch('bom/bom_data.json') → 改为 fetch('/bom/bom_data.json')
fetch('tz/data.json') → 改为 fetch('/tz/data.json')
fetch('cz/data.json') → 改为 fetch('/cz/data.json')
fetch('supplier/data.json') → 改为 fetch('/supplier/data.json')

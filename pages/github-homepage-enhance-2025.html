把悬浮粒子背景换成大小不一的 Logo

00145

00145 的诉求：背景上原本悬浮的圆形粒子，换成直径大小不一的 Logo。做法是保留粒子的运动特性，把圆形粒子替换成一张 Logo 图片，并加上旋转。

核心思路

  1. 用 <canvas> 绘制多个 Logo 实例。
  2. 每个 Logo 有不同直径、位置、移动速度和旋转角。
  3. 用 requestAnimationFrame 跑平滑动画。
  4. Logo 图加载完再开动画，避免空图。

关键参数（照录）

Logo 地址
https://cdn4.winhlb.com/2025/10/01/68dc359deeea1.jpg
直径
Math.random()*60 + 20，即 20–80px。
数量
logoCount = 屏宽×屏高 / 15000，随屏幕大小自适应。
透明度
random*0.5 + 0.3，即 0.3–0.8。
// Logo 类：位置/速度/旋转/透明度各自随机，出界后从另一侧移入 class Logo { constructor() { this.size = Math.random() * 60 + 20; this.speedX = (Math.random() - 0.5) * 1.5; this.speedY = (Math.random() - 0.5) * 1.5; this.rotation = Math.random() * 360; this.rotationSpeed = (Math.random() - 0.5) * 0.5; this.opacity = Math.random() * 0.5 + 0.3; } update() { this.x += this.speedX; this.y += this.speedY; this.rotation += this.rotationSpeed; // 出界回绕：x 超出画布就从 -size 重新进来 } draw() { ctx.globalAlpha = this.opacity; ctx.drawImage(logoImg, -this.size/2, -this.size/2, this.size, this.size); } }
性能要点：Logo 数量按屏幕面积算（除以 15000），避免小屏堆太多；窗口 resize 时重算 canvas 尺寸与 Logo 数组；内容卡片用毛玻璃 backdrop-filter: blur 压在背景之上，保证文字可读。

悬浮红心点赞按钮：陌生人也能点

00147

00147 的硬要求：文字不动、在不影响整体显示的前提下加一个红心点赞按钮，支持陌生人点赞（不用登录）。关键是用 localStorage 存状态，既防同一浏览器重复点，又不要求注册。

组成做法（照录）
按钮本体页面左下角悬浮 .heart-like，里面是 <i class="far fa-heart"> + 一个 .like-count 数字。
计数来源let currentLikes = parseInt(localStorage.getItem('pageLikes')) || 0。
防重复读 localStorage.getItem('hasLiked') === 'true'；已点过就 toast「您已经点过赞了！」，不再累加。
点赞动画点中后给按钮加 .liked，图标换实心 fas fa-heart，跑 heartBeat 0.6s 心跳关键帧。
提示.like-toast 显示「感谢您的点赞！」，2 秒后自动消失。
heartLike.addEventListener('click', function() { if (hasLiked) { showToast('您已经点过赞了！'); return; } currentLikes++; likeCount.textContent = currentLikes; localStorage.setItem('pageLikes', currentLikes); localStorage.setItem('hasLiked', 'true'); heartLike.classList.add('liked'); showToast('感谢您的点赞！'); // 实际项目把计数上报到服务端： // fetch('/api/like', { method:'POST', body: JSON.stringify({ page:'wangwei' }) }) });
localStorage 方案的边界（源笔记原话）
  • 同一浏览器里重复访问不会重复计数；不同浏览器/设备会各自独立计数。
  • 要跨设备汇总真实点赞数，必须接后端 API——源笔记留了 sendLikeToServer() 占位，注释里写明应替换为 fetch('/api/like', …)。

滚动进度条、返回顶部与访问统计

00147

00147 在同一轮优化里还加了三个「站点级」小部件：顶部滚动进度条、右下角返回顶部、页脚不蒜子 PV/UV 统计。都是纯前端、无后端。

滚动进度条

顶部 .progress-container（高 4px、fixed），里面 .progress-bar 宽度随 scrollTop / (scrollHeight - innerHeight) 变化，渐变填色。

返回顶部

右下角 .back-to-top 圆钮，初始 opacity:0; visibility:hidden；滚动超过阈值才加 .active 显现，点了 scrollTo(0,0)。

不蒜子 PV/UV

页脚引入 //busuanzi.ibruce.info/busuanzi/2.3/busuanzi.pure.mini.js（async），用 busuanzi_container_site_pv / _uv 两个容器挂本站总访问量与访客数。

搭配关系：00147 的主页同时保留了「红心点赞」和「不蒜子访客统计」——前者是交互反馈、后者是站点流量，两者互不依赖，都能纯前端跑。这也是 00148 后来拆子网页时明确要求「保留点赞和访客统计」的原因。

主页太复杂？拆成子网页标题导航

00148

00148 的转折：用户觉得主页一长页太杂，要求各板块改成子网页、主页只留标题。这正是把前面学的「子目录/子网页」用到自己身上。下面是源笔记沉淀下来的主页骨架。

00148 · 主页精简要求（照录）

主页只保留入口，内容拆出去

位置放什么
顶部个人头像往左放；头像右侧放「可拨打的电话」与「可一键复制的微信号」。
中间各板块只留标题（+图标），点进去才是子网页：健康集团、青海基地介绍、个人介绍、主要采购品类、工作目标、擅长领域、知识库、产品库。
底部正中放一个 logo，规格 285×65 像素；底部背景用黑底。
保留点赞功能 + 访客统计（即 00147 的红心与不蒜子）。

后续又迭代两轮：要求把「分类」从一排改分两行排布；产品子网页本身再做导航栏——传统渠道、电商渠道 3 区、其他、首页四个入口，每个用下拉列表展开。

「DOCTYPE 修改」这个文件名到底在说什么命名由来

这份笔记的标题里 <!DOCTYPE html> <html lang= 并不是在讨论文档类型声明——它只是用户每次提问时把当前主页的 HTML 头两行（<!DOCTYPE html>、<html lang="zh-CN">）原样粘进对话框，文件名就照抄了这两行。真正的内容是主页的一轮轮精修：渐变文字标题、毛玻璃弹窗、拆子网页、加视频。

在线视频播放器：旋转 90 度与横版适配

00148

00148 后半段连续追了几次视频需求：先给一个在线视频网址做播放页，再要求「只放一个视频、要简约」，接着要把播放器转 90 度、横版视频要完整展现、播放按钮要放在好点的位置。

需求迭代做法要点
在线播放 mp4用 <video controls autoplay> + <source src="在线mp4地址" type="video/mp4">，页面尽量留白、只放播放器。
播放器转 90 度给播放器容器套 CSS transform: rotate(90deg)，并配合调整宽高与定位，让旋转后仍居中、不溢出。
横版完整展现视频本身是横版，却只显示了一部分——用 object-fit: contain 让横版视频完整装入容器，再把播放/暂停/进度等控制条（插件）放到不遮挡画面、便于点击的位置。
<video id="player" controls autoplay playsinline> <source src="https://在线视频地址.mp4" type="video/mp4"> </video> /* 竖屏容器里把横版视频转正并完整显示 */ #player { width: 100%; height: 100%; object-fit: contain; } .rotate90 { transform: rotate(90deg); transform-origin: center; }
经验沉淀：在线视频最容易翻车的是「竖屏手机里横版视频只露一半」——根因是容器是竖的、视频是横的，光旋转不够，必须同时用 object-fit: contain 保证完整画面，再挪控制条位置。

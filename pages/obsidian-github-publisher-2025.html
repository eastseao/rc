Obsidian 自动发布 GitHub Pages 与 Git 同步

在手机或电脑上用 Obsidian 写文章，然后自动推送到 GitHub Pages。本手册把「怎么选方案、怎么装插件、怎么取 Token、怎么标发布、怎么排错」串成一条可照做的流程：Obsidian Git 全库同步、GitHub Publisher 选择性发布、Hexo Auto Updater 三套方案并列，BRAT 装插件与重新加载的坑逐一标注，仓库地址、manifest、命令名照录原笔记。

01

三套发布方案，先对号入座

00206 / 00210

核心区别在于「你对 Git 操作和网站生成流程的参与程度」：全库同步最省心，选择性发布最精细，Hexo 集成自动化最高。

方案核心插件做什么优点 / 适合谁
方案一 全库同步Obsidian Git自动把整个笔记库同步到 GitHub（建议私有仓库保护内容）；博客生成另行交给 Hugo / Jekyll 或 GitHub Pages。多设备同步简单；适合先解决笔记备份、博客生成独立的人。
方案二 选择性发布GitHub Publisher只把带 published: true 标记的笔记发布到指定仓库；可单篇或批量发布。内容管理灵活；适合精细控制哪些笔记成为公开博客。
方案三 Hexo 集成Hexo Auto Updater监控 _posts 文件夹变更，自动提交推送 Hexo 源仓库，触发 GitHub Actions 构建并部署到 Pages。发布流程自动化；适合已经用 Hexo、追求写作到部署全自动的人（配置也最复杂）。
选法：只想整库备份或博客流程独立 → Obsidian Git；要控制哪些笔记公开 → GitHub Publisher；已用 Hexo 要全自动 → Hexo Auto Updater。无论哪套，建议根目录建 .gitignore 忽略 .obsidian/、.DS_Store、Thumbs.db；大量图片用 Git LFS 管理避免仓库膨胀。
02

准备：建仓库 + 生成 Personal Access Token

00206 / 00327

两条路（GitHub Publisher 与 Obsidian Git）都要 GitHub 凭证。先建仓库，再拿令牌。

建仓库

仓库怎么建

Pages 仓库
建 你的用户名.github.io 作为 User 站点；或任意命名仓库，在 Settings → Pages 里开启。博客公开就设为 public；笔记整库备份建议设为 私有。
本地关联
把远程仓库克隆到本地，或把本地笔记文件夹 git init 后关联远程。
Git 身份
首次提交前先配全局身份：git config --global user.name '你的用户名' 与 git config --global user.email '你的邮箱'。
Token

生成 Personal Access Token（classic）

  1. 登录 GitHub，点右上角头像 → Settings。
  2. 页面一直滚到最底部左下角，进 Developer settings（不在左侧导航显眼处）。
  3. 选 Personal access tokens → Tokens (classic) → Generate new token (classic)。
  4. 起个好认的名字（如 Obsidian Sync），设过期时间；权限务必勾 repo（至少 Contents 读写）。
  5. 生成后立即复制保存——关掉页面就再也看不到，只能重生成。令牌以 ghp_ 开头。
用户名：你的 GitHub 用户名（不带 @） Password / Token 栏：粘贴上一步的 Personal Access Token（以 ghp_ 开头） ↳ 这里显示 "Password"，但填的是令牌，不是 GitHub 登录密码。
03

安装插件：三条路

00206 / 00211 / 00327

找不到「GitHub Publisher」是最常见的卡点。社区市场、手动、BRAT 三条路，按可用性依次试。

安装方式操作适用
社区市场（首选）设置 → 第三方插件，关闭安全模式 → 浏览 → 搜 GitHub Publisher → 安装 → 启用。网络正常、插件已上架。
BRAT（最可靠）装 Beta Reviewer's Auto-update Tool（作者 TfTHacker）→ Ctrl+P → BRAT: Add a beta plugin → 粘贴 https://github.com/ObsidianPublisher/obsidian-github-publisher → Ctrl+R 重载 → 启用。市场搜不到、装测试版。
手动从 releases 下 zip，解压到 你的库/.obsidian/plugins/obsidian-github-publisher/，确保含 main.js、manifest.json、styles.css，重启后启用。BRAT 也失败时。
Obsidian Git 插件同理：市场搜全称 Obsidian Git（不是「Git」）；BRAT 里填 https://github.com/Vinzent03/obsidian-git。BRAT 需 Obsidian 0.13.8+，GitHub Publisher 需 0.15.0+。
04

GitHub Publisher 配置与发布

00206 / 00209

配置分两层：插件设置面板填全局规则，每篇笔记的 Frontmatter 决定这篇发不发。

插件面板

必须填的四项 + 发布行为

GitHub Username: 你的用户名 GitHub Repository: 你的仓库名（如 username.github.io） GitHub Branch: main（旧仓库可能是 master） GitHub Token: 粘贴 ghp_ 开头的令牌 ☑ Upload images ☑ Upload attachments Image folder: images Attachment folder: attachments ☑ Convert wikilinks to markdown links ☑ Automatically clean the title Frontmatter key to publish: published Value to publish: true
Frontmatter

单篇发布标记

笔记开头 YAML 里写上 published: true 才会被发布；草稿就写 false。

--- title: "我的第一篇博客文章" date: 2024-01-15 published: true tags: - 教程 - Obsidian ---
发布动作

怎么触发发布

方式命令 / 操作
单篇发布Ctrl+P → GitHub Publisher: Publish active file；或编辑器右键 Publish this file。
批量发布GitHub Publisher: Publish all changed shared files（发布所有 published: true 且有改动的笔记）。
查看/取消Show shared settings 看状态；Unpublish active file 或把 published 改 false 取消。

发布后去仓库刷新看文件是否出现；若用 Jekyll 会自动构建，访问 https://你的用户名.github.io 看效果。

05

Obsidian Git 全库同步配置

00210 / 00327

走方案一：装 Obsidian Git 后，把自动提交/拉/推的间隔打开，让它定期帮你备份整个库。

自动同步

核心开关

自动提交同步
开 Auto commit-and-sync interval(minutes)，设间隔（如 5 / 20 / 30 分钟）；开 Auto pull interval。
启动拉取
开 Pull updates on startup，每次打开 Obsidian 先拿远程最新。
自动推送
开 Auto push，每次提交后自动推到远程。
Git 路径
报「找不到 Git」时，终端 where git（Windows）查路径，填进 Custom Git binary path。
首次提交
先 Ctrl+P 跑一次 Obsidian Git: Create backup 做初始提交，再开自动同步。
移动端注意：手机端也要装并配同款插件，多为手动 Pull/Push；不支持 SSH 认证，大库性能差，建议移动端关自动提交改手动。遇 Git 安全目录错误，终端跑 git config --global --add safe.directory "你的笔记库完整路径"。
06

排错与验证

00206 / 00211

这套流程最大的坑是「装了插件却没有命令」。按顺序排。

命令不出现：先重载，再彻底重装高频
  • 第一动作永远是重载：Ctrl+R（Mac Cmd+R）。装插件后、启用后、改配置后都要重载一次。笔记内容自动保存，不会丢。
  • 确认开关是蓝色开启，且在「已安装的插件」列表里找（不要在「浏览」里找），按 G 开头排序。
  • 仍没有命令：BRAT: Remove a beta plugin 移除 → 删掉 .obsidian/plugins/obsidian-github-publisher 残留文件夹 → 完全重启 → 重新 BRAT 添加仓库地址 → 启用 → 再 Ctrl+R。
  • BRAT 命令也不出现：说明 BRAT 本身没加载——确认它已启用、关安全模式、Ctrl+R；必要时备份并删除 .obsidian/community-plugins.json 与 plugins.json 后重启。
加载失败 / 启动即崩：查清单与冲突manifest
  • 文件齐全：插件目录必须含 main.js、manifest.json、styles.css。
  • manifest 正常：id 应为 obsidian-github-publisher，name 为 GitHub Publisher，minAppVersion 不高于你的版本。
  • 版本：设置 → 关于，确认 Obsidian 版本够新（Publisher 需 0.15.0+）。
  • 冲突：除 Publisher 与 BRAT 外禁用其他插件，重载后看命令是否出现；出现则逐个启用定位冲突。
  • 看控制台：Ctrl+Shift+I → Console 看红色报错。
发布报错对照表认证/路径
现象解决
Bad credentialsToken 失效或没勾 repo 权限，重生成。
Not Found / 仓库不存在核对仓库名拼写与访问权限。
笔记没发布Frontmatter 缺 published: true。
图片不显示勾了 Upload images、图片路径正确、文件别太大。
最终验证清单打勾
  • 插件在已安装列表、开关蓝色、重载后保持蓝色；设置左侧出现插件项。
  • Ctrl+P 输入 GitHub Publisher 能看到 Publish active file / Publish all changed shared files / Unpublish active file / Edit settings / Show shared settings。
  • 发一篇带 published: true 的测试笔记，仓库里能看到文件，Pages 能打开。

顺带：Obsidian 的功能、代价与价格

00864

选这套工作流前，先知道 Obsidian 本身的长短板和收费——核心功能免费商用也免费。

优点

本地优先纯 Markdown、数据归你所有；双向链接 + 知识图谱串起知识；超千款社区插件生态；启动搜索都快；核心功能个人完全免费。

缺点

有学习曲线；无原生实时协作，不适合团队；移动端体验弱（Android 偶有乱插字符、键盘失灵）；高级功能高度依赖插件，存在插件失维风险。

许可证 / 服务价格说明
免费使用$0所有核心功能，含商用。
Catalyst$25 一次性抢先体验测试版、社区徽章。
商业许可证$50 / 用户 / 年功能与免费版完全相同，性质是支持性徽章；按席位不按设备。
Obsidian Sync$4 / 用户 / 月（按年）跨设备同步、端到端加密、版本历史。
Obsidian Publish$8 / 站点 / 月（按年）把笔记库发布为网站（官方付费方案；本页讲的是用 GitHub Publisher 免费替代）。

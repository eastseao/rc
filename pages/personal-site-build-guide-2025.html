01

三种建站路径，先选方向再动手

00142 / 00159

源笔记把「个人网站怎么建」归成三条路：可视化平台、静态站点生成器、自托管。对新手最友好的是静态生成器里的 Jekyll——它与 GitHub Pages 原生集成，连本地环境都可以不装，直接在网页上写 Markdown 就出页面。

路径代表工具适合谁 / 代价
可视化平台WordPress、Wix、各类建站 SaaS拖拽即用，最快上线；但受制于平台模板与计费，自由度低，数据不在自己手里。
静态站点生成器Jekyll（Ruby）、Hugo、Hexo（Node.js）把 Markdown 编译成静态 HTML，托管在 GitHub Pages 免费；Jekyll 与 Pages 原生集成，Hexo 需本地装 Node 并命令行部署。
自托管自己租服务器、装 Nginx/Node自由度最高，要管运维、域名、备案；对纯静态个人主页属于杀鸡用牛刀。

Jekyll：与 GitHub Pages 无缝集成

GitHub Pages 原生支持 Jekyll，可直接在线编辑，无需本地装复杂环境。写文章就是在仓库里建 _posts/年-月-日-标题.md，文件头带一段 YAML Front Matter。

# _config.yml 应用默认主题 theme: minima

Hexo：灵活但要本地命令行

Node.js 驱动，先装 Node.js 与 Git，再用命令行初始化、本地预览、生成并推送。

npm install hexo-cli -g hexo init blog && cd blog && npm install hexo server # 预览 http://localhost:4000 hexo clean && hexo generate && hexo deploy
源笔记结论：新手强烈推荐 Jekyll 路线——仓库建好、Pages 一开、写 index.md 或 index.html 就能上线；主题在 _config.yml 里改 theme 一行即可切换，NexT、码志等简约主题社区常用。
02

新账号到上线：GitHub Pages 起步五步

00159 / 00142

注册完 GitHub 账号，核心只有两步硬规则：仓库名必须叫 <你的用户名>.github.io、仓库设为 Public。其余都是在这之上填内容、开 Pages。

00159 · 2025-10-03

三阶段流程：建仓 → 写内容 → 开 Pages

阶段操作关键点
1 建仓右上 + → New repository；Repository name 填 用户名.github.io；设 Public；可勾 Add a README仓库名必须与用户名完全一致、大小写敏感。这是个人主站点的固定命名。
2 写内容Add file → Create new file，建 index.md（或 index.html）；再建 _config.yml 写 theme: minima主页文件必须在仓库根目录，不能藏在子文件夹里。
3 开 PagesSettings → 左侧 Pages → Source 选 Deploy from a branch、分支选 main / /(root)；保存等 1–10 分钟，访问 https://用户名.github.io。
# index.md 主页最小示例 --- layout: home title: 首页 --- # 欢迎来到我的博客！ 这里是我的个人空间。 # _config.yml title: "我的博客" description: "欢迎来到我的个人博客" theme: minima url: "https://用户名.github.io"
404 打不开时，按这五点排查
  • 仓库名是否严格等于 用户名.github.io（拼写、大小写都要对）。
  • Settings → Pages 的发布分支是否选对（main / master），文件夹为 /(root)。
  • 根目录下是否真有 index.html / index.md，且文件已 Commit 成功。
  • 看 Actions 标签里的构建日志——构建失败时日志会写明原因（插件不兼容、语法错误等）。
  • 纯静态框架项目可在根目录放空文件 .nojekyll，让 Pages 跳过默认 Jekyll 构建（它默认会忽略下划线开头的目录）。
为何能访问 用户名.github.io/github.io/ 却打不开主站？命名纠偏

源笔记里的真实案例：用户只能通过 https://hdbuyer.github.io/github.io/ 访问，标准主站却 404。原因是网站文件存放在名为 github.io 的仓库里——那是一个项目站点，URL 必然带项目名；而个人主站点要求仓库名必须是 hdbuyer.github.io。

访问 URL对应仓库
https://hdbuyer.github.io仓库名应为 hdbuyer.github.io，GitHub 直接从该仓库根目录提供文件。
https://hdbuyer.github.io/github.io/仓库名是 github.io，属项目站点，URL 里必须带项目名。

修正：进入 github.io 仓库 → Settings → Repository name 改成 hdbuyer.github.io，确认主页文件在根目录、发布分支正确即可。

怎么删 GitHub 仓库（误建的库）Danger Zone

网页端删单个仓库：进入仓库 → Settings → 滚到底 Danger Zone → 点 Delete this repository → 在弹窗里输入要删的仓库名确认（可能还要输 GitHub 密码）。删除后代码、Issues、PR、Wiki 都会丢失，删前务必备份；若只是不想公开，可先把仓库设为 Private 作为缓冲。批量删库需 Personal Access Token，配合官方 API 脚本或 del-repos 类工具。

03

Jekyll Chirpy 主题：纯网页操作搭博客

00229 / 00230

Chirpy 是 Jekyll 上一款流行博客主题。源笔记分别用两个账号实操：seamoonappear / blog 与 hdbuyer / blog，结论一致——不装本地环境，全程在 GitHub 网页上点模板、改配置、写 Markdown 就能上线。

00229 / 00230

三阶段：模板建仓 → 开 Actions → 写文章

阶段网页操作（照录）
① 用模板建仓打开 cotes2020/chirpy-starter 模板仓库 → 右上绿色 Use this template → Create a new repository（不要直接 Fork）。想走 用户名.github.io 主站就把仓库名定为 用户名.github.io；源笔记实际用的是仓库名 blog，于是访问地址变成 https://用户名.github.io/blog/。设 Public，Create repository from template。
② 开 Pages + Actions仓库 → Settings → 左侧 Pages → Build and deployment 的 Source 从 Deploy from a branch 改成 GitHub Actions。回到顶部 Actions 标签，能看到一条 Build and Deploy 工作流自动触发，等它全绿（约几分钟）。
③ 改配置 + 写文章编辑根目录 _config.yml 把 url 等填对；进 _posts → Add file → Create new file，文件名 YYYY-MM-DD-标题.md，开头写 Front Matter，Commit。每次提交都自动触发重建。
# _posts 文章最小头部（Front Matter） --- title: "欢迎来到我的博客" date: 2025-10-12 20:00:00 +0800 categories: [随笔] tags: [欢迎] --- ## 这是我的第一篇文章 你好，世界！

_config.yml 关键配置项

url
完整站点地址。仓库名为 blog 时应为 https://用户名.github.io；若用 blog 子路径需另设 baseurl。
baseurl
源笔记实测：仓库名叫 blog 时必须设 baseurl: "/blog"，否则 CSS/JS 资源路径 404。本地预览用 bundle exec jekyll s --baseurl /blog。
theme
jekyll-theme-chirpy。
lang / timezone
lang: zh-CN、timezone: Asia/Shanghai。
plugins
jekyll-sitemap、jekyll-feed、jekyll-paginate、jekyll-seo-tag。
permalink
/posts/:title/。

可选：Giscus 评论系统

Giscus 基于 GitHub Discussions，免费。三步走：

  • 访问 github.com/apps/giscus 点 Install，授权访问你的博客仓库。
  • 仓库 Settings → Features 勾选 Discussions。
  • 到 giscus.app/zh-CN 选仓库，页面生成 repo / repo_id / category / category_id，填回 _config.yml 的 comments 段。
comments: active: giscus giscus: repo: 用户名/仓库 repo_id: YOUR_REPO_ID category: Announcements category_id: YOUR_CATEGORY_ID mapping: pathname

排错 · HTML-Proofer 报 JS 文件不存在

Build failed：theme.min.js / page.min.js 等 internal script reference does not exist

源笔记实战：用 blog 仓库存 Chirpy 模板后，GitHub Actions 跑 HTML-Proofer 时一次性报 113 个失败，全是 /assets/js/dist/*.min.js does not exist。根因是 Chirpy 依赖特定构建步骤生成这些压缩 JS，远程直接 Fork/模板出的仓库可能缺 assets/js、tools 等关键目录。解决：核对仓库目录结构是否完整；本地补 bundle install + npm install 后 bundle exec jekyll b；临时可在工作流里注释掉 htmlproofer 步骤或加 --disable-external；并复查 baseurl 是否设为 /blog。

移动端个人主页：一页式名片怎么排

00142

00142 用一个真实场景反复迭代：一位常驻杭州、供职北京同仁堂健康药业（青海）的包装采购从业者，要在手机上跑一张「个人名片页」。源笔记把这页从占位头像一路改到真人头像、加微信、调采购品类与目标——下面是沉淀下来的设计骨架。

页面从上到下的结构

资料区
渐变 banner 通栏，圆形头像（在线图片 URL，源笔记从 120px 放大到 160px）、姓名、公司头衔、常驻地点、电话/微信两个 CTA 按钮。
个人简介卡
三条技能：成本优化（省 15-20%）、供应商资源（50+ 长期合作）、质量管控严格。
擅长卡
包装材料专业知识、行业资源整合（源笔记中途去掉了「采购流程优化」一段）。
采购品类卡
包装制品 → 内包装品类 → 食品包装材料三段，照用户要求调过顺序、补了内包装。
三大目标卡
左侧 Logo 图 + 右侧三条：质量保证 / 成本控制 / 供应链稳定。

微信弹窗与头像替换

「添加微信」按钮弹出 modal，源笔记要求去掉二维码、只留微信号 EastSeaO 并支持一键复制：

const wechatId = 'EastSeaO'; navigator.clipboard.writeText(wechatId).then(...) // 降级：临时 textarea + execCommand('copy')

真人头像用方法一（在线图片 URL），删掉本地占位方案：

<img src="https://你的头像URL" alt="王维">
00142 · 采购铁三角

采购岗位三大核心目标（用户原文沉淀）

目标性质具体体现（照录）
1 降本增效成本目标不只是压价，而是策略性手段实现总拥有成本最低：价格谈判、全生命周期成本管理（物流/仓储/维护/运营/报废）、流程优化、价值工程与分析。
2 保障供应风险与稳定正确时间、地点、数量到货：供应商关系管理、供应链风险管理（政治/灾害/供应商财务危机，建备用方案）、交期管理、库存优化。
3 保证质量价值与合规符合质量标准、技术规格与法规：验收标准与来料检验、供应商质量审核、合规管理（RoHS、REACH）、推动持续改进。
三者关系（源笔记原文）：成本、质量、供应构成「采购铁三角」，相互制约需找最佳平衡点——单纯追低成本会掉质量或断供，过度追高质量会成本陡升，只盯供应稳定会损害利润。优秀采购的核心价值就是在三者间找最优解，从被动「下单者」转为主动「价值创造者」。
05

Markdown 个人网页的演进与文章推送

00160

00160 是一个 md 个人网页从「能看」到「好用」的连续迭代：先把浮动导航改成左侧边栏，再把文章列表改成卡片表格，最后落到 Jekyll 目录结构；同时解决「文章怎么自动推送、怎么自动打标签」两件事。

迭代阶段解决的问题
浮动导航 → 左侧边栏顶部浮动导航在长文章里频繁遮挡正文；改成左侧固定边栏后，阅读区与导航分离，滚动更顺。
文章列表 → 卡片表格纯文字列表看不出差异；卡片表格把标题、日期、分类、摘要分栏，扫读更快。
单页 → Jekyll 目录结构多页共用导航/页脚要重复维护；落到 _posts、布局模板后，新增文章只需放一个 md 文件。

文章推送的三条路

  • GitHub API：程序调用接口直接往仓库写 md 文件，适合自己做发布端。
  • Webhooks：仓库收到 push 后触发外部服务，做即时重建与通知。
  • Jekyll 静态生成：提交 md 到 _posts，GitHub Actions 自动编译成 HTML——最省心，也是前两节 Chirpy 走的路。

自动打标签：关键词规则

源笔记的做法是关键词命中规则：在 md 正文/标题里预置关键词表，命中某组关键词就自动给文章挂上对应标签，省去手动维护 Front Matter 的 tags。例如命中「采购/包装/成本」归到效率工具类，命中「Jekyll/GitHub Pages」归到建站类。

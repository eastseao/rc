00

Skill 到底是什么

来源：072 / 2026-09-09

如果把一个 Agent 比喻成一个人，Skill 不是 Agent 本身，而是 Agent 拥有的"可调用专业能力"——它等于专业技能 + SOP + 工作方法。Agent 不需要每次重新学，只需要走五步：发现 → 判断相关性 → 加载 → 执行 → 验证。

Agent 组件类比人
LLM大脑
System Prompt基本行为准则
Context当前工作记忆
Memory长期记忆
Tool手和工具
MCP工具连接协议
Skill专业技能 + SOP + 工作方法
Workflow工作流程
Agent一个能自主工作的员工
Multi-Agent一个组织
Runtime工作环境
Evaluation绩效考核
Learning培训
Policy公司制度
核心公式：个人 Skill = 你的经验 + 你的方法 + 你的判断规则 + 你的案例 + 你的输出标准 + AI 可执行流程。成熟 Skill 的完整生命周期：触发 → 理解任务 → 加载知识 → 调用方法 → 执行 → 判断 → 输出 → 自检 → 修正 → 记录经验 → Skill 升级。
01

多文件目录结构

来源：009 / 012 / 015 / 072

早期会话把 Skill 写成一个 SKILL.md 单文件；后续逐步演进为"SKILL.md 负责决策、references 负责知识、templates 负责复用、examples 负责示范"的多文件五件套。

最简结构（早期） 
skill-name/
└── SKILL.md
生产级结构（后期） 
skill-name/
├── SKILL.md           # 决策层
├── config.yaml        # 配置
├── prompts/           # 多场景 prompt
├── engines/           # 引擎逻辑
├── database/          # 数据
├── templates/         # 输出模板
├── references/        # 规则/知识
└── examples/          # 样例

四层分工原则（072 总结）

SKILL.md
核心入口。只放"什么时候用这个 Skill、按什么决策、调用哪些 references"。不把所有规则都塞进来。
references/
知识层。layout-patterns.md、component-library.md、decision-rules.md、compatibility.md 等，按需加载。
templates/
复用层。knowledge.md、research.md、strategy.md、comparison.md、project.md、tutorial.md。
examples/
示范层。before-after.md、complex-report.md，教 Agent 怎么用。

这就是 Progressive Disclosure（渐进式披露）：SKILL.md 永远只加载最小决策集，遇到具体场景再去 references/ 里取需要的那块。不要把 200 行规则全塞进一个 SKILL.md。

02

YAML Frontmatter 标准

来源：004 / 005 / 011

SKILL.md 顶部的 YAML 头是 Agent 用来"发现"这个 Skill 的元数据。字段写不全，Agent 就不知道什么时候该调用它。

---
name: wechat-viral-writer
description: >
  写公众号爆款文，从选题、标题、开头、结构到结尾的全流程。
  适用于已有素材需要改写成公众号风格的场景。
author: gervas
version: 1.0.0
tags: [公众号, 写作, 内容营销]
inputs:
  - 用户原始素材
  - 目标读者画像
outputs:
  - 标题 ×3
  - 正文全文
  - 摘要 + 标签
tools: []
capabilities:
  - 标题生成
  - 结构编排
  - 语气调整
---
description 最关键：它是 Agent 判断"要不要加载这个 Skill"的唯一依据。写"一个写作工具"等于没写；要写清"输入是什么、输出是什么、什么场景该用"。
03

三种 Skill 类型与 Agent 设计四层级

来源：015 / 032

不是所有 Skill 都长一个样。按复杂度分三档，按 Agent 整体设计分四层。

类型特征例子
单文件 Prompt 型一个 SKILL.md 搞定，无脚本无数据去 AI 味、Markdown 排版
多文件参考型SKILL.md + references/ + templates/，无脚本自适应排版、市场调研
引擎型 Skill带 engines/ + database/ + config.yaml，有评分/状态机TopicClusterEngine、Supplier Scorecard

Agent 设计四层级（032 升级方案）

  1. L1 身份层：identity.md + soul.md，定义是谁、怎么思考。
  2. L2 能力层：skills/ 目录，每个 Skill 是一个独立能力单元。
  3. L3 流程层：workflow.md，定义多步任务怎么拆、怎么串。
  4. L4 数据层：database/ + memory/，沉淀历史决策、案例、知识库。

早期只写 L1 + L2；要做工业级，必须补 L3 和 L4。WeChatHotArticleExtractor、supplier-intel V2 都是按这个四层级重构的——加了评分系统（L4）和多步工作流（L3）。

04

V2 升级路径

来源：037 / 032

V1 是"能用"，V2 是"可复用、可评分、可审计"。升级的核心不是加功能，是把判断逻辑显式化。

评分系统
supplier-intel V2：质量 30% / 成本 20% / 交付 20% / 服务 15% / 创新 10% / 风险 5%。每个维度给依据，不允许拍脑袋打分。
反向生成
先画你想要的最终输出长什么样，再反推 prompt，不要从 prompt 开始硬写。
QC 自检
输出前跑一遍 Checklist：事实对不对、数字有没有出处、合规有没有风险。
05

12 套学习型 SKILL 体系

来源：058 / 2026-05-28

当目标是"教一个 Agent 学会怎么设计 Agent"时，需要把 Agent 工程本身拆成 12 个可训练的 Skill。每个 Skill 负责一个能力维度。

Skill训练什么
AgentConceptTrainerAgent 基础概念：是什么、能做什么、不能做什么
PromptEngineeringTrainerPrompt 写法：角色、任务、约束、输出格式
MemoryArchitect记忆系统设计：短期/长期/工作记忆怎么分层
ToolUseMaster工具调用：什么时候用工具、怎么写工具描述
WorkflowDesigner工作流：多步任务怎么拆、状态怎么传
RAGKnowledgeBuilder知识库：切片、索引、检索、召回
MultiAgentSimulator多 Agent 协作：分工、通信、冲突解决
AutonomousAgentLab自主 Agent：Planning、ReAct、反思
AgentProjectGenerator从需求到项目骨架：目录、文件、配置生成
AgentDebugger调试：输出不对时怎么定位、怎么修 prompt
AgentCaseLibrary案例库：收集好案例和坏案例，做 few-shot
DailyAgentTrainer日常训练：每天一个小任务，持续打磨
落地建议：不要一次建 12 个。先做三个"母 Skill"——分析（看资料→找事实→找规律→结论）、创作（信息→策略→表达→成品）、决策（多方案→判断→筛选→推荐）。再从这三个向下拆，逐步长成你的 Personal Skill OS。

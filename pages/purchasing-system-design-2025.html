01

包装采购数据管理系统设计

00373 · 2025-10-31

起因很具体：一位包装采购电脑里散落着产品信息表、产品 BOM、采购台账等多个 Excel，问怎么用网页前端把它们串起来。这一轮从仪表盘原型起步，历经「加本地存储 → Tailwind 优化 → 整合物料单价查询 → 统一到青海厂内部管理工具中心 → 修正数据加载路径 → 设计供应商信息表 → 单独抽出 supplier 页面」共八轮迭代。

00373 · 2025-10-31

系统定位与设计思路

散落的数据文件在系统里的角色
产品信息表记录产品基本属性，作为基础档案先导入。
产品 BOM物料清单，关联产品与所需包装材料。
采购台账记录采购历史与供应商信息，最后导入。

设计目标是一个仪表盘，让采购员能够：直观查看各类数据、通过产品 ID 关联所有相关信息、快速查询和筛选数据、生成简单统计报告。系统提供五大核心功能模块：

功能模块职责
数据仪表盘关键数据统计概览（产品总数 / 活跃 BOM / 待处理采购 / 合作供应商），快速访问常用功能。
数据导入分别导入产品信息表、BOM 和采购台账，支持 Excel / CSV。
产品信息管理查看所有产品基本信息，管理产品状态（活跃 / 待审核 / 已停产）。
产品关联数据通过产品 ID 关联 BOM 和采购记录，查看物料清单与采购历史。
采购台账管理记录所有采购订单，跟踪采购状态（已完成 / 运输中 / 已下单）。
数据串联方式（照录）
  • 产品 ID 作为关键字段：所有数据表都包含产品 ID，作为关联的基础。
  • 统一数据视图：选择一个产品后，系统自动显示其 BOM 和采购历史。
  • 数据交叉引用：在采购台账中可直接查看对应产品的 BOM 信息。

导入顺序建议：先导产品信息表建档 → 再导 BOM 关联产品与物料 → 最后导采购台账记录历史，系统按产品 ID 自动关联。系统可直接在浏览器运行，无需安装额外软件。

关键实现片段：存储、数据引用与加载

纯前端实现，数据存浏览器 localStorage，页面刷新后仍保留，支持导出 JSON 备份；清除浏览器数据会丢数据，建议定期导出。整合到「青海厂内部管理工具中心」后，各模块独立加载、避免冲突，数据引用路径如下：

功能模块数据文件路径
成品信息CP/data.json
产品 BOM 查询bom/bom_data.json
物料单价查询tz/data.json

修正版（页面落到 kanban/index.html 后）改用相对路径并加备用路径与 safeFetch 兜底，用 Promise.all 同时加载、仪表盘统计在加载完成后自动更新：

// 修正后的数据加载路径
../CP/data.json
../bom/bom_data.json
../tz/data.json

// 备用路径，增加兼容性
./CP/data.json
./bom/bom_data.json
./tz/data.json

// Promise.all 同时加载所有数据，加载状态实时更新
Promise.all([loadCP(), loadBom(), loadTz(), loadSupplier()]);
技术选型演进：首版用 Bootstrap 5.3 + Font Awesome（CDN），后按要求改用 <script src="https://cdn.tailwindcss.com"> 的 Tailwind 工具类重写表格——斑马纹用 even:bg-gray-50 odd:bg-white、悬停用 hover:bg-gray-100、宽表用 overflow-x-auto 包裹实现横向滚动。

00378 · 2025-11-01

代码修正：中文字段映射与 Excel 日期转换

真实的 data.json 用的是中文键名，且「合作起始日期」是 Excel 序列数 44941、「合作状态」是中文（如「已终止」）。前端此前按英文驼峰字段取值，导致页面读不出数据。修正核心是在 loadSuppliersFromJSON 里加一层映射：

// 转换数据格式，将中文字段映射到英文字段
const convertedData = data.map(item => ({
  id: item["供应商编号"].toString(),
  name: item["名称"],
  shortName: item["简称"],
  contactPerson: item["联系人"],
  phone: item["联系电话"].toString(),
  backupPhone: item["备用电话"] ? item["备用电话"].toString() : '',
  address: item["公司地址"],
  category: item["供应品类"],
  mainProducts: item["主要产品"],
  startDate: convertExcelDate(item["合作起始日期"]),
  status: convertStatus(item["合作状态"]),
  creditRating: item["信用等级"],
  remarks: item["备注信息"] || ''
}));

配套两个转换函数——把 Excel 日期序列（自 1900-01-01 起算）转成 YYYY-MM-DD，把中文状态转成代码用的英文状态码：

function convertExcelDate(excelDate) {
  if (typeof excelDate === 'number') {
    // Excel日期序列是从1900-01-01开始
    const date = new Date((excelDate - 25569) * 86400 * 1000);
    return date.toISOString().split('T')[0];
  }
  return excelDate;
}

function convertStatus(chineseStatus) {
  switch(chineseStatus) {
    case '合作中':   return 'active';
    case '待审核':   return 'pending';
    case '暂停合作': return 'inactive';
    case '已终止':   return 'terminated';
    default:         return 'active';
  }
}
修正点内容
数据字段映射在 loadSuppliersFromJSON 加转换逻辑，把 data.json 中文字段映射到代码用的英文字段。
日期转换新增 convertExcelDate，把 Excel 日期序列转成标准 YYYY-MM-DD。
状态转换新增 convertStatus，把中文状态转成英文状态代码。
品类选项修正把品类筛选与表单中的「包装材料」改为「包装」，与数据保持一致。
示例数据修正更新示例数据的品类与状态，与 data.json 保持一致。
容错设计：JSON 加载失败时退回 localStorage 已有数据；本地也没有时再用一条内置示例数据兜底，并在页面显示「数据实时更新，本地存储 / 保密声明：内部数据，严禁外传」提示条。

采购需求页面前端修复

00190 / 00338 / 00342

三个小而具体的前端问题：三个需求标题看不见、页面配色要调、页面脚注提示语要润色。统一按「问题 → 原因 → 改法」对照。

标题显示问题（00190 · 2025-10-09）

问题
首页三个需求标题（外包装需求、内包装需求、原料需求）没显示出来。
原因
三个 h3 用了白色文字，而卡片背景偏浅，文字与背景对比度不足，等于"隐身"。
改法
为三类卡片的 h3 加专门 CSS，保留白色并叠一层文字阴影兜底：
.procurement-section.outer-packaging-card h3,
.procurement-section.inner-packaging-card h3,
.procurement-section.raw-material-card h3 {
  color: white;
  text-shadow: 0 2px 4px rgba(0, 0, 0, 0.5);
}

同一篇笔记后续又把这三个标题 color 由 white 改为 #f39c12（橙色），保留文字阴影，使其在蓝 / 绿 / 紫背景上都有对比度。

页面颜色调整（00338 · 2025-10-27）

改动一
移除头像与联系方式：删头像区、姓名 / 职位 / 位置、顶部联系按钮；导航栏边距与圆角随之调整，页面更聚焦采购需求内容。
改动二
三个二级标题重新配色：外包装需求 → #ffeb3b（黄）；内包装需求 → #8bc34a（浅绿）；原料需求 → #ff9800（橙）。
保留
供应商登记表、采购需求详细列表、底部联系按钮、微信弹窗、滚动进度条与返回顶部按钮均不变。

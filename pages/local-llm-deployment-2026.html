02

和本地模型聊天，能让它变聪明吗

00791 · 2026-03-24

结论先行：单纯聊天无法永久提升本地大模型的知识或能力。差别在模型是怎么跑起来的。

静态模型（Ollama / LM Studio / llama.cpp）

部署后权重是冻结的：每次聊天只基于训练时数据推理，对话历史只活在当前会话的上下文窗口里；关窗即「失忆」，不会因为聊得久就变聪明。

带「长期记忆」的实验架构

如 MemGPT、LangChain 记忆模块，会把对话总结存进向量数据库，下次聊天能检索到历史作参考——但权重参数依然没变，只是「伪装成记忆」。

真正「提升」知识的两条路
  • 检索增强生成（RAG）：把文档喂给它，回答时「查书」——目前本地模型获取新知识的主流方式。
  • 微调（Fine-tuning）：用新数据训练、修改权重，需要较高显存与技术门槛，已不是「聊天」。
03

本地模型如何实现「在线搜索」

00793 · 2026-03-24

本地模型本身不具备在线搜索能力——它只是一个静态本地文件、语言生成器。要搜索，得由前端/中间层先调搜索 API，再把结果连同问题喂给模型。

实现方式做法
支持联网的客户端Open WebUI、AnythingLLM、ChatGPT-Next-Web 等可配置搜索引擎 API（Google/Bing/SearchAPI）：模型需要搜索时，工具先取搜索结果，再连同问题发给模型作答。主流组合即 Open WebUI + 本地模型（如 Ollama）+ 搜索引擎 API。
自己写脚本用 Python 等先调搜索 API，把结果拼接后再调本地模型 API 接口回答。
云平台「本地部署」模型有些 API 服务虽称「本地」，实际跑在云端，是否内置搜索插件取决于平台。
附 · LM Studio 与图片

LM Studio 能不能装图片生成模型

结论：不能直接「安装/运行」图片生成模型（如 Stable Diffusion），它是专门跑大语言模型（LLM）的工具。但它能做两件和「图」相关的事。

功能能否说明
直接生成图片不能本身不是为图像生成设计的。
运行图像理解模型（VLM）能支持 VLM 读取并理解图片，官方示例 qwen2-vl-2b-instruct、gemma-3-*、pixtral-* 等，可上传图片提问。
辅助图片生成能当「提示词工程师」把想法扩成详细 Prompt 再交给绘图工具；或经 Gemini MCP Server 等插件、或作为节点接入 ComfyUI 工作流。

05

Hermes 接入本地 Qwen 7B

00955 · 2026-04-17

核心：Hermes 支持 OpenAI 兼容接口，只要模型提供符合格式的 API 地址就能无缝调用。下面是最省事的 Ollama 路径与配置文件路径。

方法一 · Ollama（新手首选）

先跑模型，再配 Hermes

第一步：确认 Qwen 已在本地经 Ollama 运行——

# 1. 拉取模型 ollama pull qwen2:7b # 2. 启动服务 ollama serve # 3. 另开终端验证状态，确认 qwen2:7b 为 loaded ollama list # 也可访问 http://localhost:11434 确认服务就绪

第二步：终端输入 hermes model 进入配置向导——Provider 选 custom（不要选 ollama，旧版 Hermes 对原生 Ollama 接口支持不佳），按下表填写：

字段填写值
Base URLhttp://localhost:11434/v1
Model NameOllama 中的确切模型名，如 qwen2:7b
API Key任意非空字符，如 ollama（Hermes 会校验，Ollama 会忽略其值）

配置完成后执行 hermes 即可与本地 Qwen 7B 对话。

方法二 · 配置文件

~/.hermes/config.yaml 手动接入

用 hermes config edit 打开配置文件，添加如下内容：

# ~/.hermes/config.yaml llm: provider: custom model: "qwen2:7b" # 你使用的模型名称 base_url: "http://localhost:11434/v1" # 本地推理服务地址 api_key: "ollama" # 任意非空值即可 # 遇 JSON 解析错误可尝试启用兼容模式 # ollama_compatible: true # 多模型共存示例 # providers: # qwen_ollama: # provider: custom # base_url: "http://localhost:11434/v1" # api_key: "ollama" # qwen_vllm: # provider: custom # base_url: "http://localhost:8000/v1" # api_key: "EMPTY"

多模型时在 providers 下定义多个服务，再用 provider名/模型名 选默认模型。进阶：vLLM 追求高性能生产部署，启动时需加 --enable-auto-tool-choice 与 --tool-call-parser hermes 才支持 Qwen 工具调用；用阿里云 DashScope 则在向导选 Qwen OAuth。

排障

三个常见问题

现象原因与解决
模型不支持最小上下文报错部分低量化 Qwen 上下文窗口小；换上下文更大的模型，如 qwen2.5:7b 或 gemma4:e2b。
连接失败 / Connection refused本地推理服务未启动或 base_url 配错；Ollama 地址通常是 http://localhost:11434/v1。
API Key 无效 / 401 UnauthorizedHermes 必须有 API Key 但 Ollama 忽略其值；填任意非空串如 ollama 或 dummy。

01

基础规范：双色系统与防截断

来源：002 / 007 / 013

早期定下的几条硬规矩，后面所有 Skill 都在遵守。

橙/蓝双色语义
蓝
信息、数据、普通说明、表头
橙
风险、注意、待处理、警示
绿
成功、成果、正向状态
紫
核心结论、战略、洞察
四反引号防截断

Markdown 里嵌套代码块时，用四个反引号包裹外层，三个反引号包内层，避免被截断。这是 ChatGPT 输出长 Markdown 时的保命技巧。

兼容性红线（022 Typora vs GitHub 审计）
  • 所有 CSS 必须 inline 写在 style="..."，不允许 <style> 标签、不允许外部 class。
  • 不使用 JavaScript、不依赖外部资源。
  • HTML 标签必须闭合；Flex 子元素必须设 min-width 防止窄屏挤崩。
  • Table 必须 border-collapse:collapse，单元格显式 padding。
  • Mermaid 只在复杂关系时用，简单流程不要炫技。

自适应排版引擎（073 最终形态）

来源：073 / 2026-09-09

这是这一组会话的终局。原版 Prompt 是"规定标题怎么做、卡片怎么做、表格怎么做"——组件驱动。新版反转成：先理解内容 → 识别信息关系 → 判断表达目的 → 选 Layout → 选组件 → 生成。

Layout 评分公式

Layout Score = 关系匹配 × 40% + 表达目的 × 25% + 信息密度 × 15% + 可读性 × 10% + 兼容性 × 10%。最高分 <60 时回退到普通 Markdown。

组件预算

S1 短文 ≤3 个视觉组件；S2 中等 ≤6 个；S3 复杂 ≤10 个；S4 长文档按章节控制。每章节最多 1 个主组件 + 0–2 个辅助。

最高优先级规则：永远不要先决定"我要用卡片"再把内容塞进去。必须先判断"这部分信息之间是什么关系"，再选结构。这是从 Markdown 美化 Prompt 升级成真正排版 Skill 的分水岭。

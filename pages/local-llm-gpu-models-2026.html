两台机的硬件底盘对比

2026-03 vs 2026-05

同一个人、两个月内问了两次「我这电脑能跑什么 AI」。两次的机器描述略有出入，合并起来才看得清瓶颈到底在哪。

项目2026-03 那台2026-05 HOMEPC
CPU未明说Intel i5-10400F，6 核 12 线程，2.9GHz
显卡总显存 10010MB，VRAM 5966MB（≈6GB）NVIDIA GTX 1660，4GB 显存，驱动 32.0.15.6094
内存未明说ADATA 8GB DDR4 3200（单条）

主板未明说微星 B560M BOMBER

两个真瓶颈
  • 显存：6GB 是 7B 量化模型的及格线；4GB 必须 Q4 量化 + 上下文压到 4K。
  • 系统内存 8GB：这是最大短板。浏览器 + Ollama + 模型一上就爆，第一升级位是内存到 32GB，不是显卡。

图片生成模型与分辨率上限

Stable Diffusion 本地部署

3 月那天连问了「能跑哪些图片软件」「最大多少像素」「怎么本地部署 SD」。结论合并：6GB 显存跑 SD1.5 完全没问题，SDXL 勉强；4GB 必须 Forge WebUI 低显存模式。

分辨率约需显存6GB 卡实测
512×512~2GB轻松
1024×1024~4GB可跑
2048×2048+6GB+爆显存，需分块 / hires fix

软件选型（按上手难度）

  • Fooocus：最像 MidJourney，自动调参，新手首选。
  • Forge WebUI：低显存优化最强，4GB 卡唯一推荐。
  • A1111 WebUI：插件生态最丰富，ControlNet + LoRA。
  • ComfyUI：节点流，显存利用率最高，批量/自动化。
  • InvokeAI：像 Photoshop 的画布编辑。

语音合成（TTS）与识别（ASR）

Tacotron 2 本地部署

3 月那次顺藤摸瓜问完图片模型又问「还能跑什么模型」，一路问到 TTS/ASR。最终落到 Tacotron 2 的本地部署步骤。

类型模型特点
TTS 语音合成Tacotron 2Google 端到端，文本→频谱→WaveNet 声码器，接近真人
FastSpeechTransformer 架构，比 Tacotron 2 快，适合实时
WaveNet / WaveGlow声码器，直接生成波形，质量高但慢
ASR 语音识别Wav2Vec 2.0Meta 自监督学习，低资源语言表现好
DeepSpeechMozilla 开源，多平台
ConformerCNN+Transformer，高精度语音助手
部署步骤

Tacotron 2 本地跑通

环境
Python 3.6+、CUDA 11.x + cuDNN、NVIDIA GPU ≥6GB VRAM。
克隆仓库
git clone https://github.com/Rayhane-mamah/Tacotron-2.git
依赖
虚拟环境内 pip install -r requirements.txt；另装 tensorflow numpy scipy matplotlib pandas librosa
预训练权重
下 Tacotron 2 模型解压到 Tacotron-2/models/；可加 NVIDIA WaveGlow 权重提音质。
推理
python synthesizer/inference.py --text "你好，欢迎使用 Tacotron 2" --model_name tacotron2
输出
logs/ 目录下 .wav 文件；6GB 显存需减小 batch size。
5 月那次更轻量的选择：语音合成直接用 EdgeTTS 或 GPT-SoVITS 小模型；语音识别用 Whisper small/base；OCR 用 PaddleOCR——这几类 4GB 显存都能跑。

Pygmalion 7B：情感互动模型怎么聊

2026-03-24

Pygmalion 7B 是专门微调过的情感陪伴 / 角色扮演模型。用户当时已经本地部署好，问的是「怎么有技巧地跟它聊天」。

模型特点

  • 7B 参数，专注情感交流与对话生成。
  • 能识别情绪变化，用关怀 / 幽默 / 支持性语气回应。
  • 开源可自定义风格（温暖 / 幽默 / 正式）。
  • 无长期记忆，靠上下文窗口维持连贯。
  • 适合情感陪伴、语言练习、创意写作。

聊天技巧

  • 开场先给系统消息定角色：「你是温暖有趣的聊天伙伴」。
  • 用开放性问题，别问是 / 否。
  • 温度 1.0 更有创意，0.7 更稳定。
  • 答偏了直接反馈：「这段不对，聊 AI 伦理」。
  • 多轮对话维持上下文，别一次塞太多问题。
from transformers import AutoModelForCausalLM, AutoTokenizer model = AutoModelForCausalLM.from_pretrained("PygmalionAI/pygmalion-7b") tokenizer = AutoTokenizer.from_pretrained("PygmalionAI/pygmalion-7b") inputs = tokenizer("你今天过得怎么样？", return_tensors="pt") out = model.generate(inputs['input_ids'], max_length=150, temperature=0.9) print(tokenizer.decode(out[0], skip_special_tokens=True))

Grok：免费额度、开源规模与写小说限制

xAI 云端模型，本地跑不动

三篇 Grok 会话分别查了免费额度、开源模型大小、写小说限制。合并后一句话：Grok 是云端级模型，6GB 本地卡跑不了，只能在 X App 或 API 里用，而且写长小说受内容审核。

项目结论
对话免费额度按 2 小时时间窗口刷新，约 2~20 次，不是按天。
Think / DeepSearch每天合计约 10 次（各 5 次），最容易用光。
生图 / 生视频24 小时约 20 图 + 20 视频（部分地区）。
API 额度每月约 $25 免费额度，按调用量计费。
Grok-1 开源总参数 ~314B，MoE 架构，Apache 2.0。
Grok-2 开源总参数 ~270B，激活 ~115B，MoE；许可证更严格。
本地能否跑全精度需 ~500GB 显存；3-bit 量化仍要 100GB+。6GB 卡完全不可能，需 A100/H100 集群。
写小说限制强审核：露骨成人 / 血腥暴力 / 未成年敏感内容会被拦；偏互联网幽默风，长篇容易跑偏或自我审查；单次输出长度有限。
写小说的替代方案
  • 普通轻剧情 / 搞笑内容：Grok 能用。
  • 成人 / 角色扮演 / 长篇情感：换本地 Pygmalion / MythoMax / Mistral 系，无审查、可控性高。

五阶段升级路线（HOMEPC 版）

2026-05-24 那次规划

最后一次（5 月 24 日）那次会话直接把整台 HOMEPC 的 AI 路线排成了五个阶段。这是整组会话里最完整的一张路线图，照录如下。

阶段装什么目标
一Ollama + Qwen2.5 3B + Open WebUI先拥有「本地 ChatGPT」，写作 / 工作 / SEO / 拆任务
二AnythingLLM + bge-m3 Embedding + 导入小说/Markdown/PDF私人 AI 大脑，懂你的资料与行业
三OpenClaw / QClawAI Agent，自动写大纲 / 拆任务 / 对比供应商
四n8n / Dify自动化工作流：读关键词→搜资料→AI 生成→排版
五内存 8GB→32GB + 显卡升 RTX 3060 12GB真正的 AI 工作站：SDXL 能跑、Flux 勉强、13B 舒服
升级优先级：第一是内存到 32GB（知识库最吃内存和 SSD，不是 GPU）；第二是加一块 2TB NVMe（向量库 + 模型文件很容易撑爆 500GB）；显卡里 RTX 3060 12GB 是本地 AI 性价比神卡——12GB 显存让 SDXL / Flux / 13B 模型全部解锁。

三种使用语境

来源：023 / 2026-04-16

在动手写代码前，先把 Hermes 的使用场景分清楚——不同语境选不同的模型和界面，不要一套配置打天下。

语境特征建议配置
本地隐私数据不出本机、离线可用Ollama + 7B 量化模型
日常助手需要较好的对话质量、可联网LM Studio + 14B/32B，或接云端 API
批处理/自动化跑 Skill、生成文件、批量处理后台无界面、Planner+Executor 模式
01

Ollama vs LM Studio 与模型规模

来源：023
Ollama
  • 命令行为主，适合服务器/后台跑
  • 模型管理简单，一行 pull
  • 默认端口 11434
  • 资源占用相对可控
LM Studio
  • 有 GUI，模型浏览器友好
  • 支持 GGUF 全系列，参数调得细
  • 适合桌面端交互式调参
  • HTTP 服务器模式给 Hermes 调
7B 够用性：桌面 Agent 做日常问答、写文件、调 Skill，7B 量化模型基本够用。但要注意 token 消耗会被放大 3–10 倍——System Prompt + Skill + 历史对话 + 工具描述叠加，一次请求实际喂进去的 token 比纯聊天多得多。显存吃紧时优先砍历史，不是换模型。
02

桌面窗口：Tkinter vs Streamlit vs Gradio

来源：024 / 2026-04-17

要做一个"双击打开"的桌面窗口，三条路线各有取舍。

方案优点缺点结论
TkinterPython 自带、打包后体积小、原生窗口感UI 丑、布局要手搓选定方案：能打包成独立 exe
Streamlit写起来快、组件丰富本质是网页、要起本地服务器、打包别扭适合内部工具，不适合交付 exe
GradioAI 场景友好、对话组件现成同样是网页架构、自定义程度低快速原型用，不做最终产品
03

Planner + Executor 双角色

来源：025 / 28 条消息

单 Agent 一把梭的问题是：既要想清楚要做什么，又要立刻执行，容易在中间迷失。Hermes 定制版把这两件事拆给两个角色。

分工

Planner
接收用户目标，拆成步骤清单，决定每步调哪个 Skill、传什么参数。不直接执行。
Executor
拿到 Planner 的步骤，一步一步调工具、跑脚本、写文件。每步完成后汇报结果给 Planner。
循环
Executor 完成一步 → Planner 判断是否完成 / 是否需要调整 → 继续派下一步或收尾。

配套能力：自动生成 Skill——当用户反复做同一件事，Hermes 会把这次流程记录下来，反向生成一个新的 SKILL.md 存进 skills/ 目录，下次直接调用。这就是 072 里说的"反向生成"在桌面端的具体落地。

04

PyInstaller 打包 exe 的坑

来源：025

从 Python 脚本到"双击就能用的 exe"，坑集中在资源文件路径和隐藏导入。

# 基本命令
pyinstaller --onefile --windowed ^
  --add-data "skills;skills" ^
  --add-data "templates;templates" ^
  --hidden-import tkinter ^
  hermes.py
坑原因解法
FileNotFoundError打包后资源文件被解压到临时目录 _MEIPASS，脚本里写的相对路径找不到用 path_utils.py 统一封装：开发态走当前目录，打包态走 sys._MEIPASS
--add-data 路径分隔符Windows 用分号 ;，mac/Linux 用冒号 :Windows 下按 --add-data "src;dst" 写
--hidden-importPyInstaller 静态分析漏了动态 import 的模块（如 tkinter 子模块、某些 SDK）运行时报 ModuleNotFoundError 就加一个 hidden-import
控制台黑窗默认会弹一个 cmd 黑窗加 --windowed（GUI 模式）
path_utils.py 核心逻辑
import sys, os
def resource_path(rel):
    if hasattr(sys, '_MEIPASS'):
        return os.path.join(sys._MEIPASS, rel)
    return os.path.join(os.path.abspath('.'), rel)

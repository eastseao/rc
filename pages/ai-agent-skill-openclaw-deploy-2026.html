01

本地部署 OpenClaw

来源：001 / 2026-03-07

OpenClaw 是一套跑在本机的 Agent 运行时。部署的核心不是装一个软件，而是把"Node 运行时 + 本地大模型 + Gateway 网关"三件套串起来。

环境要求

Node 版本
必须 ≥ 22。低版本会在依赖安装阶段直接报错，不要用旧 LTS 凑合。
本地模型
通过 Ollama 接入。OpenClaw 本身不带模型，只负责调度；模型由 Ollama 在本地拉起。
Gateway 端口
默认 18789。这是 OpenClaw 对外暴露的网关端口，后续 Skill、Agent、移动端连接都走它。
连接方式
OpenClaw → Gateway(18789) → Ollama → 本地模型。三层各自独立，出问题先分层排查。
排查顺序：Gateway 起没起来（curl 127.0.0.1:18789）→ Ollama 模型在不在（ollama list）→ OpenClaw 配置里的 base_url 有没有指向 18789。三层任一不通，Agent 都不会响应。
02

三层架构与 Agent 人格文件

来源：010 / 041

理解 OpenClaw 的关键，是把它看成"一个运行时 + 一套人格文件 + 一组可加载 Skill"，而不是一个聊天软件。

层职责对应文件/组件
运行时层调度 LLM、加载 Skill、管理上下文、执行工具OpenClaw 本体 + Gateway 18789
人格层定义这个 Agent 是谁、怎么说话、按什么原则做事identity.md（我是谁）+ soul.md（怎么思考）
能力层一组按需加载的专业 Skill，每个 Skill 是一个目录skills/<name>/SKILL.md + references/ + templates/

老王 identity.md + soul.md（041）

OpenClaw Agent 设计不是写一段 system prompt，而是拆成两个文件：

  • identity.md：这个 Agent 的身份——食品行业全能专家，擅长采购、产品、市场、供应链。它回答"我是谁、我服务谁、我不做什么"。
  • soul.md：思考方式与判断原则——遇到问题先问阶段、再问约束、最后给方案；不编数据、不替用户拍板。它回答"我怎么想、怎么决策"。

两个文件分开的好处：换人格时只改 identity，思考方式可以保留；调风格时只改 soul，身份不变。这是后续所有垂直 Agent（阿紫、采购、建站、大健康 PM）的模板起点。

03

QClaw 17 条高手技巧

来源：046 / 048 · 2026-05-21

QClaw 是 OpenClaw 的高阶用法集合。真正拉开差距的不是"会用"，而是把 Agent 从一个聊天工具拆成分工协作的组织。下面是这两条会话里沉淀下来的核心打法。

技巧怎么做解决什么问题
Agent 分工化一个大 Agent 拆成 Orchestrator + 多个专职 Agent（调研/写作/校对/数据）单 Agent 上下文爆炸、角色串味
Skill System把重复工作固化成 SKILL.md + references + templates，不要每次重写 prompt每次从零开始、输出不稳定
目录结构固定化每个 Agent 一个目录，identity/soul/skills/memory 各自归位文件散落、找不到
人格固定化identity.md 写死身份，soul.md 写死原则，不要在对话里临时改人设Agent 越聊越飘、前后矛盾
Chain Workflow多步任务显式拆链：A 输出 → B 输入，中间用文件或变量传一步到位导致漏环节
Orchestrator 总控一个调度 Agent 负责拆任务、派活、收结果，不亲自干活多 Agent 无人指挥
长期记忆重要结论写进 memory/，不要只靠上下文窗口跨对话丢失上下文
QC Agent专门加一个检查 Agent，负责挑错、查数字、核合规主 Agent 自检盲区
反向生成先写输出样例（template），再让 Agent 按样例反推 promptprompt 写了但输出不对
读者模型写之前先定义"读者是谁、他要做什么决定"写出来没人用
多模型协作重活用大模型、轻活用小模型、分类用最快的模型全用大模型烧 token、全用小模型质量差
SEO/GEO 高级玩法针对 AI 搜索做语料布局，控制行业认知传统 SEO 对 AI 搜索失效
上下文污染防控把无关历史、失败尝试从上下文里清掉Agent 被旧对话带偏
AI 工厂化把流程拆成可复用流水线，输入原料出成品每次手搓、不可复制
实操要点
  • 不要一开始就堆 17 条。先上"分工化 + Skill System + 长期记忆"三条，跑顺再加。
  • QC Agent 不是可选项——只要输出要给人看，就加一个挑错 Agent。
  • 反向生成是最被低估的一条：先画你想要的最终表格/文档长什么样，再反推 prompt。

安卓端连接指南

来源：006 / 069 · 2026-04 ~ 2026-07

OpenClaw 没有官方独立安卓版。手机要接入，靠的是 Companion Node 架构——手机作为一个远程节点，连到你电脑上跑的 Gateway。

连接架构 
安卓手机 (Companion Node)
   │  ws:// 或 wss://
   ▼
电脑 Gateway (18789)
   │
   ▼
OpenClaw 运行时
   │
   ▼
Ollama 本地模型
关键概念
协议
本地用 ws://，跨网远程用 wss://（需加密）。
devices approve
新手机首次连接，必须在电脑端 devices 列表里手动 approve，否则连不上。
Setup Code
配对码模式，适合快速直连；手动模式适合固定配置。
官方状态
没有官方独立安卓 APP。
第三方替代
andClaw 是社区第三方客户端，可作为接入方案。

红线 · 远程接入

不要把 18789 裸暴露到公网

跨网远程必须走 wss + 鉴权。直接把 ws://18789 映射到公网，任何人扫到端口都能连进你的 Agent，等于把本地模型和文件系统开放。

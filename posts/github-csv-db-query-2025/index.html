01 · 把 Excel 台账做成在线查询：包材物料（00334）

目标：把近两年包材台账做成可在线查询的前端工具。仓库gervasw.github.io，根目录建tz/文件夹，绑域名后访问https://gervas.wang/tz/。

对比方案一：静态站 + 前端筛选方案二：现成组件库
难度较低，适合初学者中等，需少量代码
核心思路数据转 JSON 嵌进网页，JS 在浏览器内筛选用 element-advanced-search 类组件做复杂多条件筛选
技术栈index.html + style.css + script.js + data.json 四件套Vue3 + Element Plus，searchConfig定义筛选项

data.json 字段（照录实际结构）：合同编号、采购订单号、供应商编码、供应商名称、项目号、项目名称、数量、单位、采购单价、订单总额。转换工具：Table Convert Online 或 ConvertCSV.com。

三条硬提醒：① 公开仓库前务必脱敏，去掉内部成本价、供应商联系方式等敏感信息；② 数据超过数万行纯前端会变慢，届时才需上数据库+后端 API，两年量前端方案足够；③ 绑自定义域名需在仓库根目录放 CNAME 文件，内容为 gervas.wang。

02 · 物料查询系统：三输入框模糊查询与加载排错（00341）

实际需求：页面名「物料查询系统」，三个输入框（供应商名称、项目号、项目名称），供应商与项目名支持模糊查询，只输一项也能查；查询按钮后表格列出八个字段，下方带金额总计。

  1. 数据格式 ：中文键名 JSON 数组（ {“合同编号”:“SC2022-1-4-04”,“供应商名称”:“四川鼎晟塑料制品有限公司”,…} ），用 fetch(‘data.json’) 加载。

  2. 不查询不显示 ：进页面表格先显示「请输入查询条件后点击查询」，无任何条件时不渲染数据。

  3. 模糊查询 ： includes() 子串匹配，三条件 AND 组合，空条件自动跳过；结果合计 parseFloat(订单总额) 并加千分位。

  4. 金额总计 ：查询结果实时累加， toLocaleString() 千分位显示。

「数据加载失败 / 无法从 tz/data.json 加载」的排错链条：

现象处理
index.html + 同目录 data.json 能否查可以，纯静态即可；CSV 也能解析，但 JSON 更省事
加了 mock 兜底但仍不引用真数据用全局变量allData在DOMContentLoaded时一次性加载，查询时读内存，不重复请求
fetch 路径写 tz/data.json 仍失败index.html 与 data.json 同在 tz 目录，用相对路径fetch('data.json')；去掉 URL 上的时间戳参数；本地双击 file:// 打开会受跨域限制，须走 http（Pages 上正常）
反复加载失败打开浏览器控制台看真实报错；确认 data.json 是合法 JSON（逗号、引号闭合）；先去掉 mock 与「正在加载…」提示，让报错直接暴露

03 · 个人名片页面：八轮迭代全过程（00337 · mycard）

名片信息：王维，北京同仁堂健康药业（青海）有限公司，采购 / 包装方案解决专员，目标「稳定供货、保证质量、降本增效」。放在mycard/文件夹，访问https://gervasw.github.io/mycard。迭代顺序照录：

  1. 初版 ：卡片式布局、头像居中、联系信息展示。

  2. 头像路径 ：统一为 assets/img/avatar.jpg （相对名片页）。

  3. 交互 ：点击微信号复制到剪贴板（navigator.clipboard + 传统 execCommand 兜底）；点击电话——手机拨号、桌面复制。

  4. 移动端 ：「主要目标」在小屏一行显示，不换行。

  5. 头像放大 + 红色主题 ：点头像灯箱放大；背景深红渐变。

  6. 回首页按钮 ：「感谢访问我的个人名片页面」上方加低调按钮，指向 https://www.gervas.wang。

  7. 重排顺序 ：先工作信息（公司/职位/主要工作），再联系信息（电话/微信），最后是目标；职位定为「采购」，保留包装方案解决内容。

04 · 不要后端：IndexedDB 纯前端本地数据库（00367）

若数据不想放公网、想存在浏览器本地，用 IndexedDB 即可。示例库LocalDB、表employees，字段 id（自增主键）、姓名、邮箱（唯一索引）、电话、部门。

能力实现
建库建表indexedDB.open(dbName, version)，onupgradeneeded里 createObjectStore（keyPath id、autoIncrement）并对 name/email/department 建索引
增删改查readwrite 事务 add/delete/clear；readonly 事务 getAll，再前端 filter 关键词
UI左侧表单添加记录、右侧表格展示、顶部搜索框、右上角 toast 提示

优势：纯前端无需服务器，数据持久化在浏览器；局限：数据只在本机当前浏览器，不适合多人间共享，公开台账查询仍走 data.json 方案。

05 · 不做地图：全国行政区划逐级树形查询（00510）

需求是逐级查「省→市→区/县→镇→村」，不要地图。本质是树形数据查询，关键在数据。

层级数据源
省/市/县/乡镇国家统计局《统计用区划和城乡划分代码》，每年发布、公开结构化，是主干
村/社区最大难点：国家无统一公开库，需从各省/市数据开放平台零散整合；或用百度/高德 API 补充（可能不全、需商用授权）

表结构：id 主键、parent_id 自关联、name、full_name、code（12 位统计用区划代码，唯一索引）、level（1 省/2 市/3 县区/4 乡镇/5 村）。API：GET /api/divisions?parent_code=110000查子级；/api/search?name=海淀&level=3模糊搜；/api/tree?code=110000&depth=3取子树。前端用级联选择器逐级加载。

关键判断：70% 精力花在数据获取、清洗、年度更新上；全国 50 万+ 村级单位，初期先做到乡镇级更现实；用第三方 API 商用前须读服务条款、申请授权。

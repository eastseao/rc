01 · 一键清理系统垃圾的 bat 脚本（00753 · 2026-03-17）

原笔记给出了从简到繁四个版本：基础版只删临时文件；全面深度版加入 DISM 组件清理、更新缓存、DNS 与浏览器缓存；专项版专治 C 盘被 Windows 更新文件占用；极简版只释放空闲内存；最后再把全部功能整合成一个菜单版全能脚本。创建方法统一：记事本粘贴代码 → 另存为时「保存类型」选「所有文件」→ 文件名以.bat结尾 → 右键「以管理员身份运行」。

红线 · 批处理安全

脚本会批量执行删除命令，一个笔误就可能误删文件

粘贴时确保括号、引号、符号均为英文半角；运行前保存并关闭所有工作文档；脚本主要清理临时文件，无法取代专业清理软件；深度版中的 DISM 清理执行后无法回退已安装的系统更新。

版本一 · 基础版

经典一键清理（照录）

@echo off echo 正在清除系统垃圾文件，请稍等...... :: 删除系统盘根目录下的特定临时文件 del /f /s /q "%systemdrive%\*.tmp" del /f /s /q "%systemdrive%\*._mp" del /f /s /q "%systemdrive%\*.log" del /f /s /q "%systemdrive%\*.gid" del /f /s /q "%systemdrive%\*.chk" del /f /s /q "%systemdrive%\*.old" :: 清空回收站 (适配NTFS文件系统) del /f /s /q "%systemdrive%\recycled\*.*" :: 删除Windows目录下的备份文件和预读文件 del /f /s /q "%windir%\*.bak" del /f /s /q "%windir%\prefetch\*.*" :: 清空Windows临时文件夹，然后重新创建它 rd /s /q "%windir%\temp" 2>nul md "%windir%\temp" :: 删除当前用户的个人临时文件和浏览器缓存 del /f /q "%userprofile%\cookies\*.*" del /f /s /q "%userprofile%\Local Settings\Temporary Internet Files\*.*" del /f /s /q "%userprofile%\Local Settings\Temp\*.*" del /f /s /q "%userprofile%\recent\*.*" echo 清除系统垃圾完成！ echo. & pause

版本四 · 极简版

只释放空闲内存（照录）

@echo off echo 正在释放空闲内存，请稍等...... %windir%\system32\rundll32.exe advapi32.dll,ProcessIdleTasks echo 内存清理完成！ pause

作用：强制系统释放当前未被使用、处于空闲状态的物理内存（RAM），不影响正在运行的程序，可随时执行。

全能系统垃圾清理工具（照录）

中文乱码怎么办（原笔记排障）
  • 原因：中文 Windows 控制台默认代码页是 GBK（936），脚本开头chcp 65001强制切 UTF-8，字体不支持就会乱码。
  • 解法：用记事本打开 .bat →「文件 → 另存为」→ 底部「编码」从 UTF-8 改为ANSI（中文系统即 GBK）→ 覆盖保存 → 重新管理员运行。
  • 兜底：原笔记另附一份纯英文版菜单脚本，去掉全部中文字符，任何系统运行都不会乱码。

02 · 强力删除顽固文件夹与 NUL 文件（01307 / 01308）

两类删不掉的文件：一是权限或属性导致的顽固文件夹（需要先夺取所有权、重置权限、清除只读/隐藏属性）；二是名为NUL的特殊文件——NUL是 Windows 保留设备名，系统会被这个名字「迷惑」，普通删除会报权限错误。

01308 · 2026-06-15

删除名为 NUL 的保留名文件

先放心：这不是病毒或恶意软件。NUL 在 Windows 中是留作特殊用途的设备名（相当于「黑洞」「空设备」），普通文件被命名为 NUL 时系统会被迷惑。按从易到难尝试：

方案成功率操作
Git Bash（最推荐）高，几乎不报错在 nul 文件所在文件夹空白处右键「Git Bash Here」，输入rm nul回车；有空格则rm "nul"。底层直接调用 Windows 删除 API，不对保留设备名做特殊处理。装了 WSL 的话，进入子系统后rm nul同样有效。
CMD 设备路径法中以管理员打开命令提示符，用特殊前缀强制按普通路径处理：del \\?\C:\Users\你的用户名\Desktop\nul（换成你自己的真实完整路径）。
PowerShell（适合批量）备选单文件：Remove-Item -LiteralPath "\\?\C:\Users\你的用户名\Desktop\nul"，-LiteralPath禁用通配符解析。批量递归删除当前目录及所有子目录的 nul 文件（CMD 中运行）：cmd /c del /s /f /q "\\?\%cd%\nul"，执行前确认确实要递归删除。
第三方工具（终极手段）兜底火绒安全「文件粉碎」；或 LockHunter / Unlocker 这类解除文件锁定的强制删除工具。
为什么会生成 nul 文件：大概率是某些开发脚本或软件 Bug 错误地在当前目录创建了它——比如 Python 程序本想丢弃输出，却写成了"nul"而不是专用的os.devnull，或配置文件误把路径硬编码成 nul。要根治需修改生成该文件的源代码或配置。

03 · WinSxS 组件存储与 C 盘空间清理（01322 · 2026-06-17）

WinSxS 是 Windows 系统核心目录，绝不能直接用 del / rd 删除，否则会导致系统崩溃。原笔记的脚本只调用 Windows 官方自带的 DISM 工具做安全清理：先分析可回收空间，再标准清理（保留更新回滚能力），深度清理（/ResetBase）可选。

脚本 · 照录

WinSxS 安全清理工具（基于 DISM）

@echo off title WinSxS 安全清理工具 (基于DISM) color 0E :: 检查是否以管理员权限运行 echo 正在检测管理员权限... net session >nul 2>&1 if %errorlevel% neq 0 ( echo 错误：此脚本需要以管理员身份运行！ echo 请右键点击本文件，选择“以管理员身份运行”。 pause exit /b ) cls echo =============================================== echo WinSxS 组件存储安全清理工具 v1.0 echo =============================================== echo. echo 注意：本工具仅调用 Windows 官方 DISM 命令， echo 不会强制删除任何系统文件，相对安全。 echo =============================================== echo. :: 第一步：分析 WinSxS 文件夹的实际大小和可回收空间 echo [1/3] 正在分析 WinSxS 组件存储，请稍候... echo ----------------------------------------------------------------- Dism /Online /Cleanup-Image /AnalyzeComponentStore echo ----------------------------------------------------------------- echo. echo 请查看上方报告中 "推荐使用组件存储清理" 的状态。 echo 如果显示 "是"，则建议进行清理；如果显示 "否"，则无需清理。 echo. :: 第二步：询问用户是否继续 set /p confirm="是否立即执行标准清理？(输入 Y 并回车确认，其他任意键退出): " if /i not "%confirm%"=="Y" ( echo 操作已取消。 pause exit /b ) echo. echo [2/3] 正在执行标准清理（保留最近安装的更新备份）... echo ----------------------------------------------------------------- Dism /Online /Cleanup-Image /StartComponentCleanup echo ----------------------------------------------------------------- echo. echo 标准清理已完成！ echo. :: 第三步：高级深度清理（可选） echo =============================================== echo 警告：深度清理选项 (/ResetBase) echo 此操作将移除所有旧版本的组件，导致已安装的 echo Windows 更新无法卸载，但可以最大程度释放空间。 echo =============================================== set /p deep="是否执行深度清理 (ResetBase)？(输入 Y 并回车确认，其他任意键跳过): " if /i "%deep%"=="Y" ( echo. echo [3/3] 正在执行深度清理（重置基础版本），请耐心等待... echo ----------------------------------------------------------------- Dism /Online /Cleanup-Image /StartComponentCleanup /ResetBase echo ----------------------------------------------------------------- echo 深度清理已完成！ ) else ( echo [3/3] 已跳过深度清理。 ) echo. echo =============================================== echo 所有操作执行完毕！建议重启计算机。 echo =============================================== pause
清理模式说明
/AnalyzeComponentStore（前置分析）先跑分析，报告里「推荐使用组件存储清理」显示「是」才建议清理；显示「否」说明系统已较精简，强行清理收益不大。
/StartComponentCleanup（标准清理）安全级别高：清理被取代的旧版本组件，同时保留近期安装的更新回滚能力，强烈建议首选。
/ResetBase（深度清理）激进模式：移除所有被取代的组件版本，清理后无法从控制面板卸载任何已安装的 Windows 累计更新，仅在确定不需要回滚更新时使用。

清理过程可能需要数分钟甚至更久，期间 CPU 占用较高属正常现象，不要强制关闭命令行窗口。

C 盘用户文件夹太大怎么办（同篇笔记后续问答）诊断 + 清理 + 迁移

红线 · 千万不要做

不要直接删除 C:\Users，也不要把整个用户文件夹搬到别的盘

用户文件夹是系统核心，直接删除会导致数据丢失或无法登录；整个文件夹强行移动会损坏用户配置文件。处理思路是「疏」而不是「堵」：先清理缓存，再迁移个人文件夹。

第一步：先「诊断」再清理

定位空间杀手
用 WizTree（免费绿色）或 TreeSize Free 扫描C:\Users\你的用户名，通常是AppData（程序缓存、游戏存档、浏览器数据）或「下载」文件夹占比最大。
系统临时文件
Win+R 输入%temp%回车，Ctrl+A 全选删除（正在用的跳过），再清空回收站。
磁盘清理（重点）
搜索打开「磁盘清理」→ 选 C 盘 →「清理系统文件」，重点勾选「以前的 Windows 安装」或「Windows 更新清理」、「临时文件」、「回收站」——这是单次释放空间最多的操作之一。
第三方缓存
浏览器：用设置里的「清除浏览数据」，不要手动删文件夹。微信/QQ：在 PC 版「设置 → 文件管理」把保存路径迁到 D 盘后再删原缓存。开发工具：npm 跑npm cache clean --force，pip 跑pip cache purge。

第二步：迁移 + 系统优化

迁移个人文件夹
右键「桌面 / 文档 / 下载 / 图片 / 视频 / 音乐」→「属性 → 位置 → 移动」→ 选 D 盘新文件夹 → 确认移动。快捷入口不变，最官方安全。
关闭休眠
管理员命令提示符运行powercfg /h off，可释放约内存大小 75% 的空间。
存储感知
「设置 → 系统 → 存储」打开存储感知，如设定回收站文件超过 30 天自动删除。
进阶（仅限熟手）
巨大缓存文件夹可剪切到 D 盘后mklink /J "C:\原路径" "D:\新路径"建目录链接；软件升级或系统更新后可能报错，不熟练不建议操作。Program Files 不能直接移动，系统盘不建议压缩。

三板斧：WizTree 扫描 → 清微信/浏览器/开发工具缓存 → 迁移「下载/桌面」到 D 盘，通常能释放 20GB–50GB 甚至更多。

04 · 注册表清理脚本与 .reg 关联修改（01329 / 00924）

注册表垃圾清理脚本（照录）

原笔记说明该脚本用于清理常见注册表无效项：无效的 ActiveX/COM 组件、应用程序路径、字体缓存、卸载信息、共享 DLL 引用等。保存为CleanRegistry.bat，右键管理员运行。

@echo off title 注册表垃圾清理工具 color 0a echo ======================================== echo 注册表垃圾清理脚本 echo 适用于 Windows 7 / 8 / 10 / 11 echo ======================================== echo. echo 注意：建议先创建系统还原点！ echo 按任意键继续，或关闭窗口取消... pause > nul echo. echo 正在扫描并清理无效注册表项... :: 清理无效的 ActiveX/COM 组件 reg delete "HKCR\CLSID" /f /va > nul 2>&1 reg delete "HKCR\Interface" /f /va > nul 2>&1 reg delete "HKCR\TypeLib" /f /va > nul 2>&1 :: 清理无效的应用程序路径 reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths" /f /va > nul 2>&1 :: 清理无效的字体缓存 reg delete "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts" /f /va > nul 2>&1 :: 清理无效的卸载信息 reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall" /f /va > nul 2>&1 reg delete "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall" /f /va > nul 2>&1 :: 清理无效的共享 DLL 引用 reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\SharedDLLs" /f /va > nul 2>&1 :: 清理无效的 MRU 列表（最近使用） reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU" /f /va > nul 2>&1 :: 清理临时注册表键 reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce" /f /va > nul 2>&1 reg delete "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce" /f /va > nul 2>&1 echo. echo 清理完成！ echo 建议重启电脑以使更改生效。 pause
使用注意（原笔记照录）
  • 务必以管理员身份运行，否则无法修改系统级注册表项。
  • 运行前创建系统还原点或备份注册表；有重要软件时谨慎使用，或先测试。
  • 原笔记称该脚本仅清理常见无效项、不会删除有效软件配置——照录供参考，实际执行前请自行权衡风险。

.md 文件右键新建关联的 .reg 写法

用户提供的一段 Typora 关联 .reg：把.md扩展名关联到 Typora，并在右键「新建」菜单加入 Markdown 文件。原笔记围绕「文件名是否要加当日日期」展开讨论，结论是按实际需求确认——这里照录用户给出的注册表内容：

Windows Registry Editor Version 5.00 [HKEY_CLASSES_ROOT\.md] @="MarkdownFile" "Content Type"="text/markdown" "PerceivedType"="text" [HKEY_CLASSES_ROOT\.md\ShellNew] "NullFile"="" [HKEY_CLASSES_ROOT\MarkdownFile] @="Markdown 文件" [HKEY_CLASSES_ROOT\MarkdownFile\DefaultIcon] @="\"C:\\Program Files\\Typora\\Typora.exe\",0" [HKEY_CLASSES_ROOT\MarkdownFile\shell\open\command] @="\"C:\\Program Files\\Typora\\Typora.exe\" \"%1\""
三种可能的理解（原笔记整理）：① 把这个 .reg 文件本身重命名为带当日日期的文件名，如Markdown关联_20260414.reg；② 修改文件内部某个键值字符串；③ 把ShellNew下的"NullFile"=""改为"FileName"="XXXX20260414.md"指定新建模板。实际改哪一处，取决于「XXXX」到底代表固定字符串、原文件名还是变量。

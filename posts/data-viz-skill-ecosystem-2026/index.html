00875 · 「养虾」黑话解读

OpenClaw 圈内把鼓捣机器人戏称「养虾」（Claw=钳子→虾）。「窃以为 SKILL 就是养虾的重要基础」意为：买舵机、打印零件、烧固件看似简单，但 PID 调参、焊接接线、避坑经验、运动学逆解全靠手上真功夫——「硬件有价，手艺无价」。

公众号技能命名规范：从中文标题到英文 slug

原始 13 个标题存在「排版1/2」「文章生成1/2/3」等编号冗余。经多轮规范化，最终采用统一前缀wechat-+ 全小写 + 连字符连接的 slug 格式。

中文名称最终 slug（wechat- 前缀）
公众号7日爆文收集wechat-collect-7-day-viral-articles
公众号爆文查询wechat-query-viral-articles
公众号标题生成wechat-generate-titles
公众号工具包wechat-operation-toolkit
公众号基础排版wechat-basic-formatting
公众号高级排版wechat-advanced-formatting
公众号文章去AI味wechat-remove-ai-flavor
公众号爆款封面生成wechat-generate-viral-cover
公众号短文生成wechat-generate-short-article
公众号长文生成wechat-generate-long-article
公众号仿写生成wechat-generate-imitation-article
公众号一站式爆文引擎wechat-all-in-one-viral-engine
公众号自动发布wechat-auto-publish
命名规范要点（照录）
  • 动词开头（collect / query / generate / remove / auto-publish）。
  • 功能对象明确（wechat, articles, titles, cover, formatting）。
  • 使用-连接，无大写，无空格；统一前缀wechat-。
  • 可直接用于 Coze / Dify / GPTs 等平台的name或slug字段。
LICENSE 文件补充说明：对话末尾用户追问 GitHub 上「本项目未明确声明 License」的含义。结论——没有 LICENSE 文件则默认保留所有权利，他人不能随意复制修改再发布；如需自由使用建议选 MIT 或 Apache 2.0。笔记中给出了标准 MIT License 全文模板。

02 · 数据可视化技能开发：五文件工程（00855 / 00859 / 00913）

从「Data Visualization 怎么翻」到完整的五文件技能工程：skill.md（对外说明）、config.yaml（参数定义）、run.py（数据抓取分析）、prompt.md（HTML/CSS 模板）、schema.json（配置校验）。

00913 · 2026-04-13

data-visualization-skill 五文件完整实现

目录结构：

data-visualization-skill/ ├── skill.md 对外说明 + 调用入口 ├── config.yaml 参数定义 ├── run.py 数据抓取 / 分析 / 图表生成 ├── prompt.md HTML/CSS 模板 └── schema.json 配置结构校验
文件核心职责关键内容
skill.md技能说明文档描述、功能特性、使用方法、输出格式规则（四反引号包裹、内联 CSS、蓝色主题 #e3f2fd/#bbdefb/#2196f3、渐变总结框）、依赖（Python 3.8+ / pandas / matplotlib / pyyaml）、config 字段表、文件结构说明。
config.yaml用户配置data_source（CSV/JSON 路径，空则用示例数据）、chart_type（bar/line/scatter）、x_column / y_column、title、output_file、include_mermaid、include_data_table、card_metrics（mean/max/min）。
run.py主执行脚本load_config → load_data → auto_select_columns → generate_chart_base64（matplotlib 转 base64 内嵌）→ generate_insight_cards（flex 卡片）→ generate_data_table（HTML 表格）→ generate_mermaid_diagram → generate_conclusion → 模板填充输出。
prompt.md报告模板居中标题、蓝色提示框、关键指标卡片区、图表区、数据表区、Mermaid 流程图区、渐变总结框、居中署名。占位符{{TITLE}}/{{INSIGHT_CARDS}}/{{CHART_IMG}}等。
schema.jsonJSON Schema 校验draft-07，定义 data_source / chart_type enum / x_column / y_column / title / output_file / include_mermaid / table_max_rows(1-100) / card_metrics enum，additionalProperties: false。

输出格式七条铁律

  1. 全文用四个反引号包裹（防内部代码块截断）。
  2. Markdown 标题划分章节，卡片化展示。
  3. 所有 CSS 写在style属性内。
  4. 引言框#e3f2fd底 +#2196f3左边框。
  5. 卡片 flex 布局，背景比边框浅。
  6. 表头#b3e5fc，行分隔#e0e0e0。
  7. 文末渐变总结框 + 居中署名日期。

00859 · 2026-04-07

文档可视化工具翻译：inference.sh CLI 指南分析与提示词

用户粘贴了一份英文 Data Visualization 指南（基于 inference.sh CLI），要求分析并整理成可直接使用的提示词。AI 先做内容分析（优点/不足），再产出一段结构化提示词。

数据关系最佳图表永远不要用
随时间变化折线图饼图
类别对比条形图（多类别用水平）折线图
部分占整体堆叠条形图 / 矩形树图饼图（条形始终更清晰）
分布直方图 / 箱线图条形图
相关性散点图条形图
排名水平条形图垂直条形 / 饼图
地理分布分级填色地图条形图
单指标KPI 大数字卡任何图表（过度设计）

饼图为什么几乎总是错的

  • 难以比较相近大小的扇区。
  • 超过 5-6 个类别就乱。
  • 3D 饼图永远错误。
  • 无法读出精确值。
  • 替代方案：水平条形图、堆叠条形图、矩形树图、直接用表格。

设计核心规则

Y 轴起点
条形图必须从 0 开始；折线图可截断（强调变化而非绝对值）。
标题即洞察
「Q2 收入增长 68%」而非「Q2 收入图」。
颜色数量
最多 5-7 色，突出单一重点，其余灰色。
色盲安全
避免仅用红绿，搭配形状或标签。
排序
条形图按值排序，不按字母。
禁止
3D 图表、双 Y 轴、图表垃圾（装饰元素）。
AI 分析指出的不足：①平台绑定 inference.sh CLI，建议补纯 Python 版本；②仅覆盖静态 PNG，缺少交互式（Plotly/Bokeh/Altair）示例；③热力图用随机数未说明从 CSV 加载；④缺少数据预处理（pandas 分组/透视）指导。

00922 · 2026-04-14

market_research_pro v2.0：结构化市场调研技能

YAML Frontmatter 定义三个输入参数：research_topic（必填）、target_market（默认全球）、depth_level（简版/标准/深度）。执行逻辑按九步顺序不得跳步：

步分析环节核心内容
1行业定义与范围界定明确产品/服务边界，排除模糊重叠品类。
2宏观环境（PEST 简化）政策 / 经济 / 社会 / 技术。
3市场规模与增长当前规模、CAGR、未来 3-5 年低/中/高情景预测。
4竞争格局分析TOP5-10 品牌、渠道结构、价格带分布。
5产品结构分析形态剂型、主流规格包装、核心卖点成分。
6消费者分析人群画像、使用场景、购买动机。
7趋势洞察3-5 条具体可验证趋势，每条附证据点。
8商业机会判断机会等级（高/中/低）、切入点（人群/价格带/渠道/形态）。
9风险与不确定性政策、技术、供应链、市场接受度。

硬性约束

  • 每个结论必须附逻辑或数据支撑。
  • 不确定数据必须标注「估算」并说明依据。
  • 禁止编造财报数字。
  • 章节不可合并或跳过。
  • 商业分析风格，避免口语化。

边缘情况处理

公开数据缺失
行业常识 + 类比市场 + 合理估算，标注「估算」。
小市场（<1亿美元）
重点分析细分机会，不强制高精度规模。
竞争信息不足
从渠道、价格带、消费者评论侧推竞争强度。
00962 · 2026-04-19

entity-memory：从 ontology 重命名为实体记忆

原技能名ontology偏学术。AI 分析其核心为「带类型的知识图谱 + 约束系统」，用于代理的结构化记忆和技能间状态共享，推荐新名entity-memory。

核心实体类型

人物组织
Person（name/email/phone）、Organization（name/type/members）。
工作
Project（name/status/goals/owner）、Task（title/status/due/priority/assignee/blockers）、Goal。
时间地点
Event（title/start/end/location/attendees）、Location。
信息
Document、Message、Thread、Note。
资源
Account、Device、Credential（禁止直接存密码，强制 secret_ref 间接引用）。

约束与工作流

存储
memory/entity-memory/graph.jsonl，append-only 规则。
校验
Task 必填 title/status；Event end ≥ start；Credential 禁止明文密码；blocks 关系无环。
技能契约
各技能在 SKILL.md 声明 reads / writes / preconditions / postconditions。
规划
多步计划建模为图变换序列（CREATE → RELATE → CREATE → RELATE），逐步校验。
主要变更：名称 ontology → entity-memory；脚本名 entity_memory.py；目录 memory/entity-memory/；触发词增加「remember」「what do I know about」「link X to Y」「show dependencies」；技能契约中 ontology: 改为 entity-memory:；整体语言从学术本体转向「记忆」场景。

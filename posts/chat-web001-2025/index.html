5️⃣ GitHub Actions 自动部署.github/workflows/pages.yml

name: GitHub Pages

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Ruby
        uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.2'
      - name: Install Jekyll
        run: gem install jekyll bundler
      - name: Build Site
        run: jekyll build
      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./_site

Q6 · 上面进行的这些工作流都失败了。（第 6 轮对话）

提问： 上面进行的这些工作流都失败了。

明白了，你遇到的问题很可能是GitHub 网页端部署 Jekyll + Chirpy时的常见坑。我们一步步分析原因并给出可行解决方案。

1️⃣ 常见失败原因

  1. 分支问题
  • GitHub Pages 默认会在main或master分支上部署，如果 Actions 配置和实际分支不一致，会失败。 -解决：确保仓库有main分支（网页端可直接新建），并且 workflow 触发分支是main。
  1. GitHub Actions Runner 环境问题
  • 安装 Ruby、Jekyll 或主题依赖时，可能版本不匹配。 - Chirpy 需要至少Ruby 2.7+。
  1. 主题未正确安装
  • 在网页端无法直接bundle install安装主题 gem。 -解决：可以使用remote theme的方式，避免本地安装依赖。
  1. 文件路径或命名错误

-_config.yml必须在仓库根目录 -_posts文件夹必须命名正确 - 主题必须使用remote_theme: chirpythemes/chirpy@v6.0.0（或者最新 tag）

  1. GitHub Actions YAML 错误
  • Actions 中直接用jekyll build，如果未安装依赖或使用bundle exec jekyll build可能失败 - 网页端创建 workflow 文件容易缩进/换行出错

2️⃣ 推荐解决方案（零命令行可行）

由于你只能网页端操作，最稳妥的方式是：

使用 Remote Theme + GitHub Pages 内建构建
  1. 不使用 GitHub Actions

remote_theme: chirpythemes/chirpy@v6.0.0
plugins:
  - jekyll-feed
  - jekyll-sitemap
  - jekyll-seo-tag
  1. 确保分支是 main
  • 仓库设置 → Pages → Source → main branch / root
  1. 创建必要文件 （网页端创建即可）

-_config.yml-index.md或index.html-about.md-_posts/文件夹 -assets/静态资源

  1. 构建步骤
  • 无需 workflow，GitHub Pages 会自动构建_config.yml配置和 remote theme

3️⃣ 优点

  • 网页端零命令行即可部署

if(!localStorage.getItem("theme")) {

    document.body.classList.add("dark-mode");
    localStorage.setItem("theme", "dark-mode");

❌ 错误原因

  1. Git 操作权限问题
  • Action 内部执行git命令（例如拉取远程主题、提交构建产物等）时，没有权限访问仓库或者 submodule。 - 常见场景： - 你在 workflow 里尝试git push，但是没有配置GITHUB_TOKEN- 使用 remote theme 时，Jekyll 需要临时 clone 远程主题，如果权限不够也可能报 128
  1. 仓库状态异常
  • 某些情况下，仓库存在未提交的文件或损坏的 Git 数据，也会导致 exit code 128。
  1. Action 环境问题
  • 有时 Actions 的actions/checkout配置不对，导致后续 git 操作失败。

env:

git config user.name "github-actions[bot]"

assets/js/theme-toggle.js
if(!localStorage.getItem("theme")) {
  localStorage.setItem("theme", "light-mode");
}
document.body.classList.add(localStorage.getItem("theme"));

const themeBtn = document.getElementById("theme-toggle");
themeBtn.addEventListener("click", () => {
  if(document.body.classList.contains("dark-mode")) {
    document.body.classList.remove("dark-mode");
    document.body.classList.add("light-mode");
    localStorage.setItem("theme", "light-mode");
  } else {
    document.body.classList.remove("light-mode");
    document.body.classList.add("dark-mode");
    localStorage.setItem("theme", "dark-mode");
  }
});

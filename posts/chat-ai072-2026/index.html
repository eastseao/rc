Q1 · 给我全方位深度的介绍下目前agent里的skill的具体含义（第 1 轮对话）

提问： 给我全方位深度的介绍下目前agent里的skill的具体含义

可以。这个问题其实非常关键——Skill 是目前 Agent 从“会聊天的模型”走向“可复用的专业工作者”的核心抽象之一。

尤其结合你之前一直在做的Agent / SKILL / OPC / Workflow / Runtime / Memory体系，我建议不要把 Skill 简单理解成“一个 Prompt 文件”。更准确的理解是：

Skill = 可被 Agent 动态发现、按需加载并执行的一套“程序化专业能力”。

截至 2026 年，Agent Skills 已经从早期的 Claude 生态扩展成一个跨 Agent 的开放标准；Claude、Codex 等都在采用这种思路。Anthropic 将其定义为由SKILL.md、指令、脚本和资源组成的可组合能力单元；OpenAI 也明确把 Skills 用于扩展 Codex 的信息处理、问题解决、写作以及实际计算机工作能力。citeturn0search3turn0search11

下面我从概念 → 原理 → 架构 → 生命周期 → 与 Prompt/Tool/MCP/Agent/Workflow/Memory 的区别 → Skill 如何真正产生“能力” → 如何设计企业级 Skill 系统，完整拆开。

一、先给你一个最重要的结论

如果把一个 Agent 比喻成一个“人”，那么：

Agent组件类比人
LLM大脑
System Prompt基本行为准则
Context当前工作记忆
Memory长期记忆
Tool手和工具
MCP工具连接协议
Skill专业技能 + SOP + 工作方法
Workflow工作流程
Agent一个能够自主工作的员工
Multi-Agent一个组织
Runtime工作环境
Evaluation绩效考核
Learning培训
Policy公司制度

所以：

Skill 不是 Agent。Skill 是 Agent 所拥有的“可调用专业能力”。

例如：

Agent：市场营销经理

Skills：
├── 市场调研 Skill
├── 竞品分析 Skill
├── 用户画像 Skill
├── 产品定位 Skill
├── 包装文案 Skill
├── 小红书内容 Skill
├── SEO Skill
└── GEO Skill

Agent 不需要每次都重新学习这些东西。

它只需要：

发现 → 判断相关性 → 加载 → 执行 → 验证

二、Skill 到底是什么？

目前主流 Agent Skills 的基本形式是：

skill-name/
│
├── SKILL.md
│
├── scripts/
│   ├── xxx.py
│   └── xxx.sh
│
├── references/
│   ├── guide.md
│   ├── rules.md
│   └── examples.md
│
└── assets/
    ├── template.docx
    ├── template.xlsx
    └── images/

其中：

SKILL.md

是核心入口。

官方架构的关键思想是Progressive Disclosure（渐进式披露）：

Level 1：Metadata

Agent 一开始只知道：

---
name: market-research
description: >
  Conduct structured market research, competitor analysis,
  trend analysis and evidence-based market reports.
---

也就是：

“我有什么技能？”

而不是把整个 Skill 全部塞进上下文。

Level 2：Instructions

真正需要使用时，才加载：

# Market Research

## Objective

Conduct evidence-based market research.

## Process

1. Define research question
2. Identify market scope
3. Search primary sources
4. Search secondary sources
5. Cross-check evidence
6. Analyze
7. Produce report

也就是：

“这个技能怎么做？”

Level 3：Resources

如果还需要更深的信息，再读取：

references/

例如：

references/
├── research-methodology.md
├── source-evaluation.md
├── competitor-framework.md
└── report-template.md
Level 4：Executable Capability

如果需要程序：

scripts/
├── scrape.py
├── analyze.py
├── generate_chart.py
└── validate.py

Agent 可以调用这些程序。

所以一个 Skill 本质上可以是：

Knowledge
+
Instructions
+
Procedures
+
Tools
+
Code
+
Resources
+
Templates

Anthropic 官方也明确把 Skill 描述为包含instructions、scripts、resources的文件夹，并通过渐进式披露减少上下文负担。citeturn0search3turn0search8

三、为什么 Skill 会出现？

这是理解 Skill 最重要的一层。

以前 Agent 通常是：

User
 ↓
Prompt
 ↓
LLM
 ↓
Answer

例如你告诉模型：

“帮我做一次竞品分析。”

模型只能：

凭已有知识
+
你的Prompt
+
当前Context

进行工作。

问题是：

问题1：重复

你每次都要告诉它：

第一步做什么
第二步做什么
第三步做什么
哪些网站可信
如何判断数据
报告怎么写
问题2：不稳定

今天：

Agent A → 竞品分析方式A

明天：

Agent A → 竞品分析方式B

换模型：

Agent B → 竞品分析方式C
问题3：上下文浪费

如果你把所有 SOP 全塞进 System Prompt：

100 个技能
×
每个 5000 tokens
=
巨大 Context

绝大多数任务根本用不到。

Skill 的解决方式

变成：

                 ┌── Skill A
                 ├── Skill B
Agent ───────────┼── Skill C
                 ├── Skill D
                 └── Skill E
                      ↓
                按需加载

所以 Skill 的核心不是：

“增加 Prompt。”

而是：

把 Agent 的专业知识和程序化工作方法模块化。

四、Skill 和 Prompt 最大的区别

这是很多人最容易搞混的地方。

Prompt

Prompt 更像：

“告诉模型这一次应该怎么做。”

例如：

你是一名专业市场分析师。

请分析以下产品：
xxx

要求：
1. 分析市场规模
2. 分析竞品
3. 分析消费者
4. 给出策略

一次性的。

Skill

Skill 是：

“把这个工作方法永久封装成可复用能力。”

例如：

market-research/
└── SKILL.md

里面规定：

任何市场研究任务：

1. 定义研究问题
2. 定义市场边界
3. 优先寻找一手资料
4. 对数据进行交叉验证
5. 区分事实/推断/观点
6. 建立竞争格局
7. 建立消费者画像
8. 输出结论
9. 给出战略建议

以后：

“帮我研究虫草市场”

Agent 就可以自动调用这个 Skill。

所以：

Prompt 是指令。 Skill 是能力封装。

五、Skill 和 Tool 完全不是一个东西

这是第二个非常关键的区别。

假设 Agent 要做市场调研。

它需要：

Skill
↓
告诉它怎么研究

然后：

Tool
↓
让它能够搜索

例如：

Market Research Skill
        │
        ├── 搜索网页
        ├── 查询数据库
        ├── 读取PDF
        ├── 分析Excel
        └── 生成报告

这里：

Skill = 怎么做

Tool = 用什么做

举个非常直观的例子：

Excel 是工具。 财务分析是技能。

Agent 有 Excel 工具，不代表它会做专业财务分析。

反过来：

Agent 有财务分析 Skill，但没有 Excel / Python / 数据库工具，也无法处理大型数据。

所以：

Skill + Tool
       ↓
真正可执行能力

六、Skill 和 MCP 又是什么关系？

这个关系非常重要。

可以把 MCP 理解成：

“连接工具和外部世界的标准接口。”

例如：

Agent
 │
 ├── MCP → GitHub
 ├── MCP → Notion
 ├── MCP → Google Drive
 ├── MCP → 数据库
 └── MCP → CRM

而 Skill 是：

Agent
 │
 └── Skill
       ↓
     如何使用这些工具完成任务

因此：

MCP = 能不能接上

Skill = 接上以后怎么干活

官方文档也明确区分：

MCP 提供外部服务和数据访问；Skill 提供完成任务所需要的程序性知识，两者可以组合使用。citeturn0search1

七、Skill 和 Workflow 的区别

这个更加高级。

Skill

解决：

“怎么做一类事情？”

例如：

SEO Skill

里面可能包含：

关键词研究
搜索意图分析
内容结构设计
内链策略
SERP分析
E-E-A-T检查
Workflow

解决：

“这几个事情按照什么顺序完成？”

例如：

产品上市 Workflow

市场调研
 ↓
消费者分析
 ↓
竞品分析
 ↓
产品定位
 ↓
包装策略
 ↓
内容营销
 ↓
渠道投放
 ↓
复盘

Workflow 可以调用多个 Skill：

Workflow
│
├── Market Research Skill
├── Consumer Insight Skill
├── Product Positioning Skill
├── Packaging Skill
├── SEO Skill
└── Marketing Skill

因此：

Skill 是能力模块。 Workflow 是能力编排。

九、Skill 最核心的创新：Progressive Disclosure

这是整个 Skill 架构里我认为最重要的设计。

传统 Agent：

启动
 ↓
加载所有知识
 ↓
巨大Context
 ↓
开始工作

Skill：

启动
 ↓
只加载 Skill 名称 + 描述
 ↓
识别任务
 ↓
发现相关 Skill
 ↓
加载 SKILL.md
 ↓
发现需要的 reference
 ↓
读取 reference
 ↓
发现需要的 script
 ↓

                 Agent
                   │
          ┌────────┴────────┐
          ↓                 ↓
      Skill Index        User Task
          │                 │
          └────────┬────────┘
                   ↓
             Skill Matching
                   ↓
            Load SKILL.md
                   ↓
             Load References
                   ↓

                   ↓

十一、所以 Skill 本质上是什么？

如果我要给一个更严格的技术定义：

Agent Skill 是一种可发现、可加载、可组合、可执行的程序性知识封装（Procedural Knowledge Package），用于将特定领域的知识、工作方法、操作规范、资源和工具调用方式转化为 Agent 可以按需调用的能力模块。

关键词是：

1. Discoverable

能够被 Agent 发现。

2. Loadable

需要的时候加载。

3. Composable

多个 Skill 可以组合。

4. Executable

可以真正执行。

5. Reusable

不同任务反复使用。

6. Portable

跨 Agent / 平台复用。

目前 Agent Skills 已经被明确作为开放标准发展，而不是某一家 Agent 的私有 Prompt 格式。citeturn0search1turn0search4

十三、一个真实 Skill 示例

比如我们做一个：

consumer-research

目录：

consumer-research/
│
├── SKILL.md
│
├── references/
│   ├── consumer-analysis.md
│   ├── persona-framework.md
│   ├── interview-method.md
│   └── evidence-rules.md
│
├── scripts/
│   ├── clean_data.py
│   └── analyze_survey.py
│
└── assets/
    └── consumer-report-template.md

SKILL.md

可以是：

---
name: consumer-research
description: >
  Conduct structured consumer research, consumer segmentation,
  persona construction, demand analysis and insight extraction.
  Use when analyzing customers, consumer needs, surveys,
  interviews, reviews or market demand.
---

然后：

# Consumer Research

## Objective

Transform raw consumer information into evidence-based
consumer insights.

## Workflow

1. Define research question.
2. Identify target consumer.
3. Collect evidence.
4. Separate facts from assumptions.
5. Segment consumers.
6. Identify needs and pain points.
7. Extract behavioral patterns.
8. Build consumer personas.
9. Generate actionable insights.

## Rules

- Do not treat assumptions as facts.
- Distinguish quantitative and qualitative evidence.
- Prioritize primary evidence.
- Explicitly identify uncertainty.
- Do not fabricate consumer data.

## Resources

For segmentation:
read references/persona-framework.md

For evidence evaluation:
read references/evidence-rules.md

For survey analysis:
use scripts/analyze_survey.py

这就已经不是普通 Prompt 了。

它已经开始成为：

一个可以复用的“消费者研究能力模块”。

十七、Skill 还有一个非常重要的属性：边界

好的 Skill 一定不是：

十八、Skill ≠ 知识库

所以：

Knowledge = What

这也是为什么 Skill 特别适合：

把一个人的工作经验“数字化”。

十、为什么 Decision Rules 特别重要？

因为专家真正值钱的地方往往不是：

“知道什么。”

而是：

“在什么情况下做什么决定。”

知道MOQ
知道模具费
知道运输费

但交期风险高
→ 不一定选择A

如果B价格高5%
但稳定性高
→ B可能更优

如果采购量达到100万
→ 可以重新议价

这就是：

Decision Skill

所以你之前一直想做的“采购 Agent”，实际上非常适合 Skill 化。

     ↓
判断产品是什么
     ↓
判断消费者是谁
     ↓
找消费者真正关心的问题
     ↓
提炼产品事实
     ↓
区分事实 / 卖点 / 利益
     ↓
把专业语言翻译成消费者语言
     ↓
建立包装信息层级
     ↓
生成正面核心文案
     ↓
生成辅助信息
     ↓
检查是否夸大
     ↓
输出方案

这已经开始从：

“Prompt”

变成：

“Skill”。

四、③ 把经验变成“判断规则”

这是 Skill 与普通 Prompt 最大的区别。

例如普通 Prompt：

请使用消费者语言。

太模糊。

你的个人 Skill 可以变成：

RULE-01
如果一个卖点需要专业知识才能理解，
优先转换成消费者可以直接理解的结果语言。

RULE-02
如果一个技术名词无法回答“对消费者有什么意义”，
则不得作为核心卖点。

RULE-03
包装正面优先表达：
产品是什么 + 核心价值 + 为什么值得购买。

RULE-04
一个包装正面原则上只保留一个第一核心卖点。

RULE-05
不得为了“显得高级”堆砌：
科技、臻选、匠心、赋能、矩阵等空泛词汇。

这就非常重要了。

因为：

Skill 的价值 ≠ 它知道什么，而是它知道“什么时候应该怎么判断”。

五、④ 把 Skill 分成 5 个核心部分

如果你是给自己长期使用，我建议不要把所有东西都塞进SKILL.md。

可以采用这个结构：

my-packaging-skill/
│
├── SKILL.md
│
├── rules/
│   ├── positioning.md
│   ├── consumer-language.md
│   ├── information-hierarchy.md
│   └── compliance.md
│
├── workflow/
│   └── workflow.md
│
├── examples/
│   ├── good.md
│   └── bad.md
│
├── templates/
│   └── packaging-output.md
│
└── evaluation/
    └── evaluation.md

核心逻辑是：

SKILL.md
   │
   ├── 我是谁 / 做什么
   │
   ├── 什么情况下使用
   │
   ├── 怎么做
   │
   ├── 怎么判断
   │
   └── 去哪里读取详细知识
        │
        ├── Rules
        ├── Workflow
        ├── Examples
        ├── Templates
        └── Evaluation

这也符合现在 Agent Skills 的一个重要设计方向：渐进式加载，而不是一开始把所有知识塞进上下文。

六、⑤ 给 Skill 一个明确的“输入 → 输出契约”

这是很多人制作 Skill 时容易忽略的。

比如：

输入
product:
  name: 有机五黑饮
  category: 植物饮品

ingredients:
  - 黑枸杞
  - 黑桑葚
  - 黑加仑
  - 黑莓
  - 黑豆

target_user:
  - 关注健康的人群

positioning:
  - 高花青素
  - 有机

Skill 不应该只是“自由发挥”。

而应该规定：

输入
↓
产品事实整理
↓
消费者需求分析
↓
核心价值提炼
↓
卖点优先级排序
↓
包装信息架构
↓
正面文案
↓
背面文案
↓
风险检查
↓
最终方案

最终输出也应该固定。

例如：

output:
  positioning:
  core_benefit:
  key_selling_points:
  front_panel:
  back_panel:
  visual_direction:
  compliance_risk:
  recommendations:

这样以后你的 Agent 才能稳定调用它。

七、⑥ 用你过去做过的“真实案例”训练 Skill

这一点对你尤其重要。

你过去已经做过大量类似：

  • 产品命名

  • 包装文案

  • 五黑饮

  • 黑枸杞

  • 冬虫夏草

  • 茶油

  • 松茸

  • 食品/健康产品

  • 消费者语言转换

这些实际上就是非常好的Skill Dataset。

不要只保存最终答案。

最好保存：

原始需求
↓
原始资料
↓
第一次方案
↓
哪里不好
↓
为什么不好
↓
如何修改
↓
最终方案
↓
为什么最终方案更好

例如：

案例：
“高活性花青素矩阵”

问题：
专业感强，但消费者不知道是什么意思。

修改：
“5种天然高花青素黑色果实”

进一步修改：
“5种天然黑色果实，富含花青素”

最终：
根据包装位置决定使用哪一种表达。

这时候 AI 学到的就不只是：

“某句话怎么写。”

而是：

“什么情况下应该这么写。”

这才是个人 Skill。

八、⑦ 最后一定要加入“自我评价标准”

这是从普通 Skill 走向生产级 Skill的关键。

例如你的包装文案 Skill，可以规定：

每次输出后必须检查：

① 消费者是否一眼理解？
② 是否明确产品是什么？
③ 是否只有一个第一核心卖点？
④ 是否存在专业术语堆砌？
⑤ 是否存在空泛营销词？
⑥ 是否存在重复表达？
⑦ 是否存在夸大宣传？
⑧ 是否符合产品真实事实？
⑨ 是否适合包装实际面积？
⑩ 是否具有购买理由？

然后让 AI 自己评分：

消费者理解度：9/10
卖点聚焦度：8/10
差异化：7/10
可信度：9/10
包装适配度：8/10

综合：8.2/10

这时候 Skill 就开始具有：

执行 → 检查 → 修正

的闭环。

九、你可以把自己的 Skill 看成一个“数字化分身”

这个思路我认为特别适合你。

你之前问过：

一本书能不能蒸馏成 Skill？ 一个人的语言和思维方式能不能蒸馏成 Skill？ 一个好用的技能能不能蒸馏出来？

答案实际上可以统一成：

原始专家
   ↓
经验资料
   ↓
案例
   ↓
决策过程
   ↓
判断规则
   ↓
方法论
   ↓
Skill
   ↓
Agent

所以：

Skill ≠ 知识库

知识库：

“我知道什么。”

Skill：

“我会怎么做。”

而你的个人 Skill 最有价值的部分其实是：

“我为什么这么做，而不是那么做。”

十、我建议你建立自己的“个人 Skill 工厂”

如果你准备长期做，我不建议一个一个手工写 Skill。

可以建立：

                 ┌──────────────┐
                 │   我的经验   │
                 └──────┬───────┘
                        ↓
                 ┌──────────────┐
                 │ 任务识别器   │
                 └──────┬───────┘
                        ↓
                 ┌──────────────┐
                 │ 方法提取器   │
                 └──────┬───────┘
                        ↓
              ┌─────────┴─────────┐
              ↓                   ↓
        决策规则提取          工作流程提取
              ↓                   ↓
              └─────────┬─────────┘
                        ↓
                 ┌──────────────┐
                 │ Skill生成器  │
                 └──────┬───────┘
                        ↓
                 ┌──────────────┐
                 │ Skill评测器  │
                 └──────┬───────┘
                        ↓
                  Production Skill
                        ↓
                 实际使用 / 反馈
                        ↓
                   Skill进化

最终形成：

你的个人 Skill OS。

十一、最适合你的制作路线

按照你之前一直在做的 Agent / OPC / Skill 体系，我建议不要从几十个 Skill 开始。

先做3 个“母 Skill”：

① 分析 Skill

负责：

看资料 → 找事实 → 找问题 → 找规律 → 得出结论

例如：

资料分析
竞品分析
市场分析
产品分析
文档分析
② 创作 Skill

负责：

信息 → 策略 → 表达 → 成品

例如：

包装文案
产品命名
营销文案
视觉提示词
方案撰写
③ 决策 Skill

负责：

多个方案 → 判断 → 筛选 → 推荐

例如：

供应商选择
包装方案选择
产品定位
采购决策
方案评审

然后再从这三个母 Skill 向下拆：

Personal Skill OS
│
├── Analysis
│   ├── Document Analysis
│   ├── Competitor Analysis
│   ├── Product Analysis
│   └── Market Analysis
│
├── Creation
│   ├── Packaging Copy
│   ├── Product Naming
│   ├── Marketing Copy
│   └── Visual Prompt
│
└── Decision
    ├── Supplier Selection
    ├── Packaging Evaluation
    ├── Product Positioning
    └── Procurement Decision

这样就不是在“做几个 Prompt”。

而是在逐渐建立：

**一个属于你自己的 AI 能力系统。**🚀

最关键的一句话

如果让我把整个方法压缩成一个公式：

个人 Skill
=
你的经验
+ 你的方法
+ 你的判断规则
+ 你的案例
+ 你的输出标准
+ AI可执行流程

而一个成熟 Skill 最终应该形成：

触发
 ↓
理解任务
 ↓
加载必要知识
 ↓
调用方法
 ↓
执行
 ↓
做判断
 ↓
输出
 ↓
自检
 ↓
修正
 ↓
记录经验
 ↓
Skill升级

这就已经从Prompt Engineering开始进入Personal Agent Engineering了。

如果你愿意进一步做，我建议下一步直接拿你最擅长、最经常做的一项工作，把它从你的实际经验中反向“蒸馏”出来。我可以带你一步一步把它做成一个真正可以放进OpenClaw / Claude / Codex / 自己的 Agent 系统里的生产级 Skill。

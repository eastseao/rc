文章分类和页面添加

10 Nov, 2025
|编辑页面

Q1 · 我想给文章都加上分类，并在pages/里加入一个分类的.md页面（第 1 轮对话）

提问： 我想给文章都加上分类，并在pages/里加入一个分类的.md页面

你可以通过以下方式为文章添加分类，并创建一个新的分类页面：

1. 为文章添加分类

在每篇文章的front matter中，添加categories字段。你可以为每篇文章添加一个或多个分类。

例如：

---
layout: post
title: "我的第一篇文章"
date: 2025-11-09
categories: [技术, 编程]
tags: [Jekyll, Blog]
---
2. 创建分类页面

在pages/目录下，创建一个新的.md文件，用来展示所有分类的列表。例如，创建一个categories.md文件。

---
layout: page
title: "分类"
permalink: /categories/
icon: fas fa-list-alt
---

<h2>文章分类</h2>

<ul>
  {% for category in site.categories %}
    <li><a href="{{ site.baseurl }}/categories/{{ category[0] }}">{{ category[0] }}</a> ({{ category[1].size }})</li>
  {% endfor %}
</ul>

这段代码会列出你所有的分类，并且每个分类都会链接到该分类的页面。

3. 显示特定分类的文章

你可以为每个分类创建一个页面，列出属于该分类的文章。为此，在categories/目录下创建一个新的.md文件，并按以下方式修改：

---
layout: category
title: "技术"
permalink: /categories/技术/
icon: fas fa-laptop-code
---

{% for post in site.categories.技术 %}
  <h3><a href="{{ post.url }}">{{ post.title }}</a></h3>
  <p>{{ post.date | date: "%B %d, %Y" }}</p>
  <p>{{ post.excerpt }}</p>
{% endfor %}

这段代码会在categories/技术/页面上列出所有属于技术分类的文章。

4. 调整_config.yml

确保在_config.yml中启用分类功能：

defaults:
  - scope:
      path: "posts"
    values:
      categories: []

完成后，你的博客会有一个分类页面，并且每个分类下会显示对应的文章。

Q2 · 点击3的页面，一片空白（第 2 轮对话）

提问： 点击3的页面，一片空白

明白了，这种情况通常是布局模板layout: category不存在或不兼容，所以页面渲染为空。你有两个解决方案：

方案 1：使用已有布局page，在 Markdown 中用 Liquid 生成分类列表

修改你的分类页面，例如pages/category-tech.md：

---
layout: page
title: "技术分类"
permalink: /categories/技术/
---

<h2>技术分类下的文章</h2>

<ul>
  {% assign posts_in_category = site.categories.技术 %}
  {% for post in posts_in_category %}
    <li>
      <a href="{{ post.url }}">{{ post.title }}</a> - {{ post.date | date: "%Y-%m-%d" }}
    </li>
  {% endfor %}
</ul>

这里不用layout: category，直接用page就可以显示列表。

方案 2：自定义一个category.html布局

如果你希望用专门的布局：

  1. 在 _layouts/ 目录下创建 category.html ，内容示例：
---
layout: default
---

<h1>{{ page.title }}</h1>

<ul>
  {% assign posts_in_category = site.categories[page.category] %}
  {% for post in posts_in_category %}
    <li><a href="{{ post.url }}">{{ post.title }}</a></li>
  {% endfor %}
</ul>
  1. 然后在页面 front matter 中引用：
---
layout: category
title: 技术分类
category: 技术
permalink: /categories/技术/
---

✅总结： 空白页大多数是因为layout: category不存在或 Liquid 变量没写对。最简单方法是直接用layout: page+ 在页面内写 Liquid 循环生成文章列表。

Q5 · 404（第 5 轮对话）

提问： 404

明白了，你遇到404是因为 GitHub Pages 并不会像本地 Jekyll 那样自动生成新的页面文件，如果你只是写了循环生成的链接，但是对应的.md文件不存在，点击就会报 404。

也就是说，所有分类页都必须有真实的.md文件或者 HTML 文件存在仓库里。Liquid 循环本身不会替你生成物理文件。

最简单可行的做法（网页版即可操作）
  1. 总分类页 （列出所有分类）

pages/categories.md：

---
layout: page
title: "文章分类"
permalink: /categories/
---

<h1>文章分类</h1>

<ul>
  {% for category in site.categories %}
    {% assign category_slug = category[0] | slugify %}
    <li>
      <a href="{{ site.baseurl }}/categories/{{ category_slug }}/">
        {{ category[0] }} ({{ category[1].size }}篇文章)
      </a>
    </li>
  {% endfor %}
</ul>
  1. 为每个分类创建页面

在pages/categories/下手动创建一个.md文件，例如技术.md：

---
layout: page
title: 技术分类
permalink: /categories/技术/
---

<h1>技术分类下的文章</h1>

<ul>
  {% for post in site.categories.技术 %}
    <li>
      <a href="{{ post.url }}">{{ post.title }}</a> - {{ post.date | date: "%Y-%m-%d" }}
    </li>
  {% endfor %}
</ul>

  • layout: page 用已有布局即可，不需要新建 category.html 。

  • 点击总分类页里的链接就不会 404，因为页面真实存在。

  1. 其他分类重复步骤 2

每个分类都建一个.md文件，内容只需改title和category名称。

💡关键点：GitHub Pages 上Liquid 循环无法自动生成页面文件，所以必须保证每个链接对应的.md文件存在仓库里，否则访问会 404。

Q6 · 现在进入感悟页面，只有： 感悟分类下的文章 - - - - - -（第 6 轮对话）

提问： 现在进入感悟页面，只有： # 感悟分类下的文章 --------

明白了，你看到的是一堆- -，说明页面渲染了<ul>但是Liquid 循环没有获取到任何文章。出现这种情况一般有几个原因：

1️⃣ 文章 front matter 分类写法不对

请检查每篇文章的 front matter，categories的写法必须正确。例如：

---
layout: post
title: "我的感悟文章"
date: 2025-11-09

tags: [生活, 学习]
---

⚠ 注意：

  • 必须是数组形式 [感悟] 或者单值 categories: 感悟 。

  • 名称大小写必须一致， 感悟 ≠ 感悟 （尾部空格也会导致匹配失败）。

2️⃣ 分类页面 Liquid 循环写法

确保你的分类页面.md文件里循环正确。例如pages/categories/感悟.md：

---
layout: page
title: "感悟分类"
permalink: /categories/感悟/
---

# 感悟分类下的文章

<ul>
  {% for post in site.categories.感悟 %}

    </li>

  • site.categories.感悟 必须和文章 front matter 的分类完全一致。

  • 如果文章没有写 categories: 感悟 或者写成 category: 感悟 ，就不会出现在这里。

3️⃣ 确认_posts文件夹

  • 文章必须在 _posts 或你配置的 posts 目录下。

  • GitHub Pages 上默认只会扫描 _posts 目录下的文章。

<p>感悟分类文章数量：{{ site.categories.感悟 | size }}</p>

如果输出是0，说明文章分类没被识别，需要检查 front matter 或路径。

Q8 · 还是不显示文章（第 8 轮对话）

提问： 还是不显示文章

明白了，你现在遇到的问题是分类页不显示文章，即使模板正确，也没有文章被渲染出来。这在 Jekyll / GitHub Pages 上最常见的原因是文章的 front matter 分类没有被正确识别或文章文件路径不在_posts目录。我们一步步排查：

1️⃣ 确认文章位置

  • GitHub Pages 默认只会读取 _posts 目录下的文章。

  • 文件命名必须符合 Jekyll 规范： YYYY-MM-DD-标题.md

例如：_posts/2025-11-09-感悟文章.md

如果你的文章不在_posts目录，site.categories是无法识别的。

2️⃣ 确认 front matter 分类字段

每篇文章必须包含：

---
layout: post
title: "我的感悟文章"
date: 2025-11-09
categories: [感悟]
---

✅ 注意事项：

  • categories 必须是 数组形式 [感悟] 或单值 categories: 感悟 。

  • 中文分类名必须和分类页里使用的完全一致。

  • 不要写成 category （少了 s）或者其他拼写。

3️⃣ 测试分类是否识别

在分类页里临时加一行：

<p>感悟分类文章数量：{{ site.categories.感悟 | size }}</p>

  • 如果输出是 0 → 说明 Jekyll 没有识别文章分类。

  • 如果输出大于 0 → 说明模板循环有问题。

4️⃣ 简单可用模板（确保显示文章）
---
layout: page
title: "感悟分类"
permalink: /categories/感悟/
---

# 感悟分类下的文章

{% assign posts_in_category = site.categories.感悟 %}

<p>共 {{ posts_in_category.size }} 篇文章</p>

{% for post in posts_in_category %}
- [{{ post.title }}]({{ post.url }}) - {{ post.date | date: "%Y-%m-%d" }}
{% endfor %}

{% if posts_in_category.size == 0 %}
<p>目前还没有文章归类到“感悟”。</p>
{% endif %}

用最简单的 Markdown 列表和链接渲染，确保不会因为 HTML 或 CSS 问题导致空白。

总结：

  1. 文章必须在 _posts 目录。

  2. categories 必须正确写。

  3. 分类页里循环字段必须和 categories 一致。

    Q17 · 还是不行（第 17 轮对话）

    提问： 还是不行

    这就有意思了。site.categories.感悟 | size能显示数量，但文章列表始终不渲染，连layout: null和最简 HTML 都试过了还是空白。

    这说明问题不是 Liquid、不是 front matter、不是 CSS——而是 GitHub Pages 的 Jekyll渲染顺序 + 你仓库目录结构的问题。

    你现在遇到的是：

    分类名能计数 ✅ 但循环for post in site.categories.xxx输出为空 ❌

    这只会在一种情况下发生：

    🔥 你的文章不是被 Jekyll 当成“文章”处理

    也就是说：

    ✅_posts/2025-01-01-xxx.md这种格式 → 才会被识别
    ❌posts/xxx.md或pages/xxx.md或文章名.md→ 不算博客文章

    你可能现在的文章是：

    pages/xx.md

    或者你的_posts目录名字有错，比如：

    _posts/  ✅
post/    ❌
_posts   ❌(没下划线)
_posts/2025-11-01-文章.md ✅
_posts/文章.md ❌(没有日期)
    ✅ 请你确认这三件事
    1. 仓库根目录是否有_posts/文件夹

    如果没有，请新建：Add file → Create new file

    文件名:

    _posts/.keep
    2. 你的文章文件名格式必须像这样

    ✅ 正确例子：

    _posts/2025-11-01-my-life-note.md

    ⚠️ 错误例子：

    2025-11-01-my-life-note.md          ❌不在_posts
_posts/my-life-note.md              ❌无日期
_posts/2025-11-01-我的文章          ❌无.md
    3. front matter 必须有 categories
    ---
title: "生活中的小确幸"
date: 2025-11-01
categories: [感悟]
---

    Q18 · 1,2,3都是正确部署的，测试也是对的（第 18 轮对话）

    提问： 1,2,3都是正确部署的，测试也是对的

    非常好——这其实是个关键信息。 如果_posts/2025-01-01-test.md出现在site.categories.感悟中、并能正确显示数量，但页面还是空白，那我们几乎可以断定：

    Liquid 模板确实在运行，但循环部分被吞掉了——要么被 theme 的 include / layout 结构覆盖，要么是 markdown 渲染顺序出问题。

    我们可以现在来精准定位这一层问题。

    🧭 第一步：确认 Markdown 是否干扰了 Liquid 渲染

    Jekyll 对.md文件的处理顺序是：

    Front matter → Liquid → Markdown → Layout

    有时，如果分类页面写成.md且模板中有 HTML 或 Liquid 逻辑， 它会被 Markdown “吃掉”一部分标签。

    解决方法：把分类页从.md改成.html。

    ✅ 操作

    把原来的：

    pages/categories/ganwu.md

    改名为：

    pages/categories/ganwu.html

    内容改成：

    ---
layout: simple
category_name: "感悟"
permalink: /categories/ganwu/
title: "感悟分类"
---

<h1>{{ page.title }}</h1>

{% assign posts_in_category = site.categories[page.category_name] %}
<p>共 {{ posts_in_category | size }} 篇文章</p>

{% if posts_in_category.size > 0 %}
  <ul>
    {% for post in posts_in_category %}
      <li>
        <a href="{{ post.url }}">{{ post.title }}</a> - 
        <span style="color: #888;">{{ post.date | date: "%Y-%m-%d" }}</span>
      </li>
    {% endfor %}
  </ul>
{% else %}
  <p>目前还没有文章归类到“{{ page.category_name }}”。</p>
{% endif %}

    🧭 第二步：确认layout: simple真被加载

    打开页面后，按 F12 → 查看页面源代码。 看看最上方<title>是否是 “感悟分类”。

    如果<title>没变，那 Jekyll 仍在用主题默认的 layout，而不是我们的simple.html。

    如果是这样，请尝试：

    layout: null

    直接让页面不使用任何布局，确保渲染逻辑来自文件本身。

    🧭 第三步：临时调试输出所有分类和文章

    在页面底部加上：

    <hr>
<h2>调试信息</h2>
<ul>
{% for cat in site.categories %}
  <li>{{ cat[0] }}: {{ cat[1] | size }} 篇
    <ul>
    {% for post in cat[1] %}
      <li>{{ post.title }} → {{ post.url }}</li>
    {% endfor %}
    </ul>
  </li>
{% endfor %}
</ul>

    这会暴力打印出 Jekyll 识别到的所有分类及其文章。 哪怕前面的循环被吞掉，这段一定能显示。

    如果这段能正确打印所有分类和文章，那么我们可以肯定 Liquid 是正常的，只是前面的 HTML 或 layout 被覆盖。 如果这段都不显示，那么我们要查_config.yml是否禁用了categories相关变量（某些 theme 会在collections配置中重载posts）。

    Q19 · 404（第 19 轮对话）

    提问： 404

    明白，这说明分类页的路径和 GitHub Pages 的路由不一致。 我们来彻底修复它，让分类页能正确加载。请按照以下步骤操作：

    ✅1. 修改分类页文件位置

    确保你的文件路径是：/pages/categories.html（不是.md）

    如果是.md文件，请改成.html。

    ✅2. 修改文件头部 Front Matter

    请将文件内容改为以下版本（完整替换）：

    ---
layout: default
title: 分类
permalink: /categories/
icon: fas fa-folder
---

<h1>文章分类</h1>

<ul>
  {% assign categories = site.categories | sort %}
  {% for category in categories %}
    <li>
      <a href="{{ '/categories/' | append: category[0] | relative_url }}">
        {{ category[0] }} ({{ category[1].size }})
      </a>
    </li>
  {% endfor %}
</ul>

    说明：permalink: /categories/会确保页面访问路径是https://你的用户名.github.io/categories/。 之前 404 是因为路径没注册或 permalink 不匹配。

    ✅3. 给文章添加分类

    在_posts里的文章头部（Front Matter）加上：

    ---
layout: post
title: "我的第一篇感悟"
date: 2025-11-09
categories: [感悟]
tags: [生活, 思考]
---

    注意：categories必须是一个数组（即用方括号），否则 Jekyll 不会识别。

    ✅4. 提交后访问

    提交更新后，等 GitHub Pages 构建完成，再访问：

    https://seamoonappear.github.io/categories/

    你应该会看到：

    感悟 (1)
学习 (2)
生活 (3)

    点击“感悟”会进入/categories/感悟/页面，显示文章列表。

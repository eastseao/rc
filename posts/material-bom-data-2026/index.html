01 · 采购明细表的加列与排序规范（00031 · 2025-07-21）

最早的一篇是一条很具体的整理需求：面对一堆已有的采购单表格，每份购单的「采购明细」这一栏，名称、规格、数量、单位、价格都要保留，再往后补两列、并按提交时间重排。这是整套物料数据工作的起点——先把单子理干净，才谈得上查询与联动。

00031 · 整理要求

对现有采购明细表要做的三件事

动作具体要求
保留明细列每份购单的「采购明细」栏原样保留：名称、规格、数量、单位、价格，不删不改。
追加两列在采购明细这一栏的价格后面依次加：审批编号、提交人。
统一排序整理后的整张表按提交的时间排列，早提交的在前、晚提交的在后。
口径说明：原始笔记只有这一条整理指令，未附具体表格数据；本节照录要求本身，作为后续「物料查询与 BOM」系统里明细表字段设计的依据。

02 · 物料查询与产品 BOM 的联动扩展（00365 · 2025-10-31）

在网页上已经搭好「物料查询」和「产品 BOM 查询」、并上传了关联数据 data.json 之后，下一步能做哪些联动？笔记按六类给出了十二项设计，并顺手解决了计量单位英文代码换中文的问题。

00365 · 六类联动

基于 data.json 可以扩展的十二类联动功能

联动类别功能点
核心数据联动① 物料-BOM 双向联动：点击物料 → 显示使用该物料的所有产品；点击产品 → 展示 BOM 中所有物料详情。② 实时库存监控：物料库存预警联动 BOM 需求；低库存物料影响的产品生产计划提醒。
智能分析联动③ 成本计算联动：自动计算产品物料成本；物料价格变动 → 实时更新产品成本。④ 供应链风险分析：关键物料缺货影响的产品清单；供应商变更影响分析。
高级查询联动⑤ 交叉查询：按物料特性筛选适用产品；按产品类型反推所需物料类别。⑥ 相似产品推荐：基于物料使用相似度的产品推荐；替代物料智能推荐。
可视化联动⑦ BOM 层级可视化：树状图展示产品物料结构，点击任一节点查看详细信息。⑧ 物料依赖关系图：展示物料在产品间的使用关系网络。
业务流程联动⑨ 生产计划模拟：输入生产数量 → 自动计算所需物料总量；物料可用量 → 计算最大可生产数量。⑩ 采购建议生成：基于销售预测自动生成采购需求，考虑现有库存和采购周期。
预警与通知联动⑪ 智能预警系统：物料价格异常波动预警；库存周转率异常提醒。⑫ 变更影响分析：物料规格变更影响的产品清单；工程变更通知（ECN）影响范围。

笔记给出两个直接可用的实现示例——按物料反查产品、按产品汇总成本：

// 物料-BOM 联动查询 function getProductsByMaterial(materialId) { return data.boms.filter(bom => bom.components.some(comp => comp.material_id === materialId) ).map(bom => bom.product_id); } // 产品成本计算 function calculateProductCost(productId) { const bom = data.boms.find(b => b.product_id === productId); return bom.components.reduce((total, comp) => { const material = data.materials.find(m => m.id === comp.material_id); return total + (material.price * comp.quantity); }, 0); }

  • 版本控制——BOM 版本历史追踪
  • 权限管理——不同部门查看不同信息
  • API 集成——对接 ERP / MES 系统
  • 移动端适配——随时随地查询

04 · 食品公司 BOM 拆解的职责归属（01112 · 2026-05-08）

「产品 BOM 的拆解一般是产品经理还是采购完成？」——结论是不是单一角色，而是产品经理主导、采购与研发与生产密切协作的团队项目：产品/研发出配方，采购出价格与规则，生产出方法。

01112 · 四阶段分工

BOM 拆解各阶段的主导方与关注点

阶段主导方主要职责与关注点
配方研发与设计产品经理 / 研发关注产品的功能、口味、包装等市场与技术要求；确定 BOM 的「骨架」，即产品的原料、配方和初步生产工艺。
成本核算与分析产品经理 / 研发关注产品的商业可行性与成本；主导 BOM 的成本测算，为产品定价和盈利能力负责。
采购 BOM 构建与支持采购关注成本、供应商与供应链效率；将理论物料转化为可采购的物料清单（PBOM），提供采购规则、供应商信息和价格。
BOM 审核与发布产品经理 / 研发关注最终产品的完整性与一致性；综合采购、生产等意见，审核并批准最终的 BOM 版本，并维护其准确性。

为什么采购不可或缺

现代食品公司的 BOM 至少有三副面孔——研发 EBOM、制造 MBOM、采购 PBOM，强行统一成一套反而造成管理混乱。采购主导PBOM：以「白砂糖」为例，同样 500 公斤，采购必须明确规格是 50 公斤/袋还是 500 公斤/吨袋、验收标准、供应商、最小起订量，这份清单对研发配方至关重要。

常见实践场景

大型集团
产品经理或研发主攻设计与成本，采购在框架内深入优化、提供市场信息与备选方案；有的公司专设「BOM 工程师」「BOM 文员」岗位，专职 BOM 数据创建、维护与跨部门协调。
中小企业
角色融合，常出现「产品采购经理」一类岗位，既懂产品开发又懂供应链，独自完成从概念到落地的全过程。

GitHub 上传技能流程

20 Apr, 2026
|编辑页面

Q1 · 我要把我的技能都上传到我的github里，怎么操作，告诉我详细流程（第 1 轮对话）

提问： 我要把我的技能都上传到我的github里，怎么操作，告诉我详细流程

好，这件事本质就是：把你的 Skill 文件夹 → 推到 GitHub 仓库。我给你一套小白也能走通的完整流程（纯网页版 + 本地版两种），你按你当前能力选一种就行。

🚀 一、最简单（推荐）：纯网页上传（不用装任何工具）

适合你现在这种：不会本地操作 / 不想折腾环境

✅ 第一步：创建仓库

  1. 打开 👉 entity[“website”,“GitHub”,“code hosting platform”]

  2. 登录账号（你是 seamoonappear 对吧）

  3. 右上角点 “+” → New repository

填写：

  • Repository name： my-skills （随便起）

  • 选择：✅ Public（建议公开）

  • 勾选：✅ Add a README

点击：Create repository

✅ 第二步：创建目录结构

在仓库页面：

点击：Add file → Create new file

文件名输入：

wechat-article-pro/skill.md

👉 注意：这样会自动创建文件夹

然后粘你 skill.md 内容 → Commit

✅ 第三步：继续补全结构

重复操作，创建这些文件：

wechat-article-pro/config.yaml

wechat-article-pro/prompt/topic.md
wechat-article-pro/prompt/outline.md
wechat-article-pro/prompt/rewrite.md
wechat-article-pro/prompt/deai.md
wechat-article-pro/prompt/layout.md
wechat-article-pro/prompt/image.md
wechat-article-pro/prompt/cover.md
wechat-article-pro/prompt/explode.md

wechat-article-pro/templates/article.md
wechat-article-pro/templates/title.txt

wechat-article-pro/Memory.md

⚡ 一个关键技巧（避免你手动建太慢）

你可以：

👉 先在本地用记事本整理好一个文件夹 👉 压缩成 zip 👉 用 GitHub 网页直接拖进去上传

🧠 二、进阶版（推荐你以后用）：Git + 本地上传

如果你想走“专业路线”，一定要学这个。

✅ 第一步：安装 Git

去下载 👉 entity[“software”,“Git”,“version control system”]

安装一路 Next 就行

✅ 第二步：克隆仓库

打开终端（或 Git Bash）：

git clone https://github.com/seamoonappear/my-skills.git

进入目录：

cd my-skills

✅ 第三步：把你的 Skill 丢进去

比如你本地结构：

wechat-article-pro/

直接拖进my-skills文件夹

✅ 第四步：提交 + 上传

git add .
git commit -m "upload my skill"
git push

🔥 三、高手效率流（你后面一定会用）

等你 Skill 多了，建议这样组织：

my-skills/
├── wechat-article-pro/
├── deaify/
├── graphmind/
├── novel-writer/
├── printing-knowledge/

👉 一个仓库 = 所有技能库 👉 方便你做“AI技能市场”

🧩 四、给你一个优化建议（很重要）

你现在不是在“存文件”，你是在做：

👉个人AI能力资产库

建议你每个 Skill 加：

README.md

写：

  • 这个技能干嘛

  • 怎么用

  • 示例输入输出

未来你可以直接：

👉 做 GitHub 展示 👉 做知识付费 👉 做 Agent 商店

⚠️ 常见坑（提前帮你踩掉）

❌ 上传失败

→ 没登录 GitHub / 没权限

❌ 文件夹传不上去

→ GitHub 不允许空文件夹 👉 解决：放一个.gitkeep

❌ 中文乱码

→ 文件统一 UTF-8

我可以帮你直接做：

✅ 一键打包完整 Skill 仓库结构 ✅ 帮你命名所有技能体系 ✅ 给你做成“AI工作室级 GitHub 项目”

你只需要说一句：

Q2 · 一个库里可以放很多个Skill吗（第 2 轮对话）

提问： 一个库里可以放很多个Skill吗

可以，而且强烈建议这么做。

你现在这个阶段，用「一个仓库管理多个 Skill」是最合理的，不然很快就会乱掉。

🧠 一句话结论 👉 一个 GitHub 仓库完全可以放很多个 Skill 👉 而且这是主流做法（类似插件市场 / 工具集合）

📦 推荐结构（直接照这个来就行）

my-skills/
├── README.md              # 总说明（你的技能宇宙入口）
│
├── wechat-article-pro/   # 爆款文章技能
│   ├── skill.md
│   ├── config.yaml
│   ├── prompt/
│   ├── templates/
│   └── Memory.md
│
├── deaify/               # 去AI味技能
│   ├── skill.md
│   ├── prompt/
│   └── examples/
│
├── novel-writer/         # 小说生成技能
│   ├── skill.md
│   ├── outline.md
│   ├── chapters/
│   └── Memory.md
│
├── graphmind/            # 结构化记忆技能
│   ├── skill.md
│   ├── schema.yaml
│   └── data/
│
└── printing-knowledge/   # 印刷知识库
    ├── skill.md
    ├── docs/
    └── assets/

🔥 为什么要这样做（重点）

1️⃣ 集中管理（不容易乱）

如果你一个 Skill 一个仓库：

👉 10 个 skill = 10 个 repo 👉 管理直接崩

2️⃣ 更像“产品体系”

一个仓库就是：

👉你的 AI 工具箱 / 技能商店

3️⃣ 方便未来扩展

以后你可以直接：

  • 做官网（配合 GitHub Pages）

  • 做 Skill 文档站

  • 接入 Agent（OpenClaw / Hermes）

⚖️ 什么时候要拆成多个仓库？

只有这几种情况才拆：

✅ 技能特别大（像项目）

比如：

  • SaaS工具

  • 带后端服务

  • 独立产品

✅ 需要单独开源/商业化

比如：

👉 一个 Skill 要单独卖 / 引流

🧩 进阶玩法（你后面一定会用）

在根目录做一个总入口 README：

# 🧠 My AI Skills

## ✍️ 内容创作
- wechat-article-pro
- deaify

## 📚 知识系统
- graphmind
- printing-knowledge

## 📖 写作系统
- novel-writer

👉 这一步非常关键 👉 直接决定你项目的“专业感”

🎯 给你一个更狠的建议（重要）

你现在其实可以升级成：

👉AI技能工作室架构

仓库名建议改成：

ai-skill-studio

未来你可以：

  • 放 20+ skills

  • 做自动化流水线

  • 做内容工厂

👉一个仓库放多个 Skill = 标准做法（推荐）👉一个 Skill 一个仓库 = 后期才需要

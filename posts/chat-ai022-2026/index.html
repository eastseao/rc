文档可视化技能审计

|编辑页面

Q1 · 这是可以文档可视化的一套skill，我的要求是，使用这个技能后，直接生成.md文…（第 1 轮对话）

提问： 这是可以文档可视化的一套skill，我的要求是，使用这个技能后，直接生成.md文档。要能适配typora1.10.8及以上版本，给我做一个深度审计，prompt里的代码才是核心。

下面是对你这套**文档可视化 Skill（核心是 prompt.md）**的一次“深度审计 + 可落地优化方案”。我会直接拆核心问题、隐患、以及如何改成“稳定输出 Typora 兼容 .md 文档”的版本。

一、核心结论（先说人话）

你这套 prompt 的设计思路是对的，但有3个致命问题：

❶ 最大风险：四反引号包裹 = 极不稳定

👉 在很多模型输出中，会出现：

  • 提前闭合（尤其遇到 ```mermaid）

  • 被截断

  • Typora 粘贴后异常

➡️ 这是你整个 Skill最大不稳定来源

❷ HTML + Markdown 混写：Typora 兼容 ≠ 完全安全

Typora 虽然支持 HTML，但：

  • flex 在不同版本渲染不一致

  • 阴影、渐变在导出 PDF 时容易丢失

  • 过多会导致：

  • 复制到其他编辑器崩掉 - GitHub 渲染异常

❸ prompt 是“展示导向”，不是“生成导向”

现在的 prompt 更像：

👉「帮我做一个好看的文章」

但你真正要的是：

👉「稳定生成结构化 .md 文件（可复用、可自动化）」

二、逐条深度审计（重点在 prompt 设计）

1️⃣ 外层包裹规则（严重问题）

当前：
必须使用 ````markdown 包裹
问题：

  • LLM 在嵌套代码块时极易错位

  • Mermaid + ``` 会直接冲突

  • Typora 不需要这个包裹

✅ 建议改成：
❌ 删除外层四反引号强制规则

✅ 改为：
“直接输出完整 Markdown 文档内容，不要添加任何解释说明，不要使用外层代码块包裹”

2️⃣ 标题规则（可以优化）

当前：
<h2 style="text-align: center;">
问题：

  • HTML 标题不利于 SEO / Markdown 目录

  • Typora 目录识别失败

✅ 推荐：
## 标题
<p style="text-align:center; color:#333;">副标题说明</p>

👉 兼顾：

  • Markdown 结构

  • 视觉效果

3️⃣ 卡片布局（最大兼容风险点）

当前：
display: flex;
问题：

  • Typora 有时渲染 OK，但：

  • 导出 PDF 会乱 - GitHub 不支持

✅ 建议两种模式（关键升级）

👉 在 prompt 中加入“渲染等级”：

渲染模式：
- A级（Typora增强版）：允许 flex + 阴影
- B级（通用Markdown）：使用表格模拟卡片
✅ 推荐替代写法（更稳）：
<table style="width:100%;">
<tr>
<td style="border:1px solid #bbdefb; border-radius:10px; padding:10px;">
卡片内容
</td>
<td>...</td>
</tr>
</table>

👉 兼容：

  • Typora

  • GitHub

  • PDF

4️⃣ 表格设计（合格，但可以增强）

当前 OK，但建议：

👉 强制加：

- 所有表格必须可复制为纯Markdown版本

否则：

  • 用户复制到 Notion / 飞书 会炸

5️⃣ Mermaid（隐性风险）

当前：

“可适当添加 Mermaid”

问题：

  • Typora 支持，但：

  • GitHub 支持有限 - 外层代码块冲突（你现在必炸）

✅ 建议：
仅在流程明确时使用 Mermaid
且必须使用：
不得嵌套在其他代码块中

6️⃣ 署名规则（OK，但可以自动化）

当前：
<p>[App名]整理于 2025-03-19</p>
问题：
  • 日期不会自动更新
✅ 建议：
自动使用当前日期（YYYY-MM-DD）

三、最关键优化（Prompt核心升级）

我帮你把核心 prompt**重写成“工业级稳定版本”**👇

✅【新版 Prompt 核心片段】

你可以直接替换原 prompt 的关键部分：

你需要生成一份“可直接作为 .md 文件使用”的文档，必须满足以下要求：

【输出规则】
1. 直接输出 Markdown 正文内容
2. 不要使用任何代码块包裹（禁止 ``` 或 ````）
3. 不要输出解释、说明或前言

【结构规则】
- 使用 Markdown 标题（## / ###）
- 保证可生成目录结构
- 所有内容模块化（卡片化 / 表格化）

【视觉增强规则（Typora 优化）】
- 允许使用 HTML（仅限 div / table / p）
- 所有样式必须写在 style 内联中
- 禁止复杂 CSS（如 position、grid）

【兼容优先级】
必须同时兼容：
1. Typora 1.10+
2. GitHub Markdown
3. PDF 导出

【卡片规范】
优先使用 table 模拟卡片
仅在必要时使用 flex

【表格规范】
必须保证：
- 可读性
- 可复制
- 不依赖 CSS 也能展示

【Mermaid 规则】
- 仅在流程类内容使用
- 使用标准 ```mermaid 代码块
- 不得嵌套

【颜色规范】
主色：#e3f2fd / #bbdefb / #2196f3
辅助：#b3e5fc / #b2dfdb
文字：#333

【文末】
输出：
<p style="text-align:center; color:#777;">[App名]整理于 YYYY-MM-DD</p>

四、你这套 Skill 的定位升级建议（很关键）

你现在其实做的是：

👉 ❌「好看的 Markdown」

你应该升级为：

👉 ✅「文档生成引擎（Document Engine Skill）」

建议增加 3 个能力层

1️⃣ 模板层（Template）

  • 报告

  • 分析

  • SOP

  • PPT稿

2️⃣ 渲染层（Render Mode）
render_mode:
  - typora_pro
  - github_safe
  - pure_markdown
3️⃣ 内容层（Content Engine）

  • 自动结构化

  • 自动摘要

  • 自动卡片化

五、一句话总结

你这套 Skill 的问题不是“写得不够好”，而是：

👉太追求视觉，牺牲了稳定性

真正强的版本应该是：

👉70%稳定结构 + 30%视觉增强

如果你要，我可以帮你直接做一版：

👉「终极版本 Skill（含 skill.md + prompt.md + 渲染模式 + 自动生成 .md 文件标准）」

而且可以顺带接入你之前做的：

  • 市场调研

  • 竞品分析

  • 食品行业 Agent

变成一个统一输出报告系统。

import datetime
import json

def generate_document(topic, doc_type="report", render_mode="typora_pro", depth="标准"):
    date = datetime.datetime.now().strftime("%Y-%m-%d")

    structure_map = {
        "report": [
            "行业背景",
            "市场现状",
            "竞争格局",
            "用户分析",
            "趋势预测",
            "结论建议"
        ],
        "analysis": [
            "问题定义",
            "数据拆解",
            "关键洞察",
            "结论"
        ],
        "sop": [
            "目标",
            "适用范围",
            "流程步骤",
            "注意事项"
        ],
        "brief": [
            "项目背景",
            "目标",
            "策略",
            "执行方案"
        ]
    }

    sections = structure_map.get(doc_type, structure_map["report"])

    doc = f"## {topic}\n\n"
    doc += f"<p style='text-align:center;'>自动生成文档</p>\n\n"

    doc += f"<div style='background:#e3f2fd; padding:10px;'>本报告围绕「{topic}」展开分析</div>\n\n"

    for sec in sections:
        doc += f"### {sec}\n\n"
        doc += f"- 内容生成中...\n\n"

    doc += f"<div style='background:linear-gradient(145deg,#bbdefb,#b2dfdb); padding:10px;'>总结内容</div>\n\n"
    doc += f"<p style='text-align:center; color:#777;'>Document Engine · {date}</p>"

    return doc


if __name__ == "__main__":
    result = generate_document("测试主题")
    print(result)

## Q1 · 一般的OPENCLAW skill文件 有几个文件构成？（第 1 轮对话）

> **提问：** 一般的OPENCLAW skill文件 有几个文件构成？

一般来说，一个标准的**OpenClaw Skill**并不是单一文件，而是一个**小型模块目录**。根据目前主流实践（尤其是社区常用结构），一个 Skill 通常由**3～6个核心文件**组成，既能跑，又方便维护和复用。

我给你拆清楚👇

---

# 🧩 一、最基础（最小可用结构：3个文件） 这是“能用就行”的版本：

```
my-skill/
├── skill.md
├── config.yaml
└── run.py（或 run.js）
```

##### 1️⃣`skill.md`（核心灵魂）

👉 必须有

作用：

- 定义 Skill 的 能力说明 + Prompt

- Agent 调用时，最先读取这个

通常包含：

- YAML Frontmatter（元信息）

- 使用说明

- Prompt模板

---

##### 2️⃣`config.yaml`（配置文件）

👉 强烈建议有

作用：

- 定义参数、输入输出格式

- 控制 Skill 行为

比如：

```
name: market_research
inputs:
  - keyword
outputs:
  - report
```

---

##### 3️⃣`run.py / run.js`（执行逻辑）

👉 如果是“工具型 Skill”就必须有

作用：

- 真正执行任务（调用API / 爬数据 / 处理逻辑）

---

# 🚀 二、进阶结构（推荐：5~6个文件） 适合你要做“市场调研 / 行业分析”这种复杂 Skill 👇

```
my-skill/
├── skill.md
├── config.yaml
├── run.py
├── prompt.md
├── schema.json
└── README.md
```

---

##### 4️⃣`prompt.md`（提示词分离）

👉 推荐

作用：

- 把 Prompt 从 skill.md 拆出来

- 更好维护复杂逻辑

---

##### 5️⃣`schema.json`（结构定义）

👉 高级玩法

作用：

- 规范输入输出（类似接口文档）

- 方便多Agent协作

---

##### 6️⃣`README.md`（说明文档）

👉 团队协作必备

作用：

- 告诉别人怎么用这个 Skill

---

# 🧠 三、不同类型 Skill 的文件差异

##### 🟢 1. Prompt型 Skill（最简单）

👉 纯AI生成，不调用外部工具

```
skill.md
config.yaml（可选）
```

✔ 没有 run 文件 ✔ 本质就是“高级提示词”

---

##### 🔵 2. Tool型 Skill（你最需要）

👉 调API / 做数据分析 / 市场调研

```
skill.md
config.yaml
run.py
```

✔ 有执行逻辑 ✔ 可接数据库 / 爬虫 / GPT

---

##### 🟣 3. Workflow型 Skill（高级）

👉 多步骤任务（比如完整行业报告）

```
skill.md
config.yaml
run.py
prompt.md
schema.json
```

✔ 多阶段执行 ✔ 类似 mini-Agent

---

# 📊 四、一句话总结

👉 一个 OpenClaw Skill 本质是：

> **Prompt（skill.md） + 配置（config） + 执行逻辑（run）**

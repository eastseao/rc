## Q1 · openclaw的skill.md技能一般是什么格式的（第 1 轮对话）

> **提问：** openclaw的skill.md技能一般是什么格式的

在**entity["software","OpenClaw","game engine or tool context"]**（通常指开源版《entity["video_game","Captain Claw","classic platform game"]》的资源结构）里，`skill.md`这类文件一般不是程序强制规范的格式，而是**开发者/模组作者约定的“技能说明文档”**，本质就是 Markdown 文件，用来定义或描述技能逻辑、参数和效果。

不过从实际项目和常见模组习惯来看，它通常会遵循一种**“结构化 Markdown + 半配置化字段”**的写法，大致长这样👇

---

#### 一、常见`skill.md`基本结构

```
# Skill: Fireball

## 基本信息
- ID: skill_fireball
- 类型: 主动技能
- 冷却: 5s
- 消耗: 20 mana

## 技能描述
发射一枚火球，对敌人造成伤害并附带燃烧效果。

## 数值设定
- 基础伤害: 100
- 燃烧伤害: 10/s
- 持续时间: 3s

## 触发逻辑
- 按键: KEY_ATTACK
- 条件: mana >= 20

## 效果表现
- 动画: fireball_cast.anim
- 特效: fireball_effect.fx
- 音效: fireball.wav

## 脚本/逻辑（可选）
```

function onCast(player) spawnProjectile("fireball", player.position) end

```

```

---

#### 二、核心格式特点（重点）

##### 1️⃣ Markdown 外壳（人读）

- 用 # / ## 分区块

- 用列表写参数

- 方便策划 / 开发 / mod作者阅读

👉 本质是**文档 + 配置混合体**

---

##### 2️⃣ 关键字段“伪配置化”

虽然是`.md`，但里面会有类似：

- ID

- cooldown

- damage

- trigger

- effect

👉 这些字段有时会被脚本解析（取决于项目实现）

---

##### 3️⃣ 可嵌脚本（核心差异点）

很多项目会在`skill.md`里嵌：

- Lua

- JSON片段

- YAML风格字段

👉 用来驱动实际逻辑（不是纯说明）

---

##### 4️⃣ 强约定 > 强规范

不像`.json/.yaml`那么严格：

- 没有统一官方标准

- 完全取决于项目或团队约定

---

#### 三、进阶格式（更工程化写法）

有些项目会写成更“配置文件风格”👇

```
# Ice Blast

[meta]
id = skill_ice_blast
type = active

[cost]
mana = 30
cooldown = 8

[damage]
base = 120
freeze_chance = 0.3

[effect]
animation = ice_cast.anim
sound = ice.wav
```

👉 这种其实已经接近：

- .ini

- .toml

只是包了一层 Markdown

---

#### 四、本质总结（给你一句话理解）

`skill.md`≈ 👉**“给人看的技能说明 + 给程序读的轻量配置 + 可嵌逻辑脚本”**

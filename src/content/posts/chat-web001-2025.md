# 5️⃣ GitHub Actions 自动部署`.github/workflows/pages.yml`

```
name: GitHub Pages

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Ruby
        uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.2'
      - name: Install Jekyll
        run: gem install jekyll bundler
      - name: Build Site
        run: jekyll build
      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./_site
```

> ⚠ 注意：如果你网页端没有 main 分支，可以在网页端新建 main 分支，然后复制文件。

## Q6 · 上面进行的这些工作流都失败了。（第 6 轮对话）

> **提问：** 上面进行的这些工作流都失败了。

明白了，你遇到的问题很可能是**GitHub 网页端部署 Jekyll + Chirpy**时的常见坑。我们一步步分析原因并给出可行解决方案。

---

#### 1️⃣ 常见失败原因

1. 分支问题

- GitHub Pages 默认会在`main`或`master`分支上部署，如果 Actions 配置和实际分支不一致，会失败。 -**解决**：确保仓库有`main`分支（网页端可直接新建），并且 workflow 触发分支是`main`。

1. GitHub Actions Runner 环境问题

- 安装 Ruby、Jekyll 或主题依赖时，可能版本不匹配。 - Chirpy 需要至少**Ruby 2.7+**。

1. 主题未正确安装

- 在网页端无法直接`bundle install`安装主题 gem。 -**解决**：可以使用**remote theme**的方式，避免本地安装依赖。

1. 文件路径或命名错误

-`_config.yml`必须在仓库根目录 -`_posts`文件夹必须命名正确 - 主题必须使用`remote_theme: chirpythemes/chirpy@v6.0.0`（或者最新 tag）

1. GitHub Actions YAML 错误

- Actions 中直接用`jekyll build`，如果未安装依赖或使用`bundle exec jekyll build`可能失败 - 网页端创建 workflow 文件容易缩进/换行出错

---

#### 2️⃣ 推荐解决方案（零命令行可行）

由于你**只能网页端操作**，最稳妥的方式是：

##### 使用 Remote Theme + GitHub Pages 内建构建

1. 不使用 GitHub Actions

- 直接依赖**GitHub Pages 自带的 Jekyll 构建**- 在`_config.yml`中加入：

```
remote_theme: chirpythemes/chirpy@v6.0.0
plugins:
  - jekyll-feed
  - jekyll-sitemap
  - jekyll-seo-tag
```

1. 确保分支是 main

- 仓库设置 → Pages → Source → main branch / root

1. 创建必要文件 （网页端创建即可）

-`_config.yml`-`index.md`或`index.html`-`about.md`-`_posts/`文件夹 -`assets/`静态资源

1. 构建步骤

- 无需 workflow，GitHub Pages 会自动构建`_config.yml`配置和 remote theme

#### 3️⃣ 切换按钮 JS（`assets/js/theme-toggle.js`）

```
// 自动初始化主题（默认 light）
if(!localStorage.getItem("theme")) {
  localStorage.setItem("theme", "light-mode");
}
document.body.classList.add(localStorage.getItem("theme"));

// 切换按钮逻辑
const themeBtn = document.getElementById("theme-toggle");
themeBtn.addEventListener("click", () => {
  if(document.body.classList.contains("dark-mode")) {
    document.body.classList.remove("dark-mode");
    document.body.classList.add("light-mode");
    localStorage.setItem("theme", "light-mode");
  } else {
    document.body.classList.remove("light-mode");
    document.body.classList.add("dark-mode");
    localStorage.setItem("theme", "dark-mode");
  }
});
```

> ⚡ 优点：刷新页面后会记住用户选择的主题，存储在`localStorage`。

if(!localStorage.getItem("theme")) {
  localStorage.setItem("theme", "light-mode");
}
document.body.classList.add(localStorage.getItem("theme"));

const themeBtn = document.getElementById("theme-toggle");
themeBtn.addEventListener("click", () => {
  if(document.body.classList.contains("dark-mode")) {
    document.body.classList.remove("dark-mode");
    document.body.classList.add("light-mode");
    localStorage.setItem("theme", "light-mode");
  } else {
    document.body.classList.remove("light-mode");
    document.body.classList.add("dark-mode");
    localStorage.setItem("theme", "dark-mode");
  }
});

## Q16 · buildAction failed with "The process '/u…（第 16 轮对话）

> **提问：** build Action failed with "The process '/usr/bin/git' failed with exit code 128"

明白了，你现在遇到的错误是：

```
The process '/usr/bin/git' failed with exit code 128
```

这是**GitHub Actions 构建失败的常见 Git 错误**，与 Jekyll 或主题本身无关。下面分析原因和解决方案。

---

#### ❌ 错误原因

1. Git 操作权限问题

- Action 内部执行`git`命令（例如拉取远程主题、提交构建产物等）时，没有权限访问仓库或者 submodule。 - 常见场景： - 你在 workflow 里尝试`git push`，但是没有配置`GITHUB_TOKEN`- 使用 remote theme 时，Jekyll 需要临时 clone 远程主题，如果权限不够也可能报 128

1. 仓库状态异常

- 某些情况下，仓库存在未提交的文件或损坏的 Git 数据，也会导致 exit code 128。

1. Action 环境问题

- 有时 Actions 的`actions/checkout`配置不对，导致后续 git 操作失败。

---

#### ⚡ 解决方案

##### 1️⃣ 检查 workflow 配置（推荐）

如果你在使用自定义 GitHub Actions workflow 构建 Jekyll，确保：

```
- uses: actions/checkout@v3
  with:
    fetch-depth: 0   # 拉取完整仓库，便于构建 remote theme
```

- fetch-depth: 0 可以避免浅克隆导致 git 操作失败

---

##### 2️⃣ 确认 Git 权限

- 如果 workflow 里需要推送代码（例如更新 gh-pages 分支），确保：

```
env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

- 并在 git 命令里使用 HTTPS 方式：

```
git config user.name "github-actions[bot]"
git config user.email "github-actions[bot]@users.noreply.github.com"
```

---

##### 3️⃣ 简化构建流程（网页端推荐）

- 既然你之前希望 完全网页端操作 ：

1. 不使用 GitHub Actions 自动构建 2. 直接通过 GitHub Pages**Remote Theme +`_config.yml`+ Markdown 文件**构建 3. 这样就不会触发任何 git 操作，自然避免 exit code 128

> 本质上，你的博客完全可以**不依赖 Actions**，仅使用 GitHub Pages 的自带构建机制（网页端提交文件即可）。

---

##### 4️⃣ 如果你仍想使用 Actions

- 确认 workflow 文件里：

1. 使用`actions/checkout@v3`并`fetch-depth: 0`2. 配置`GITHUB_TOKEN`3. 避免在 Actions 里进行复杂的 git push 操作（网页端部署更简单）

---

💡**总结**：

- 错误 128 是 Git 权限或仓库问题，不是 Jekyll 或主题本身问题

- 对你当前场景（完全网页端部署）， 直接使用 GitHub Pages 构建即可 ，无需 Actions

- 如果坚持使用 Actions，需要检查 checkout 配置 + token 权限

##### `assets/js/theme-toggle.js`

```
if(!localStorage.getItem("theme")) {
  localStorage.setItem("theme", "light-mode");
}
document.body.classList.add(localStorage.getItem("theme"));

const themeBtn = document.getElementById("theme-toggle");
themeBtn.addEventListener("click", () => {
  if(document.body.classList.contains("dark-mode")) {
    document.body.classList.remove("dark-mode");
    document.body.classList.add("light-mode");
    localStorage.setItem("theme", "light-mode");
  } else {
    document.body.classList.remove("light-mode");
    document.body.classList.add("dark-mode");
    localStorage.setItem("theme", "dark-mode");
  }
});
```

## Q1 · 我想把导航栏的回顾页面成下拉：navbar-links: - [首页, /]（第 1 轮对话）

> **提问：** 我想把导航栏的回顾页面成下拉：navbar-links: - [首页, /] - [回顾, /archives/] - [更多, "#", about]

导航栏想把“回顾”从一个普通链接变成**下拉菜单**，那就需要把它写成 Beautiful Jekyll 支持的“扩展格式”，像你现在的“更多”一样。

你现在的写法是：

```
navbar-links:
  - [首页, /]
  - [回顾, /archives/]
  - [更多, "#", about]
```

要改成下拉，只要把“回顾”改成这种结构就行：

```
navbar-links:
  - [首页, /]

  # 回顾改成下拉菜单
  - 回顾:
      归档: "/archives/"
      时间线: "/timeline/"
      随便写个示例: "/something/"

  # 更多的下拉保持不变
  - 更多:
      关于我: "/about/"
      联系方式: "/contact/"
```

说明一下：

- 只要最外层写成 - 回顾: （注意不要方括号），Jekyll 就会自动识别为下拉菜单。

- 冒号下面的键值对就是下拉菜单项的“名称: 链接”。

- 如果你的“回顾”当前只有一个页面，也可以只放一个：

```
  - 回顾:
      全部文章: "/archives/"
```

你的导航栏就会出现一个带下拉的小箭头，点开才能看到“回顾”里的子项。

如果你想继续扩展，比如给“回顾”做更漂亮的结构，或加入年份分组，都可以继续玩下去。

## Q2 · 更多的里面有：兴趣、随手拍、驻足点、和关于我（第 2 轮对话）

> **提问：** 更多的里面有：兴趣、随手拍、驻足点、和关于我

那就给“更多”补齐你想要的四个子项，同时把“回顾”改成下拉。整段写成这样最干净也最兼容 Beautiful Jekyll 的格式：

```
navbar-links:
  - [首页, /]

  # 回顾下拉菜单
  - 回顾:
      全部文章: "/archives/"

  # 更多下拉菜单
  - 更多:
      兴趣: "/interests/"
      随手拍: "/photos/"
      驻足点: "/stops/"
      关于我: "/about/"
```

逻辑很简单： 写成`- 更多:`就是“下拉菜单”，下面的每个键值对都是子页面。

路径你可以按自己的实际页面文件来定，只要保持格式`/xxx/`即可，Jekyll 会自动映射。

等你把页面也整齐放好之后，整个导航栏会显得很像一本小百科目录。有时间可以再一起玩下导航的图标美化或者 hover 效果，细节做起来挺有趣的。

## Q3 · 这种方式不对，要采用这样的格式： - [更多, "", about]（第 3 轮对话）

> **提问：** 这种方式不对，要采用这样的格式： - [更多, "#", about]

好——你想保留数组简写（像`- [更多, "#", about]`）的形式，同时让第三个元素作为“下拉菜单的 ID”去拉取子项。下面给出**完整可用方案**（不改你当前的数组风格），包括：

1. _config.yml 中的导航（保持你想要的数组简写），

1. 一个单独的数据文件 /_data/navbar-dropdowns.yml 来定义每个下拉 ID 对应的子项，

1. 以及一个 Liquid 模板片段（可粘到 _includes/header.html 里替换原来渲染导航的那段），负责检测第三个数组元素并渲染下拉菜单。

把下面三部分照着放好就能按你要求工作。

---

##### 1)`_config.yml`（导航部分 — 保持数组形式）

```
navbar-links:
  - [首页, /]
  - [回顾, /archives/, archives]
  - [更多, "#", more]
```

说明：第三个元素是我们约定的下拉`id`（比如`archives`、`more`），会去`site.data.navbar_dropdowns`里查对应项。

---

##### 2) 新建数据文件：`_data/navbar-dropdowns.yml`

```
archives:
  全部文章: "/archives/"
  时间线: "/timeline/"

more:
  兴趣: "/interests/"
  随手拍: "/photos/"
  驻足点: "/stops/"
  关于我: "/about/"
```

说明：键名（`archives`/`more`）要与`_config.yml`中数组第三个元素一致。每个键值对格式为`显示文字: 链接`。

---

##### 3) 在`_includes/header.html`（或主题中负责渲染导航的文件）替换或插入下面的渲染循环

> 注意：不同版本的 Beautiful Jekyll header 结构不尽相同，这段代码是通用 Liquid 实现，按你当前文件里渲染导航的地方替换原有循环即可（保留原有的样式类/结构或把类名改回你主题使用的类）。

```html
{%- comment -%}
  渲染 navbar-links，支持三种形式：
  1) 映射形式（例如 - 回顾: ...） - 可按主题原有逻辑处理
  2) 数组两项 [label, url]
  3) 数组三项 [label, url, id] -> 从 site.data.navbar_dropdowns[id] 读取下拉项
{%- endcomment -%}

<ul class="navbar-nav ml-auto">
  {%- for item in site.navbar-links -%}
    {%- if item == nil -%}
      {%- continue -%}
    {%- endif -%}

    {%- if item.size == 3 -%}
      {%- assign label = item[0] -%}
      {%- assign url = item[1] -%}
      {%- assign id = item[2] -%}
      {%- assign dropdown = site.data.navbar_dropdowns[id] -%}

      {%- if dropdown -%}
        <li class="nav-item dropdown">
          <a class="nav-link dropdown-toggle" href="{{ url }}" id="nav-{{ id }}" role="button" data-toggle="dropdown" aria-haspopup="true" aria-expanded="false">
            {{ label }}
          </a>
          <div class="dropdown-menu" aria-labelledby="nav-{{ id }}">
            {%- for text, link in dropdown -%}
              <a class="dropdown-item" href="{{ link | relative_url }}">{{ text }}</a>
            {%- endfor -%}
          </div>
        </li>
      {%- else -%}
        <!-- 如果没有找到对应 data，则作为普通链接渲染 -->
        <li class="nav-item"><a class="nav-link" href="{{ url | relative_url }}">{{ label }}</a></li>
      {%- endif -%}

    {%- elsif item.size == 2 -%}
      {%- assign label = item[0] -%}
      {%- assign url = item[1] -%}
      <li class="nav-item"><a class="nav-link" href="{{ url | relative_url }}">{{ label }}</a></li>

    {%- else -%}
      {%- comment -%}
        其它可能的格式（例如 mapping: - 回顾: ...），按你原来主题逻辑处理或扩展。
      {%- endcomment -%}
    {%- endif -%}
  {%- endfor -%}
</ul>
```

---

##### 额外说明与注意事项（简洁）

- site.data.navbar_dropdowns 来自 _data/navbar-dropdowns.yml ，Jekyll 会自动加载。

- 如果你的主题已经在 header.html 中用 Bootstrap 的类名（如 dropdown 、 dropdown-menu 等），上面的 HTML 结构即可直接工作；如果主题用了不同的 CSS 类，保留上面逻辑但把类名换回你主题里的类（比如 nav-item 、 nav-link 之类）。

- 如果你不想改 header 源码，也可以把上面的逻辑“拼接”成你当前循环里可复用的条件分支（即只需把判断与下拉输出插入现有渲染循环中）。

- 本方案向后兼容：如果数组第三项指向一个不存在的 ID，会退回成普通链接显示（不会报错）。

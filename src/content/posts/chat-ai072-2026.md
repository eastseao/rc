## Q1 · 给我全方位深度的介绍下目前agent里的skill的具体含义（第 1 轮对话）

> **提问：** 给我全方位深度的介绍下目前agent里的skill的具体含义

可以。这个问题其实非常关键——**Skill 是目前 Agent 从“会聊天的模型”走向“可复用的专业工作者”的核心抽象之一。**

尤其结合你之前一直在做的**Agent / SKILL / OPC / Workflow / Runtime / Memory**体系，我建议不要把 Skill 简单理解成“一个 Prompt 文件”。更准确的理解是：

> **Skill = 可被 Agent 动态发现、按需加载并执行的一套“程序化专业能力”。**

截至 2026 年，Agent Skills 已经从早期的 Claude 生态扩展成一个跨 Agent 的开放标准；Claude、Codex 等都在采用这种思路。Anthropic 将其定义为由`SKILL.md`、指令、脚本和资源组成的可组合能力单元；OpenAI 也明确把 Skills 用于扩展 Codex 的信息处理、问题解决、写作以及实际计算机工作能力。citeturn0search3turn0search11

下面我从**概念 → 原理 → 架构 → 生命周期 → 与 Prompt/Tool/MCP/Agent/Workflow/Memory 的区别 → Skill 如何真正产生“能力” → 如何设计企业级 Skill 系统**，完整拆开。

# 一、先给你一个最重要的结论

如果把一个 Agent 比喻成一个“人”，那么：

| Agent组件 | 类比人 |
|---|---|
| LLM | 大脑 |
| System Prompt | 基本行为准则 |
| Context | 当前工作记忆 |
| Memory | 长期记忆 |
| Tool | 手和工具 |
| MCP | 工具连接协议 |
| **Skill** | **专业技能 + SOP + 工作方法** |
| Workflow | 工作流程 |
| Agent | 一个能够自主工作的员工 |
| Multi-Agent | 一个组织 |
| Runtime | 工作环境 |
| Evaluation | 绩效考核 |
| Learning | 培训 |
| Policy | 公司制度 |

所以：

> **Skill 不是 Agent。Skill 是 Agent 所拥有的“可调用专业能力”。**

例如：

```
Agent：市场营销经理

Skills：
├── 市场调研 Skill
├── 竞品分析 Skill
├── 用户画像 Skill
├── 产品定位 Skill
├── 包装文案 Skill
├── 小红书内容 Skill
├── SEO Skill
└── GEO Skill
```

Agent 不需要每次都重新学习这些东西。

它只需要：

> **发现 → 判断相关性 → 加载 → 执行 → 验证**

# 二、Skill 到底是什么？

目前主流 Agent Skills 的基本形式是：

```
skill-name/
│
├── SKILL.md
│
├── scripts/
│   ├── xxx.py
│   └── xxx.sh
│
├── references/
│   ├── guide.md
│   ├── rules.md
│   └── examples.md
│
└── assets/
    ├── template.docx
    ├── template.xlsx
    └── images/
```

其中：

```
SKILL.md
```

是核心入口。

官方架构的关键思想是**Progressive Disclosure（渐进式披露）**：

##### Level 1：Metadata

Agent 一开始只知道：

```
---
name: market-research
description: >
  Conduct structured market research, competitor analysis,
  trend analysis and evidence-based market reports.
---
```

也就是：

> “我有什么技能？”

而不是把整个 Skill 全部塞进上下文。

---

##### Level 2：Instructions

真正需要使用时，才加载：

```
# Market Research

## Objective

Conduct evidence-based market research.

## Process

1. Define research question
2. Identify market scope
3. Search primary sources
4. Search secondary sources
5. Cross-check evidence
6. Analyze
7. Produce report
```

也就是：

> “这个技能怎么做？”

---

##### Level 3：Resources

如果还需要更深的信息，再读取：

```
references/
```

例如：

```
references/
├── research-methodology.md
├── source-evaluation.md
├── competitor-framework.md
└── report-template.md
```

---

##### Level 4：Executable Capability

如果需要程序：

```
scripts/
├── scrape.py
├── analyze.py
├── generate_chart.py
└── validate.py
```

Agent 可以调用这些程序。

所以一个 Skill 本质上可以是：

```
Knowledge
+
Instructions
+
Procedures
+
Tools
+
Code
+
Resources
+
Templates
```

Anthropic 官方也明确把 Skill 描述为包含**instructions、scripts、resources**的文件夹，并通过渐进式披露减少上下文负担。citeturn0search3turn0search8

# 三、为什么 Skill 会出现？

这是理解 Skill 最重要的一层。

以前 Agent 通常是：

```
User
 ↓
Prompt
 ↓
LLM
 ↓
Answer
```

例如你告诉模型：

> “帮我做一次竞品分析。”

模型只能：

```
凭已有知识
+
你的Prompt
+
当前Context
```

进行工作。

问题是：

##### 问题1：重复

你每次都要告诉它：

```
第一步做什么
第二步做什么
第三步做什么
哪些网站可信
如何判断数据
报告怎么写
```

---

##### 问题2：不稳定

今天：

```
Agent A → 竞品分析方式A
```

明天：

```
Agent A → 竞品分析方式B
```

换模型：

```
Agent B → 竞品分析方式C
```

---

##### 问题3：上下文浪费

如果你把所有 SOP 全塞进 System Prompt：

```
100 个技能
×
每个 5000 tokens
=
巨大 Context
```

绝大多数任务根本用不到。

---

##### Skill 的解决方式

变成：

```
                 ┌── Skill A
                 ├── Skill B
Agent ───────────┼── Skill C
                 ├── Skill D
                 └── Skill E
                      ↓
                按需加载
```

所以 Skill 的核心不是：

> “增加 Prompt。”

而是：

> **把 Agent 的专业知识和程序化工作方法模块化。**

---

# 四、Skill 和 Prompt 最大的区别

这是很多人最容易搞混的地方。

#### Prompt

Prompt 更像：

> “告诉模型这一次应该怎么做。”

例如：

```
你是一名专业市场分析师。

请分析以下产品：
xxx

要求：
1. 分析市场规模
2. 分析竞品
3. 分析消费者
4. 给出策略
```

一次性的。

---

#### Skill

Skill 是：

> “把这个工作方法永久封装成可复用能力。”

例如：

```
market-research/
└── SKILL.md
```

里面规定：

```
任何市场研究任务：

1. 定义研究问题
2. 定义市场边界
3. 优先寻找一手资料
4. 对数据进行交叉验证
5. 区分事实/推断/观点
6. 建立竞争格局
7. 建立消费者画像
8. 输出结论
9. 给出战略建议
```

以后：

```
“帮我研究虫草市场”
```

Agent 就可以自动调用这个 Skill。

所以：

> **Prompt 是指令。** **Skill 是能力封装。**

---

# 五、Skill 和 Tool 完全不是一个东西

这是第二个非常关键的区别。

假设 Agent 要做市场调研。

它需要：

```
Skill
↓
告诉它怎么研究
```

然后：

```
Tool
↓
让它能够搜索
```

例如：

```
Market Research Skill
        │
        ├── 搜索网页
        ├── 查询数据库
        ├── 读取PDF
        ├── 分析Excel
        └── 生成报告
```

这里：

```
Skill = 怎么做

Tool = 用什么做
```

举个非常直观的例子：

> **Excel 是工具。** **财务分析是技能。**

Agent 有 Excel 工具，不代表它会做专业财务分析。

反过来：

Agent 有财务分析 Skill，但没有 Excel / Python / 数据库工具，也无法处理大型数据。

所以：

```
Skill + Tool
       ↓
真正可执行能力
```

# 六、Skill 和 MCP 又是什么关系？

这个关系非常重要。

可以把 MCP 理解成：

> **“连接工具和外部世界的标准接口。”**

例如：

```
Agent
 │
 ├── MCP → GitHub
 ├── MCP → Notion
 ├── MCP → Google Drive
 ├── MCP → 数据库
 └── MCP → CRM
```

而 Skill 是：

```
Agent
 │
 └── Skill
       ↓
     如何使用这些工具完成任务
```

因此：

```
MCP = 能不能接上

Skill = 接上以后怎么干活
```

官方文档也明确区分：

> MCP 提供外部服务和数据访问；Skill 提供完成任务所需要的程序性知识，两者可以组合使用。citeturn0search1

# 七、Skill 和 Workflow 的区别

这个更加高级。

##### Skill

解决：

> **“怎么做一类事情？”**

例如：

```
SEO Skill
```

里面可能包含：

```
关键词研究
搜索意图分析
内容结构设计
内链策略
SERP分析
E-E-A-T检查
```

---

##### Workflow

解决：

> **“这几个事情按照什么顺序完成？”**

例如：

```
产品上市 Workflow

市场调研
 ↓
消费者分析
 ↓
竞品分析
 ↓
产品定位
 ↓
包装策略
 ↓
内容营销
 ↓
渠道投放
 ↓
复盘
```

Workflow 可以调用多个 Skill：

```
Workflow
│
├── Market Research Skill
├── Consumer Insight Skill
├── Product Positioning Skill
├── Packaging Skill
├── SEO Skill
└── Marketing Skill
```

因此：

> **Skill 是能力模块。** **Workflow 是能力编排。**

# 九、Skill 最核心的创新：Progressive Disclosure

这是整个 Skill 架构里我认为最重要的设计。

传统 Agent：

```
启动
 ↓
加载所有知识
 ↓
巨大Context
 ↓
开始工作
```

Skill：

```
启动
 ↓
只加载 Skill 名称 + 描述
 ↓
识别任务
 ↓
发现相关 Skill
 ↓
加载 SKILL.md
 ↓
发现需要的 reference
 ↓
读取 reference
 ↓
发现需要的 script
 ↓
执行 script
```

可以画成：

```
                 Agent
                   │
          ┌────────┴────────┐
          ↓                 ↓
      Skill Index        User Task
          │                 │
          └────────┬────────┘
                   ↓
             Skill Matching
                   ↓
            Load SKILL.md
                   ↓
             Load References
                   ↓
              Run Scripts
                   ↓
             Execute Task
```

Anthropic 把它明确设计成多层加载：Metadata → Instructions → Resources/Code。citeturn0search3turn0search9

这意味着：

> **Skill 本质上也是一种 Context Engineering 架构。**

```
隐性经验

显性化
↓
结构化
↓
程序化
↓

```

这实际上就是：

#**Knowledge → Procedure → Capability**

也就是：


# 十一、所以 Skill 本质上是什么？

如果我要给一个更严格的技术定义：

> **Agent Skill 是一种可发现、可加载、可组合、可执行的程序性知识封装（Procedural Knowledge Package），用于将特定领域的知识、工作方法、操作规范、资源和工具调用方式转化为 Agent 可以按需调用的能力模块。**

关键词是：

##### 1. Discoverable

能够被 Agent 发现。

##### 2. Loadable

需要的时候加载。

##### 3. Composable

多个 Skill 可以组合。

##### 4. Executable

可以真正执行。

##### 5. Reusable

不同任务反复使用。

##### 6. Portable

跨 Agent / 平台复用。

目前 Agent Skills 已经被明确作为开放标准发展，而不是某一家 Agent 的私有 Prompt 格式。citeturn0search1turn0search4

```
Skill
│
├── 1. Identity
│      ├── name
│      └── description
│
├── 2. Intent
│      ├── When to use
│      └── When NOT to use
│
├── 3. Knowledge
│      ├── concepts
│      ├── rules
│      └── domain knowledge
│
├── 4. Procedure
│      ├── workflow
│      ├── steps
│      └── decision rules
│
├── 5. Resources
│      ├── references
│      ├── templates
│      └── examples
│
├── 6. Execution
│      ├── scripts
│      ├── tools
│      └── APIs
│
└── 7. Validation
       ├── quality checks
       ├── constraints
       └── evaluation
```

官方最基本的 Skill 规范要求`SKILL.md`至少包含`name`和`description`；复杂 Skill 则可以继续向下引用资源和代码。citeturn0search8

# 十三、一个真实 Skill 示例

比如我们做一个：

```
consumer-research
```

目录：

```
consumer-research/
│
├── SKILL.md
│
├── references/
│   ├── consumer-analysis.md
│   ├── persona-framework.md
│   ├── interview-method.md
│   └── evidence-rules.md
│
├── scripts/
│   ├── clean_data.py
│   └── analyze_survey.py
│
└── assets/
    └── consumer-report-template.md
```

---

#### SKILL.md

可以是：

```
---
name: consumer-research
description: >
  Conduct structured consumer research, consumer segmentation,
  persona construction, demand analysis and insight extraction.
  Use when analyzing customers, consumer needs, surveys,
  interviews, reviews or market demand.
---
```

然后：

```
# Consumer Research

## Objective

Transform raw consumer information into evidence-based
consumer insights.

## Workflow

1. Define research question.
2. Identify target consumer.
3. Collect evidence.
4. Separate facts from assumptions.
5. Segment consumers.
6. Identify needs and pain points.
7. Extract behavioral patterns.
8. Build consumer personas.
9. Generate actionable insights.

## Rules

- Do not treat assumptions as facts.
- Distinguish quantitative and qualitative evidence.
- Prioritize primary evidence.
- Explicitly identify uncertainty.
- Do not fabricate consumer data.

## Resources

For segmentation:
read references/persona-framework.md

For evidence evaluation:
read references/evidence-rules.md

For survey analysis:
use scripts/analyze_survey.py
```

这就已经不是普通 Prompt 了。

它已经开始成为：

> **一个可以复用的“消费者研究能力模块”。**

# 十七、Skill 还有一个非常重要的属性：边界

好的 Skill 一定不是：

> “什么都能做。”

而是：

> **定义清晰的能力边界。**

例如：

```
SEO Skill
```

应该明确：

##### 能做

```
关键词研究
搜索意图
内容结构
SEO审查
内链建议
```

##### 不负责

```
广告投放
品牌战略
视觉设计
销售管理
```

为什么？

因为 Skill 越大：

```
Skill范围 ↑
↓
触发边界模糊
↓
上下文增加
↓
执行不稳定
```

所以：

> **Skill 应该像“一个专业岗位能力”，而不是“万能助手”。**

# 十八、Skill ≠ 知识库

这个区别也非常重要。

##### Knowledge Base

回答：

> “知道什么？”

例如：

```
公司产品资料
历史销售数据
行业报告
品牌资料
```

---

##### Skill

回答：

> “知道怎么做什么？”

例如：

```
如何分析销售数据
如何研究市场
如何写品牌策略
如何进行供应商评估
```

所以：

```
Knowledge = What

Skill = How
```

这也是为什么 Skill 特别适合：

> **把一个人的工作经验“数字化”。**

# 十九、这和你之前问的“蒸馏”其实高度相关

你之前问过：

> 能不能把一本书、一个人的语言思维风格、一个好用的技能进行蒸馏？

现在可以把这件事情进一步抽象。

例如一个专家：

```
专家
│
├── 知识
├── 判断
├── 方法
├── SOP
├── 经验
```

# 六、第三层：Skill Contract

这是我认为很多现有 Skill 最缺失的一层。

Skill 不应该只是：

> “请按照以下方法做。”

而应该有：

```
Input
↓
Processing
↓
Output
```

也就是：

# Skill Contract

例如：

```
input:
  type: object
  required:
    - product
    - market

output:
  type: object
  required:
    - competitors
    - positioning
    - opportunities
```

例如：

```json
{
  "product": "有机黑枸杞饮料",
  "market": "中国",
  "objective": "寻找高端市场机会"
}
```

输出：

```json
{
  "competitors": [],
  "market_structure": {},
  "positioning": {},
  "opportunities": []
}
```

这一步非常关键。

因为：

> **没有 Schema 的 Skill，本质上还是自然语言 Prompt。**

有了 Schema：

> **Skill 开始成为机器可组合的 Capability。**

# 七、第四层：Knowledge

```

```

```
├── industry-rules.md
├── standards.md
└── examples.md
```

但这里有一个重要原则：

##### 不要把所有知识塞进 SKILL.md。

应该：

```
SKILL.md
    ↓
告诉 Agent
“如果需要X，请读取 references/X”
```

例如：

```

For consumer segmentation:
read references/segmentation.md

read references/evidence-rules.md
```

这样才能做到：

```
需要什么
↓

```

而不是：

```
所有知识
↓
全部加载
```

因为专家真正值钱的地方往往不是：

> **Decision Skill**

## Q3 · 如何制作一个适合自己的skill？（第 3 轮对话）

> **提问：** 如何制作一个适合自己的skill？

可以。其实**“适合自己的 Skill”不是从写 Prompt 开始，而是从提炼你自己的工作方法开始**。

结合你之前一直在做的 Agent、Skill、知识库和 OPC 体系，我建议你把 Skill 理解成：

> **把一个人稳定、可复用、可验证的做事方法，压缩成 AI 可以调用的一套能力。**

最重要的不是“写得多”，而是**把你的经验变成规则、流程和判断标准**。

---

# 一、先理解：什么才叫“自己的 Skill”

一个普通 Prompt：

> 帮我做一个产品包装方案。

一个普通 Skill：

> 当用户需要产品包装方案时，按照产品定位 → 人群 → 卖点 → 信息层级 → 包装结构 → 文案 → 视觉方向 → 验证的流程完成。

而一个真正**适合你自己的 Skill**，应该进一步加入：

> **“我通常是怎么判断的？”**

例如你做包装工作时，可能已经形成了很多隐性的判断：

- 消费者第一眼应该看到什么？

- 哪些信息不能放正面？

- 什么卖点消费者真正听得懂？

- 高端产品为什么不能堆砌“高科技”？

- 食品包装上的专业术语应该如何转成消费者语言？

- 产品名称、核心卖点、产地、工艺之间如何排序？

- 什么情况下应该突出原料？

- 什么情况下应该突出功效场景？

- 什么情况下应该砍掉 50% 的文字？

这些东西才是**你的 Skill 核心资产**。

---

# 二、制作自己的 Skill，我建议采用 7 步法

可以把整个过程压缩成：

```
经验
 ↓
任务
 ↓
方法
 ↓
规则
 ↓
流程
 ↓
案例
 ↓
Skill
```

具体如下。

---

#### ① 找一个“高频重复任务”

不要一上来做：

> “我的营销 Skill”

太大。

应该从一个具体任务开始。

例如：

```
产品包装文案优化
```

或者：

```
食品包装卖点提炼
```

或者：

```
竞品包装分析
```

或者：

```
采购方案比价
```

或者：

```
Markdown 文档结构化
```

或者：

```
把复杂专业资料整理成消费者语言
```

##### 一个好 Skill 通常满足三个条件

| 条件 | 说明 |
|---|---|
| 高频 | 你经常做 |
| 重复 | 每次都有类似过程 |
| 有经验壁垒 | 你比普通人判断得更好 |

尤其是：

> **你已经做过 50 次，但每次还要重新告诉 AI 怎么做。**

这种任务最值得 Skill 化。

---

# 三、② 把“你脑子里的方法”挖出来

这是制作个人 Skill 最关键的一步。

不要问：

> “这个 Skill 应该写什么？”

应该问：

> **“如果让我手把手教一个新人，我会怎么教？”**

比如你要做一个：

**「消费者语言包装文案 Skill」**

你可以把自己的思维拆成：

```
输入产品资料
     ↓
判断产品是什么
     ↓
判断消费者是谁
     ↓
找消费者真正关心的问题
     ↓
提炼产品事实
     ↓
区分事实 / 卖点 / 利益
     ↓
把专业语言翻译成消费者语言
     ↓
建立包装信息层级
     ↓
生成正面核心文案
     ↓
生成辅助信息
     ↓
检查是否夸大
     ↓
输出方案
```

这已经开始从：

**“Prompt”**

变成：

**“Skill”**。

---

# 四、③ 把经验变成“判断规则”

这是 Skill 与普通 Prompt 最大的区别。

例如普通 Prompt：

> 请使用消费者语言。

太模糊。

你的个人 Skill 可以变成：

```
RULE-01
如果一个卖点需要专业知识才能理解，
优先转换成消费者可以直接理解的结果语言。

RULE-02
如果一个技术名词无法回答“对消费者有什么意义”，
则不得作为核心卖点。

RULE-03
包装正面优先表达：
产品是什么 + 核心价值 + 为什么值得购买。

RULE-04
一个包装正面原则上只保留一个第一核心卖点。

RULE-05
不得为了“显得高级”堆砌：
科技、臻选、匠心、赋能、矩阵等空泛词汇。
```

这就非常重要了。

因为：

> **Skill 的价值 ≠ 它知道什么，而是它知道“什么时候应该怎么判断”。**

---

# 五、④ 把 Skill 分成 5 个核心部分

如果你是给自己长期使用，我建议不要把所有东西都塞进`SKILL.md`。

可以采用这个结构：

```
my-packaging-skill/
│
├── SKILL.md
│
├── rules/
│   ├── positioning.md
│   ├── consumer-language.md
│   ├── information-hierarchy.md
│   └── compliance.md
│
├── workflow/
│   └── workflow.md
│
├── examples/
│   ├── good.md
│   └── bad.md
│
├── templates/
│   └── packaging-output.md
│
└── evaluation/
    └── evaluation.md
```

核心逻辑是：

```
SKILL.md
   │
   ├── 我是谁 / 做什么
   │
   ├── 什么情况下使用
   │
   ├── 怎么做
   │
   ├── 怎么判断
   │
   └── 去哪里读取详细知识
        │
        ├── Rules
        ├── Workflow
        ├── Examples
        ├── Templates
        └── Evaluation
```

这也符合现在 Agent Skills 的一个重要设计方向：**渐进式加载，而不是一开始把所有知识塞进上下文。**

---

# 六、⑤ 给 Skill 一个明确的“输入 → 输出契约”

这是很多人制作 Skill 时容易忽略的。

比如：

##### 输入

```
product:
  name: 有机五黑饮
  category: 植物饮品

ingredients:
  - 黑枸杞
  - 黑桑葚
  - 黑加仑
  - 黑莓
  - 黑豆

target_user:
  - 关注健康的人群

positioning:
  - 高花青素
  - 有机
```

Skill 不应该只是“自由发挥”。

而应该规定：

```
输入
↓
产品事实整理
↓
消费者需求分析
↓
核心价值提炼
↓
卖点优先级排序
↓
包装信息架构
↓
正面文案
↓
背面文案
↓
风险检查
↓
最终方案
```

最终输出也应该固定。

例如：

```
output:
  positioning:
  core_benefit:
  key_selling_points:
  front_panel:
  back_panel:
  visual_direction:
  compliance_risk:
  recommendations:
```

这样以后你的 Agent 才能稳定调用它。

---

# 七、⑥ 用你过去做过的“真实案例”训练 Skill

这一点对你尤其重要。

你过去已经做过大量类似：

- 产品命名

- 包装文案

- 五黑饮

- 黑枸杞

- 冬虫夏草

- 茶油

- 松茸

- 食品/健康产品

- 消费者语言转换

这些实际上就是非常好的**Skill Dataset**。

不要只保存最终答案。

最好保存：

```
原始需求
↓
原始资料
↓
第一次方案
↓
哪里不好
↓
为什么不好
↓
如何修改
↓
最终方案
↓
为什么最终方案更好
```

例如：

```
案例：
“高活性花青素矩阵”

问题：
专业感强，但消费者不知道是什么意思。

修改：
“5种天然高花青素黑色果实”

进一步修改：
“5种天然黑色果实，富含花青素”

最终：
根据包装位置决定使用哪一种表达。
```

这时候 AI 学到的就不只是：

> “某句话怎么写。”

而是：

> **“什么情况下应该这么写。”**

这才是个人 Skill。

---

# 八、⑦ 最后一定要加入“自我评价标准”

这是从普通 Skill 走向**生产级 Skill**的关键。

例如你的包装文案 Skill，可以规定：

```
每次输出后必须检查：

① 消费者是否一眼理解？
② 是否明确产品是什么？
③ 是否只有一个第一核心卖点？
④ 是否存在专业术语堆砌？
⑤ 是否存在空泛营销词？
⑥ 是否存在重复表达？
⑦ 是否存在夸大宣传？
⑧ 是否符合产品真实事实？
⑨ 是否适合包装实际面积？
⑩ 是否具有购买理由？
```

然后让 AI 自己评分：

```
消费者理解度：9/10
卖点聚焦度：8/10
差异化：7/10
可信度：9/10
包装适配度：8/10

综合：8.2/10
```

这时候 Skill 就开始具有：

> **执行 → 检查 → 修正**

的闭环。

> “我知道什么。”

> **“我会怎么做。”**

而你的个人 Skill 最有价值的部分其实是：

> **“我为什么这么做，而不是那么做。”**

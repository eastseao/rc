## Q1 · 我要设计一个用来编写windows桌面应用软件的Agent，请给我提供这个age…（第 1 轮对话）

> **提问：** 我要设计一个用来编写windows桌面应用软件的Agent，请给我提供这个agent的全套文件

完全可以，而且我建议不要只做一个普通的「Windows开发助手」，而是设计成一个**生产级 Windows Desktop Software Architect Agent**。

这个Agent的定位应该不是"帮你写代码"，而是**能够独立完成一款Windows桌面软件从需求→架构→UI→数据库→代码→测试→打包→发布的完整开发流程。**

#### 🚀 推荐升级为「Windows Desktop Studio Agent」

如果目标是打造一个长期使用、具备企业级开发能力的Agent，我建议进一步扩展为一个约**80~120 个文件**、覆盖完整软件工程生命周期的专业开发体系，而不仅仅是几个基础配置文件。

第二版（Studio版）可以增加：

- 🧠 Memory Layer ：项目上下文、编码规范、历史决策、技术债务记录。

- 🏗️ Architecture Library ：MVVM、Clean Architecture、插件化、DDD、微内核等多套可选架构模板。

- 🧩 UI Component Library ：常用窗口、对话框、数据表格、图表、设置页等组件模板。

- ⚙️ Code Generator ：自动生成 ViewModel、Repository、Service、DTO、配置文件等样板代码。

- 🔍 Quality Layer ：静态检查、安全检查、性能分析、单元测试、UI 自动化测试。

- 📦 Release Layer ：MSIX、WiX、Inno Setup、自动更新、数字签名、CI/CD 流程。

- 🤖 AI Integration Layer ：支持接入大模型、本地模型、MCP、RAG、OCR、语音识别等现代 AI 能力。

这样，这个 Agent 的能力将更接近一位资深 Windows 首席架构师，能够持续负责从产品规划到交付维护的整个研发过程，而不仅仅是代码生成。

# 🌟 我建议增加一个第九个核心文件（强烈推荐）

实际上，企业级 Agent 最关键的不是`style.md`，而是一个**`decision-engine.md`**。

它定义 Agent 在面对多个技术方案时如何决策，例如：

- 框架选择 ：WinUI、WPF、Avalonia、MAUI、Qt、Electron 在什么场景下优先使用。

- 数据库选择 ：SQLite、SQL Server、PostgreSQL、MySQL 的适用条件。

- ORM 选择 ：EF Core、Dapper、原生 ADO.NET 的权衡标准。

- 架构选择 ：三层架构、Clean Architecture、DDD、插件化架构的决策规则。

- 性能优先还是开发效率优先 ：在不同项目规模下的默认策略。

- AI 集成方案 ：本地模型、云端 API、RAG、MCP 等的选择逻辑。

这样 Agent 不只是“知道很多”，而是拥有**一致且可解释的工程决策能力**。

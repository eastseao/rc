## 01 · 三种建站路径，先选方向再动手（00142 / 00159）

源笔记把「个人网站怎么建」归成三条路：**可视化平台**、**静态站点生成器**、**自托管**。对新手最友好的是静态生成器里的 Jekyll——它与 GitHub Pages 原生集成，连本地环境都可以不装，直接在网页上写 Markdown 就出页面。

| 路径 | 代表工具 | 适合谁 / 代价 |
|---|---|---|
| **可视化平台** | WordPress、Wix、各类建站 SaaS | 拖拽即用，最快上线；但受制于平台模板与计费，自由度低，数据不在自己手里。 |
| **静态站点生成器** | Jekyll（Ruby）、Hugo、Hexo（Node.js） | 把 Markdown 编译成静态 HTML，托管在 GitHub Pages 免费；Jekyll 与 Pages 原生集成，Hexo 需本地装 Node 并命令行部署。 |
| **自托管** | 自己租服务器、装 Nginx/Node | 自由度最高，要管运维、域名、备案；对纯静态个人主页属于杀鸡用牛刀。 |

> **源笔记结论**：新手强烈推荐 Jekyll 路线——仓库建好、Pages 一开、写`index.md`或`index.html`就能上线；主题在`_config.yml`里改`theme`一行即可切换，NexT、码志等简约主题社区常用。

## 02 · 新账号到上线：GitHub Pages 起步五步（00159 / 00142）

注册完 GitHub 账号，核心只有两步硬规则：**仓库名必须叫`<你的用户名>.github.io`**、仓库设为**Public**。其余都是在这之上填内容、开 Pages。

##### 排错 · HTML-Proofer 报 JS 文件不存在

Build failed：theme.min.js / page.min.js 等 internal script reference does not exist

源笔记实战：用 blog 仓库存 Chirpy 模板后，GitHub Actions 跑 HTML-Proofer 时一次性报 113 个失败，全是`/assets/js/dist/*.min.js does not exist`。根因是 Chirpy 依赖特定构建步骤生成这些压缩 JS，远程直接 Fork/模板出的仓库可能缺`assets/js`、`tools`等关键目录。解决：核对仓库目录结构是否完整；本地补`bundle install`+`npm install`后`bundle exec jekyll b`；临时可在工作流里注释掉 htmlproofer 步骤或加`--disable-external`；并复查 baseurl 是否设为 /blog。

## 05 · Markdown 个人网页的演进与文章推送（00160）

00160 是一个 md 个人网页从「能看」到「好用」的连续迭代：先把浮动导航改成左侧边栏，再把文章列表改成卡片表格，最后落到 Jekyll 目录结构；同时解决「文章怎么自动推送、怎么自动打标签」两件事。

| 迭代阶段 | 解决的问题 |
|---|---|
| **浮动导航 → 左侧边栏** | 顶部浮动导航在长文章里频繁遮挡正文；改成左侧固定边栏后，阅读区与导航分离，滚动更顺。 |
| **文章列表 → 卡片表格** | 纯文字列表看不出差异；卡片表格把标题、日期、分类、摘要分栏，扫读更快。 |
| **单页 → Jekyll 目录结构** | 多页共用导航/页脚要重复维护；落到`_posts`、布局模板后，新增文章只需放一个 md 文件。 |

## Q1 · openclaw的skill.md技能，文件内容一般是什么格式的（第 1 轮对话）

> **提问：** openclaw的skill.md技能，文件内容一般是什么格式的

在**entity["software","OpenClaw","AI agent framework"]**体系里，`skill.md`本质上是一个**“技能说明 + 执行规范”文件**，它通常采用：

> **Markdown + YAML Frontmatter**的结构

你可以把它理解为： 👉「给 AI 的技能说明书 + 调用规则 + 提示词模板」

---

# 一、标准结构（核心格式）

一个典型的`skill.md`通常长这样：

```
---
name: skill_name
description: 简要描述这个技能是干什么的
version: 1.0
author: your_name
inputs:
  - name: input1
    type: string
    description: 输入说明
outputs:
  - name: output1
    type: string
    description: 输出说明
---

# 🧠 Skill: 技能名称

## 🎯 功能说明
详细描述这个技能能做什么

## 📥 输入参数
- input1: 描述
- input2: 描述

## 📤 输出结果
- output1: 描述输出格式

## ⚙️ 执行逻辑
1. 步骤1
2. 步骤2
3. 步骤3

## 🧾 Prompt 模板（关键）
你是一个XXX专家，请完成以下任务：
{{input1}}

要求：
1. …
2. …

输出格式：
- xxx
```

---

# 二、拆解一下本质（你要真正理解的）

#### 1️⃣ YAML Frontmatter（必须有）

👉 这是“机器读的配置”

常见字段：

| 字段 | 作用 |
|---|---|
| name | 技能唯一标识 |
| description | 给Agent看的简介 |
| inputs | 输入参数定义 |
| outputs | 输出结构定义 |
| version | 版本控制 |

📌 本质： ➡️ 决定这个 skill 能不能被调用、怎么被调用

---

#### 2️⃣ Markdown正文（给AI看的“行为说明”）

这一部分才是真正影响效果的核心：

##### ✔ 必备模块

###### ① 功能说明（干什么）

让 Agent 知道： 👉 “什么时候该用这个技能”

---

###### ② 输入/输出定义（人类可读版）

补充 YAML，增强理解

---

###### ③ 执行逻辑（流程）

👉 类似 SOP：

```
先分析 → 再处理 → 最后输出
```

---

###### ④ Prompt模板（最关键🔥）

👉 这是技能的“灵魂”

通常包含：

- 角色设定

- 任务指令

- 限制条件

- 输出格式

---

# 三、常见高级写法（进阶玩家）

如果你想做“强能力 Agent”，一般会加：

---

#### ✅ 1. Few-shot 示例

```
## 🧪 示例

输入：
xxx

输出：
xxx
```

👉 提升稳定性（非常重要）

---

#### ✅ 2. 规则约束

```
## ❗约束

- 不允许编造数据
- 必须结构化输出
```

---

#### ✅ 3. 多步骤思维（Chain-of-Thought）

```
## 🧠 推理步骤

1. 理解问题
2. 拆解结构
3. 生成结果
```

---

#### ✅ 4. 输出格式锁定（防跑偏）

```json
## 📦 输出格式（严格）

{
  "title": "",
  "content": ""
}
```

👉`skill.md`=

> **YAML（定义能力） + Markdown（约束AI行为） + Prompt（驱动输出）**
